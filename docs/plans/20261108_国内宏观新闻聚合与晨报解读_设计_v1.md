# 国内宏观新闻聚合与晨报解读 · 设计 v1.0（2026-11-08）

> **缘起**：用户提供金十"行业动态预览"接口样例并问——快讯有没有单独的国内宏观经济聚合？
> 要不要单独分析汇总联动/LLM 解读？
> **结论先行**：没有（现状只订 4 栏目）；**有缺口且底座便宜**（预览接口 1 次请求 = 17 栏目头条）；
> LLM 解读**要，但做成按需按钮**（不自动推送、不烧常驻额度），规则聚合先行。

## 0. 接口规格（2026-11-08 实测，**实现前必读**）

> 原稿只写了"用户实测样例"却没给地址 ⇒ 下游无法开工。本节是**实测补全**。

### 0.1 预览接口（1 请求 = 17 个文本栏目，已实测）

```http
GET https://mp-api.jin10.com/api/home/item
    ?category_id=52045&page=1&limit=20&platform=pc
Headers:
    x-app-id : fiXF2nOnDycGutVA
    x-version: 1.0
```

- **实测 HTTP 200，响应 20,198 字节**（1 次请求拿全 17 栏目，egress 极低）
- **不需要 `x-token`**（与 `tidy-news/details` 不同，该接口公开可读）
- `category_id=52045` 是"行业动态预览"这个**容器**的 ID，**不是**具体栏目

**响应结构**：

```jsonc
{
  "status": 200,
  "message": "",
  "data": [                      // list，实测 20 项
    {
      "title": "A股每日市场要闻回顾",
      "type": 8,                 // 8 = 文本卡；4 = 图片卡（无文本，忽略）
      "type_id": 50030,          // ← 栏目 ID
      "data": {
        "desc": "国家能源局：…",        // = list[0]，首条完整文本
        "list": ["…", "…", ...],       // ← **字符串数组**，实测 6 条
        "data_id": 60171,              // ← **详情接口要用的 id**
        "category_id": 50030
      },
      "display_time": "2026-11-06T00:00:00.000Z",
      "allow_sub": 1
    }
  ]
}
```

**⚠️ 三个易错点（实测踩到）**：
1. **`data.list` 是 `List[str]`，不是对象数组** —— 拿到的就是 6 条头条的**纯文本**。
2. **详情要用 `data.data_id`，不是 `type_id`** —— `type_id` 是栏目号（50030），
   `data_id` 才是文章号（60171）。用户给的详情样例 `?id=60172` 正是
   「50010 房地产」的 `data_id`，已验证对应。
3. **`data.desc` 与 `data.list[0]` 内容相同** —— 不要重复计入。

**type 分布**：实测 `{4: 3, 8: 17}` ⇒ **17 个文本栏目 + 3 张图片卡**（图片卡无文本，忽略）。

### 0.2 详情接口（按需，默认关闭）

### 0.4 egress 账（重算）

| 路径 | 请求数 |
|---|---|
| 现状 `jin10_tidy.compute(days=N)` | **4 栏目 × N 天 = 4N 个请求** |
| 新增预览接口 | **1 个请求**（拿全部 17 栏目 × 6 条） |
| 若预览**替代** tidy 的 4 栏目抓取 | **净减少**：4N → 1（N≥1 时成立） |

**⇒ 原稿"egress 预算 +1 请求/日"的说法偏保守。**
若确认预览接口的 50029/50030/50033/50034 数据与 tidy 同源（需对比验证），
则整体是**降本**而非增本。**建议先在实验脚本里对比两者当日的 6 条头条是否一致**，再决定是否替换。

## 二、三层方案（规则先行，LLM 按需）

### 层 1 · 数据（P0，零 LLM，1 请求/日）

- 新模块 `app/macro_digest.py`：每日 1 次调**行业动态预览**接口 → 落表：

```sql
CREATE TABLE macro_news_digest (        -- ⚠️ 表名不叫 macro_digest
    date           TEXT,
    type_id        INTEGER,             -- 栏目（50022 等，来自响应 type_id）
    category_name  TEXT,                -- 响应 title
    data_id        INTEGER,             -- 详情用（data.data_id）
    headlines_json TEXT,                -- data.list 的 6 条字符串数组
    desc_text      TEXT,                -- data.desc（= list[0]，单列存便于全文检索）
    created_at     TEXT,
    PRIMARY KEY (date, type_id)
)
```

**为什么改名 `macro_news_digest`**：库里已有 **7 个** `macro*` 表
（`macro_daily` / `macro_daily_history` / `macro_history` / `macro_regime_class` /
`macro_regime_events` / `macro_regime_state` / `macro_signal_log`）。
`macro_digest` 与 `macro_daily` 只差一个词、语义又都像"每日宏观"，
排查时极易混。加 `news_` 把它钉死为"新闻聚合"。
- **栏目白名单（冻结，2026-11-08 已对实测响应逐个核对）**：
  50022 昨日今晨 / 50029 盘前 / 50030 回顾 / 50012 债券 / 50020 期货 /
  50011 投行观点 / 50016 + 50032 大宗（**两者标题完全相同，按 title 去重**）/
  50023 欧美汇总 / 50024 美股 / 50015 外汇 / 50017 港股 /
  **50021 俄乌冲突局势跟踪**（实测存在，原稿漏列，归"海外/地缘"）= **12 个**；
  按需再加：50007 AI / 50009 电动车 / 50010 地产 / 50014 隔日全球股市。
  ⚠️ **白名单只决定"哪几栏进晨报"，不影响请求数**——预览接口永远是 1 次请求，
     拿回全部 17 栏；白名单是**展示过滤**，不是取数过滤；
- `type=4` 图片卡跳过；请求失败退回既有 jin10_tidy 4 栏目（**降级不崩**）；
- **egress 预算**：+1 请求/日 + 按需详情（默认 0）。

### 层 2 · 规则聚合（P0，零 LLM）

- `macro_digest_view(day)`：按**三类**输出结构化晨报——
  ① `政策/定调`：命中 `policy_tone_watch` 关键词族（单一事实源复用）；
  ② `数据/资金`：PMI/CPI/社融/两融/央行操作等数字类；
  ③ `海外/商品`：美联储/关税/油价/地缘；

**归类规则（冻结，避免实现时各写一套）**：

| 问题 | 决定 |
|---|---|
| 一条头条**命中多类** | 按 **①→②→③ 优先级取第一个命中的类**，**不重复展示** |
| 三类**都没命中** | 归入 `其他` 栏，**不丢弃**（晨报底部折叠，作为"口径完整性"证据） |
| "复用 policy_tone_watch" | **只复用 `KEYWORDS` 常量（词表）**，**不要调 `compute()`** —— 后者是"账本落库"语义，会把宏观晨报的头条写进 `policy_tone_log`，污染既有的政策账本 |
| 拉丁词大小写 | 用与 `compute()` 相同的 `lower()` 处理（SFISF / PMI / CPI / PPI） |
| 同一条在 `desc` 与 `list[0]` 重复 | **只取 `list`**（`desc` 就是 `list[0]`，重复计入会让 hit_count 虚高） |
- 展示：**盘前决策卡旁新增"宏观晨报"小卡**（三栏折叠，头条级，标注产出时间与栏目）；观察词命中照常走既有提醒（不新增推送通道）。

### 层 3 · LLM 晨报解读（P1，按需按钮）

- 与 flash_brief 同款模式：`POST` 手动触发 + **按日缓存 + 数据指纹**（头条集变了才可重烧）+ 单次 LLM；
- 定位：把三栏头条**连读**出"今日宏观主线 2-3 条 + 对 A 股风险偏好的方向提示"——**不重复决策卡/竞价 LLM 的对象**；
- **措辞硬约束（红线，必须写进 prompt 与返回校验）**：
  · 只允许「风险偏好**偏暖 / 偏冷 / 无明确指向**」三档 + 依据（引用哪几条头条）；
  · **禁止**出现：买入 / 卖出 / 加仓 / 减仓 / 仓位 / 目标价 / 止损 / 抄底 / 逃顶
    （与 G4 文案纪律、教练 BK-58 同款禁词表）；
  · **禁止**输出数字化的操作建议（如"建议 3 成仓"）；只能引用头条里的**事实数字**
    （如"社融同比 +8.2%"）；
  · 返回后做一次**禁词扫描**，命中则整段拒收并降级为"规则三栏原样展示"（不重试、不润色）；
- 不自动推送（与"金十消息面 AI 归纳"按钮先例一致）。

### 联动矩阵（读取既有装置，零改造）

| 装置 | 联动方式 |
|---|---|
| `policy_tone_watch` | 宏观晨报头条命中冻结词表 ⇒ 定调证据（账本照旧，只加"来源=宏观晨报"标注） |
| 竞价面板 | 晨报头条若有"互换便利/汇金/稳市机制" ⇒ 资金类高亮（已有词族） |
| `macro_regime_class` | 晨报数据类头条作为其证据层的**人工阅读补充**（不改判据） |
| G7 题材归类 | 题材热点栏目 ↔ 涨停归类互链（展示层） |

## 三、红线与明确不做

1. 全部为**观察/展示层**，不进评分/闸门/仓位（R2）；
2. LLM 输出**不自动推送**，按钮触发、按日缓存、指纹失效提示；
3. **不爬详情全文**（预览头条已够晨报；详情按需单卡拉取，默认关闭省 egress）；
4. 周末/节假日接口不更新 ⇒ 如实显示最近一期（口径日期标注，`allow_sub` 卡同款处理）；
5. 栏目白名单改动须留痕（同 tone 词表纪律）。

## 四、分期

- **P0**（~1d）：层 1 数据落库 + 层 2 三栏晨报小卡（盘前）；
- **P1**（~0.5d）：层 3 LLM 按钮；
- **不做**：自动晨报推送、全文爬取、图片卡解析、栏目全量订阅。

**本轮（2026-11-08）新增的前置验证项**（不写代码，先回答）：

1. **同源对比**：预览接口返回的 50029/50030 的 6 条头条，与
   `jin10_tidy` 按 `category_id + date` 抓到的内容**是否一致**？
   → 若一致，则预览可**替代** tidy 的 4N 请求（净降本）；
     若不一致（头条只是摘要、详情才是全文），则两者**互补**，不替换。
2. **`allow_sub` 语义**：响应里有 `allow_sub` 字段（50030 是 1、图片卡是 0），
   猜测含义是"是否可订阅"，但**未验证**——若它表示"是否公开"，取数范围要按它过滤。
3. **周末/非交易日**：`display_time` 实测是 `2026-11-06T00:00:00Z`（周五），
   周末是否停更、停更时 `data` 是否为空 list，**需观察一个周末**。

## 五、与既有表/模块的关系（防混淆）

| 名称 | 是什么 | 别混淆 |
|---|---|---|
| `macro_daily` | 宏观指标日值（利率/汇率/油价等数值） | **不是**新闻 |
| `macro_regime_class` | 宏观四类概率账（观察器） | **不改它** |
| `macro_news_digest` | **本文新增**：新闻头条聚合 | 与上面两个无关 |
| `jin10_tidy_news` | 现有 4 栏目整理稿（全文） | 预览接口的头条**更短**，是摘要 |
| `flash_news` | 金十爆/沸/热热榜 | 来源不同（热榜子集） |
