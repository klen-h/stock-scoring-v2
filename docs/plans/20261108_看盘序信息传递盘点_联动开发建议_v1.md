# 看盘序信息传递盘点与联动开发建议（2026-11-08）v1.0

> **缘起**：用户要求"整合盘前、竞价等 tab 之间的信息传递，看看是否存在信息传递功能可开发"。
> **方法**：7 阶段 × 产出/消费矩阵 → 已有机制盘点 → 断点分析 → 可开发项分档。
> **红线预览**：本文全部建议均为**观察/展示层**；任何"竞价/盘中数据反过来影响决策"的
> 路径一律划入"明确不做/需预登记"（R2：这些数据没有任何检验结论）。
> **一句话结论**：链路的**骨架已成型**（预判→对账、计划→执行、基线→收盘都落了库），
> 但阶段间的**读取大多是断的**——上游产出都在库里，下游不读。断点 7 处，其中
> **3 处可以低成本接上**（数据全部现成，纯展示层接线）。

## 1. 七阶段 × 产出/消费矩阵（现状）

| 阶段 | 时点 | 核心产出（落库） | 应消费的上游 | 实际消费现状 |
|---|---|---|---|---|
| **盘前** premarket | 09:10 | 决策卡（做不做/做什么/做多少/错了怎么办 + 持仓扫描，规则聚合零 LLM，`trader_brief.build_decision_card`）；盘前简报；情绪预判落库 | 昨日日报（含明日预案）、宏观面板、财经日历 T-N、两融情绪 | 宏观/日历 ✓；**昨日日报 `tomorrow_watch` ✗ 不读**；昨日竞价/盘中表现 ✗ |
| **竞价** auction | 09:15 | `market_emotion_daily.auction_*`（高开低开家数/平均缺口/竞价额）+ 高开低开榜 + 规则判读 verdict；**11-08 新增面板三块**（昨日关键位对比/板块联动/LLM 解读） | 盘前决策卡、昨日日报 | "回看盘前决策卡"**链接**（手动跳转）✓；昨日日报关键位 ✓（新）；**决策卡候选/关注池 ✗**；**日报 `tomorrow_watch` ✗** |
| **早盘** intraday | 09:30 | 实时情绪/涨停复盘/异动/评分榜 | 竞价定稿（verdict/量比/板块结构） | **✗ 完全不读竞价结论（最粗的断点）** |
| **早盘复盘** amreview | 11:30 | `am_*` 早盘定稿 + digest（LLM 可选） | 竞价定稿、盘前计划 | am_* 自身 ✓；**竞价定稿 ✗**；**盘前计划 ✗** |
| **午盘** midday | 13:00 | 同盘中 | 同早盘 | 同上 |
| **盘后** postmarket | 15:00 | `close_*`、涨停复盘、行业成交占比、盘后简报、**日报（LLM"明日预案与持仓观察"段 + `tomorrow_watch` 结构化 3-5 条，`daily_report.py:1066/1102`）** | 全天各段 | 自身 ✓；**`tomorrow_watch` 产出后无人消费（断）** |
| **复盘** review | 盘后深读 | 一致性 KPI、交易计划 | 情绪对账（预判 vs 实际 30 天）✓、尾盘承接（14:30 基线 → 收盘）✓、教练一致性 ✓ | **骨架最全的一段** |

## 2. 已存在的信息传递机制盘点（12 条）

| # | 机制 | 方向 | 载体 | 自动化程度 | 证据 |
|---|---|---|---|---|---|
| 1 | 盘前决策卡（做不做/做什么/做多少/错了怎么办） | 昨夜数据 → 盘前计划 | `GET /system/workbench-decision-card`，规则聚合 | 全自动 | `trader_brief.py:1025` |
| 2 | **"回看盘前决策卡"链接** | 竞价 → 盘前 | 页内跳转 | 手动点击 | `Workbench.vue` 竞价卡脚注 |
| 3 | **竞价面板"昨日日报联动"**（11-08 新增） | 昨日日报 → 竞价 | 关键位/预期区间 vs 开盘 + 板块联动 + LLM | 全自动（进 phase 即拉） | `auction_panel.py` |
| 4 | **情绪对账**：盘前预判 → 盘后实际 | 盘前 → 复盘 | `emotion-review` 30 天表 | 全自动 | `market.py:1301/1336` |
| 5 | 早盘定稿 `am_*` → 早盘复盘页 | 早盘 → 午休 | 11:30-11:40 一次性落库（幂等） | 全自动 | `market.py:1004` |
| 6 | 尾盘承接：14:30 基线 → 收盘 | 盘中 → 复盘 | `tail-review` | 全自动 | `market.py:1546` |
| 7 | 三段复盘（盘前/午休/盘后 LLM）+ 企微推送 | 各段 → 人（跨天阅读） | `run_review` + 推送 | 定时自动 | `flash/scheduler` |
| 8 | 事件 T-N 提示（FOMC/选举等） | 日历 → 竞价/观察器 | `EVENTS` + `event_alert` 文字提示 | 全自动（只提示） | `scenario_watch.py` |
| 9 | 财经日历 T-N → 盘前 | 日历 → 盘前 | `calendar_ahead` | 全自动 | `flash/calendar_ahead.py` |
| 10 | 矛盾验证闭环 T+1 | 当日观点 → 次日验证 | `contradictions validator` | 日批自动 | `contradictions/validator.py` |
| 11 | 日报"明日预案与持仓观察" | 盘后 → 次日 | LLM 段落 + `tomorrow_watch` 结构化 | **产出自动、消费无** | `daily_report.py:1066/1102` |
| 12 | 输出消费标记（👍/👎） | 各卡 → 周复盘 | `output_feedback` | 手动二选一 | `InsightBody`（C2） |

**规律**：①→产出一侧全部自动化了；②→**消费一侧靠人跳转或干脆没人读**；③→唯一成环的只有"情绪预判→对账"（#4）——因为它当初就是按"对账"设计的。

## 3. 断点分析（7 处，按疼痛程度排序）

| # | 断点 | 后果 | 接线成本 |
|---|---|---|---|
| **D1** | 日报 `tomorrow_watch`（结构化 3-5 条明日观察指标）**产出后无人消费** | 昨天收盘后系统最值钱的一段前瞻输出，第二天早上不见了 | **极低**：字段结构化，读出来展示即可 |
| **D2** | 竞价定稿（verdict/量比/板块强弱）**不进早盘页** | 9:25 定稿的判断在 9:30 最需要它的时刻消失；早盘页看不到"开局是强是弱" | **低**：面板数据现成，早盘 phase 加一张只读摘要卡 |
| **D3** | 盘前决策卡的候选 Top3/关注池 **不与竞价实际对照** | 计划做完了，开盘后"我关注的票竞价如何"要自己肉眼对 | **低**：决策卡候选 codes × 竞价 gaps 一次 join |
| **D4** | 盘前计划（档位/候选）**不进早盘复盘对照** | 午休复盘"上午做得如何"缺"上午计划是什么"那一列 | 低 |
| **D5** | `auction_*` 历史**只落库不回测**（09-25 评估缺口①） | "竞价强度 → 当日走势"永远停在经验阈值 | 数据在积累，回测须预登记 |
| **D6** | 推演区间位置（强于/弱于预期，11-08 新增）**不进对账体系** | "预期区间"只有当天看的价值，没有对账价值 | 按日落库一行即可攒样本 |
| **D7** | 提示通道分散（浏览器通知/企微/各卡内提示） | 跨阶段信息靠人记得去看 | 收件箱属于大工程，暂缓 |

## 4. 可开发项分档

### A 档：立即可做（观察/展示层，数据全现成，零决策链，零 LLM——除标注外）

| # | 内容 | 数据源 | 改动点 | 成本 | 验收 |
|---|---|---|---|---|---|
| **A1** | **日报 `tomorrow_watch` 接入**：盘前决策卡顶部 + 竞价面板①表下方，显示"昨日日报的明日关注 3-5 条"（标注生成日期） | `daily_reports` 表 LLM 输出 JSON 的 `tomorrow_watch` 字段（结构化现成） | 决策卡聚合函数 + 竞价面板各加一段读取展示 | 0.5d | 盘前/竞价页能看到昨日日报的明日关注清单且带日期 |
| **A2** | **竞价定稿摘要卡进早盘页**：早盘 phase 顶部只读一条——"竞价定稿（9:25）：判读 X · 量比 Y · 强势板块 A/B · 缺口 Z%"（数据取 `market_emotion_daily.auction_*` + 面板 sectors） | `auction_*`（已落库）+ `auction_panel` 已有聚合 | `loadPhaseData('intraday')` 加一次读取 + 一张小卡 | 0.5d | 早盘页可见当日 9:25 定稿摘要；休市日显示非当日口径 |
| **A3** | **计划偏离对照**：竞价面板加"我的计划股竞价"小节——决策卡候选 Top3 + 观察池 ready 高的票 × 竞价缺口（"+2.1% 高开，高于介入参考价"式纯事实） | 决策卡 candidates + `gate_watch` 观察池 × `_stock_gaps()` | `auction_panel` 加一段 join + 前端一小节 | 0.5d | 能看到"我计划里的票今天竞价如何"；**只陈述不建议** |
| **A4** | **早盘复盘补"盘前计划 vs 上午实际"两列**：左=决策卡档位/候选/回避方向（昨夜生成），右=`am_*` 实际（涨跌/涨停/缺口兑现） | 决策卡（按请求日重算或落库快照）+ `am_*` | amreview phase 加两列卡 | 1d | 午休页左右两列可直接对读 |

### B 档：需攒样本 / 预登记（不要现在写代码）

| # | 内容 | 前置 | 红线检查 |
|---|---|---|---|
| **B1** | **"竞价强度 → 当日走势"回测**（缺口 D5）：高开结构/量比分档 vs 当日/次日收益 | `auction_*` 已按日落库；**样本攒够 ≥20 个交易日**后，先写预登记判据（分档口径/收益口径/聚类方式）再跑——同 C5 形态检验纪律 | R2/R3 全适用；判据未冻结不得跑数 |
| **B2** | **推演区间位置对账**（缺口 D6）：每日落一行"开盘区间位置 → 收盘区间位置"，攒"预期 vs 兑现"样本 | 面板已算区间位置；加一行落库 + 复盘页展示 | 纯记录不校准（N<30） |

### C 档：明确不做

| # | 内容 | 理由 |
|---|---|---|
| C1 | 竞价结果**自动**调整决策卡档位/闸门/仓位/模拟盘 | R2：竞价数据无任何检验结论；与"regime 判市减仓 KILL"同一类坑。若未来 B1 通过，须另行预登记 + 拍板 |
| C2 | 跨阶段 LLM 大摘要（"一天收件箱"） | 成本高；与三段复盘（#7）功能重叠；提示通道分散（D7）暂忍 |
| C3 | 竞价/盘中数据触发的**交易建议推送** | 同 C1，且与 WECHAT 纪律冲突 |

## 5. 建议排序

```
A1（tomorrow_watch 接入，最便宜且最值钱）
→ A2（竞价定稿进早盘，补最粗断点 D2）
→ A3（计划偏离对照，盘前↔竞价成环）
→ A4（早盘复盘两列，计划↔执行成环）
→ B2 顺手落库攒样本
→ B1 等样本 ≥20 交易日后预登记
```

> **设计原则**（贯穿 A 档）：传递的是**事实与对照**，不是**结论与指令**——
> 每一处接线都保持"上游产出什么就显示什么 + 口径日期如实标注"，
> 不做二次解读（解读已有专门装置：规则判读 / LLM 解读 / 对账账本）。

## 附：与既有计划的关系

- 本盘点是 `20261107_政策定调窗口观察计划` 之外的**工程层**梳理，不改变其判据与排期；
- A 档各项为纯展示接线，**不构成新信号**，无需预登记（同"观察器样式整修"性质）；
- B 档各项一旦要做，走 `PLAN_NEXT` C 类流程（点头 → 冻结判据 → 实现）。
