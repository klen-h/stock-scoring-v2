## 0. 四个与设计文档不一致的发现（**先看这个**）

设计文档 §0.3 的白名单基于「栏目 ID + 标题」，内容层核对后**有 4 处需要修正**：

### ① `50021`「俄乌冲突最新24小时局势跟踪」是**陈旧数据**

```
50021  display_time = 2026-10-18T00:00:00.000Z    ← 比其他栏目早 19 天
其余 16 栏          = 2026-11-06T00:00:00.000Z
```

**⇒ 这一栏在容器里基本不更新（停留在 10-18 的旧快照）。**
设计文档曾写「原稿未列入，但建议纳入外围/地缘」——**按实测应剔除**：
拿它做晨报会推送 3 周前的俄乌信息，比不收更糟。

### ② `50032` 与 `50016` **标题相同但不是同源重复**

```
50016  data_id=60168  2026-11-06  意大利燃气电厂 / 俄炼厂遇袭 / 印度储能…
50032  data_id=60114  2026-11-03  西方石油CEO / 特朗普油价 / 阿联酋能源…
```

设计文档写「两者标题完全相同，按 title 去重」——
**实测是两份不同期次、不同内容的大宗商品摘要**（11-06 vs 11-03）。
按 title 去重会导致**随机保留其中一份**，可能留下 11-03 的旧内容。

**建议**：不按 title 去重；按 `display_time` **取最新**，并加「与基准日差 ≤1 天」校验。

### ③ `50023`「欧盘美盘重要新闻汇总」**名字骗人，内容是国内**

实测前 6 条：

```

6. 特朗普：我百分之百支持"超级智能"

**⇒ 5/6 条是 A 股相关政策**，是本次实测里**国内政策含量第二高**的栏目（仅次于 50022）。
设计文档把它与其他海外栏并列，实现时容易被误降级。

### ④ `50014`「隔日全球股市走势回顾」**实为 A 股/港股收盘速览**

```
1~6 条全是：上证综指 / 深证成指 / 沪深300 / 创业板指 / 科创50 / 恒生指数 的收盘点位与涨跌幅

**⇒ 对 A 股直接有用**（晨报的"昨日盘面"可零成本取自这里），但**没有任何"全球"内容**。
注意它是**纯数字不是新闻**，不能当文字素材喂 LLM 做定性判断。

## 2. 实现层必须加的三道闸（本次实测得出的硬约束）

设计文档没写这三条，不加会出事故：

### 闸 1 · `display_time` 新鲜度校验（**P0，必须**）

```python
# 逐栏判定，不是整包判定
if (基准日 - parse(display_time)).days > 1:
    skip(该栏)          # 记日志，不报错
```

**理由**：`50021` 停在 10-18、`50032` 停在 11-03，而整包仍然 HTTP 200。
**只看状态码永远发现不了**，只能看每栏自己的 `display_time`。

### 闸 2 · **不要按 title 去重**，按 `display_time` 取最新

`50016` / `50032` 标题完全相同但期次不同（11-06 vs 11-03）。
按 title 去重等于掷硬币，可能留下旧的。

### 闸 3 · 相对时间词与陈旧数据互斥

凡出现「下周」「昨日」「今天」等词，**必须**确认 `display_time` 新鲜，
否则会写出「3 周前的下周将举行会谈」这类错误晨报。

## 4. 复测方法（下次刷新用）

```python
import json, urllib.request
URL = ("https://mp-api.jin10.com/api/home/item"
       "?category_id=52045&page=1&limit=20&platform=pc")
H = {"x-app-id": "fiXF2nOnDycGutVA", "x-version": "1.0", "User-Agent": "Mozilla/5.0"}
d = json.loads(urllib.request.urlopen(urllib.request.Request(URL, headers=H), timeout=30).read())
for c in d["data"]:
    if c.get("type") != 8:
        continue
    x = c["data"]
    print(x.get("type_id"), str(c.get("display_time"))[:10], c.get("title"), len(x.get("list") or []))
```

**验收标准**：所有栏目 `display_time` 与基准日差 ≤1 天；否则按 §2 闸 1 跳过。

## 5. 结论

1. **设计文档的 17 栏清单是栏目层的**（ID + 标题），本文补齐了**内容层**。
2. **不能直接照设计文档的白名单实现** —— 2 栏陈旧、1 栏命名误导、1 栏重复标题、
   2 栏价值被低估。
3. **最关键的一条**：整包 HTTP 200 ≠ 每栏新鲜。**必须逐栏校验 `display_time`**，
   否则会把 3 周前的"下周"写进今天的晨报。
4. 这批数据是**单日单次快照**，栏目更新频率尚不清楚。
   `50021`/`50032` 停了 19 天/3 天可能只是"该栏目低频"，
   建议**连续观察 3 个工作日**再最终冻结白名单（本清单 v1.0 的先验判定已足够开工）。
