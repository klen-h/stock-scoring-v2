# ISSUE 草稿：`direction.score` 日间跳变过大，建议引入 3 日平滑（并列输出，不覆盖 raw）

> 状态：草稿（2026-10-30），**未实现**，待回测决定是否采纳
> 关联：`docs/kimi/20261030_fed_chair_speech_brief.md`（讲话后宏观分被列为"误导样本"）

## 一、现象（实测数据）

`macro_daily.data_json.direction.score`：

| 日期 | score | level | 底层变化（布伦特 / 10Y / 美元） |
|---|---|---|---|
| 2026-10-27 | **0.2** | 中性 | 109.95（-0.72%）/ 4.987（+0.1bp）/ 102.04（+0.02%） |
| 2026-10-28 | **-2.9** | 中性 | 109.76（+0.32%）/ 4.998（+0.7bp）/ 102.37（-0.01%） |
| 2026-10-29 | **19.8** | **偏多** | 110.67（-0.87%）/ 5.031（**-0.3bp**）/ 102.25（+0.1%） |

**单日从 -2.9 跳到 19.8，振幅 22.7 分**，而三个底层输入的变化都很小
（油 ±0.9%、10Y ±1bp、美元 ±0.1%）。

## 二、影响

1. **闸门/仓位随分数跳变** —— 同一周内"中性 → 中性 → 偏多"，中间没有任何过渡。
2. **用户失去参考价值** —— 每天翻转的信号，实际不可用于决策。
3. **与组合风险档冲突** —— 10-29 分数跳到"偏多 19.8"，但该日恰好是
   「滞胀交易」原始条件成立日（油 110.67 / 10Y 下行 / 美元 102.25），
   **机械分方向与该组合对成长股的含义相反**。

## 三、根因假设（待验证，不要直接当结论）

- 评分是**当日截面求值**，没有时间维度；
- 阈值型规则（如 `bp_change < 0`）在临界点附近会因 **0.1bp** 的差异整体翻转 ⇒
  分母（有效规则强度）变化 ⇒ 归一化后**分量被放大**；
- 实测 `us10y_bp_change` 在 10-27/28/29 是 `+0.1 / +0.7 / -0.3`，
  符号在这里翻了一次，而分数翻了 22 分 —— 量级明显不成比例，需要逐因子核对。

## 四、建议方案（最小改动）

1. **保留 raw**：`direction.score` / `mechanical_score` 一律不动（红线）。
2. **新增** `score_smoothed` = 近 3 个交易日加权均值（建议 `0.5 / 0.3 / 0.2`）。
3. **并列输出**，前端两个数并排显示，并注明"平滑值/原始值"。
4. **无数据日不参与平滑**（不能把缺失当 0 —— 否则会把平均值人为拉低）。
5. 平滑窗口与权重走 env，默认 3 日。

## 五、验收标准

- [ ] `score_smoothed` 与 `score` **并存**，raw 未被任何代码路径覆盖
- [ ] 窗口/权重可配（env），默认 3 日 / 0.5-0.3-0.2
- [ ] 缺失日不参与计算，且输出里标注"参与平滑的天数"
- [ ] **回测报告**：平滑前后与次日/3日涨跌的 IC 或胜率对比，样本量写明
- [ ] 回测不显著优于 raw ⇒ **不采纳**（宁可保留跳变，也不引入未验证的平滑）
- [ ] 前端文案明确"平滑值仅供参考，闸门仍按原始分执行"

## 六、不要做的事

- ❌ 不要为了让分数"看起来稳定"而直接改规则阈值 —— 那是调参掩盖问题
- ❌ 不要用平滑值替换闸门输入（未经回测的平滑 = 引入未知延迟）
- ❌ 不要在同一 PR 里既改阈值又加平滑（无法归因）
