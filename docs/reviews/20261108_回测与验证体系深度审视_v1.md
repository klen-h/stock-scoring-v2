## 一、体系总览（文字数据流图）

```
数据层   backtest_prices(989只日K) · mainforce_state · ranking_history/live
            │
回测引擎  backtest/engine.py（撮合现实化：一字板剔除/跌停顺延/费用/止损v2）
            ├── 回测中心 BacktestView ← routers/backtest.py（战法×regime 分层回测）
            ├── 系统绩效 Performance ← 三轨（模拟盘前瞻/排行半前瞻/战法回放in-sample）
            └── 评分验证 BucketStats ← 评分子指标分桶 + edge_verify 月度队列

生产侧   影子榜（H2' 防御影子榜/H3 双锚 eq_anchor）：先影子后拍板的转正通道
```

**体系哲学**：R2（信号不进决策链除非过预登记检验）+ R3（判据先冻结）贯穿全部四模块；影子榜是"检验通过前只影子、拍板后转正"的机制化。

## 二、回测中心

**功能定位**：战法与假设的**历史检验台**——不是预测工具。产出的所有胜率/超额只用于预登记判定（GO/KILL），不直接给买卖。

**核心规则（engine.py，全部带证据）**：
| 规则 | 内容 | 状态 |
|---|---|---|
| T+1 开盘成交 | 信号日次一交易日开盘价入场；涨停一字买不进剔除 | ✅ 09-05 现实化；**11-07 BK-33 修复**：一字容差 0.001→0.006（复权半Tick界，SQL 重放：716,301 样本日漏判 166 个 +27.1%） |
| 跌停顺延 | 触发日封死跌停 ⇒ 卖单顺延次日开盘 | ✅（卖侧同款容差已对称修复） |
| 退出 v2 | 持有 3 日 / -7% 止损 / 不设目标价（`WARFARE_EXIT_POLICY=v2`） | ✅ 预登记定版 |
| 费用 | 佣金+滑点+印花（买卖分列，etf/stock 两套） | ✅ |
| regime 分层 | `backtest_warfare_by_regime`（进攻/震荡/防御 × 波动）→ ADMISSION_MATRIX 数据依据 | ◐ 样本不足（防御期无战法样本，等 regime 转好） |

**已知偏差（诚实清单）**：
- **BK-36（未修）**：数据右缘截断持仓仍计"持有到期"（无 truncated 标记）；盘后信号以当日收盘入场且零成本 ⇒ **回测偏乐观**。⚠️ 与 BK-33 修复叠加 ⇒ **所有历史回测结论的绝对数值存在系统性偏差**——预登记的 KILL/PARTIAL 是**相对判据**（超额、分位）受影响较小，但绝对胜率数字引用时要打折。
- **BK-33 的遗留责任**：只做了数据层重放对照（166 漏判量化），**未重跑各战法历史回测** ⇒ 现存战法胜率（如单阳不破 57%）是旧口径数字，引用需标注"BK-33 前口径"。

## 三、评分验证（BucketStats + edge_verify）

**功能定位**：把"看起来有效"变成"过了预登记才算数"的裁判所。两层：

1. **BucketStats（分桶验证）**：评分子指标按桶（吸筹/出货/状态/分位）统计未来收益——评分子指标的**解释力体检**（routers/scoring.py:717 bucket，缓存键含全参——BK-10 已修）。
2. **edge_verify（月度自动复检队列）**：`SCRIPTS` 注册制——每个预登记假设一个脚本，每月自动跑出 PASS/FAIL/PARTIAL 并推送（`edge_verify.py:43-55,233`）。**本体系的存在原因**："脚本写了但没人跑 = 白等"（模块注释原话）。

**已出结论总表（引用必须带口径）**：

| 假设 | 结论 | 关键数字 |
|---|---|---|
| 评分 Top50 买入含义 | **KILL** | T+5 −1.48pt / T+20 −4.23pt（vs 可取价池，P<0.0001） |
| regime 判市**减仓** | **KILL** | vs 满仓 −0.30pt/20 日；机制=趋势跟随滞后 |
| 主力节奏 H1（吸筹∧三绿） | PARTIAL | T+10 +1.14pt(P .0025) 但子样本翻转 ⇒ 无稳健超额 |
| 消息分 | FAIL | 按日 IC T+2 −0.003 / T+5 +0.004 |
| 龙虎榜净买 | 多头禁用/空头可用 | 次日开盘 CI 跨 0 |
| 缩量启动形态 | 预登记中 | 只对 ≥2026-10-15 前瞻样本生效 |
| A2 回避侧反向 | 等时钟 | ≈11 月中旬，达标前不看数字 |

## 四、影子榜（H2'/H3——检验通过前的转正通道）

**功能定位**：评分 KILL 之后，"高分股在防御市跑输"被证实 ⇒ 但**回避侧/分市况**的价值未证 ⇒ 阴跌防御市里用**影子榜**（独立标签页+工作台 Top10）只展示不推送，等 A2 结论拍板转正。

**核心规则（两处证据）**：
- **H2' 阴跌防御影子榜**：独立冻结公式（`live=1` 同口径实时预览），影子期 **10-23 起算**；
- **H3 双锚并跑**：等权锚 `eq_anchor_history` 为**判态单一事实源**（10-26 定案）；
- 变体机制：`scoring/decay.py`（shadow-rank 两口径单一事实源，供接口与 `scripts/shadow_decay_ranking.py` 共用；`live_ranking.py:54` 把日期照搬进 `shadow_rank_daily` ⇒ 防跨标签对齐错位）；
- **数据流**：live_ranking（实时）→ shadow_rank_daily（按日落库）→ compare_shadow_rank（按交易日对齐复检）→ 拍板。

## 五、系统绩效（Performance）

**功能定位**：回答"这套系统整体上有没有正向价值"——**三轨刻意分开**（`routers/performance.py:225`，1h 缓存）：

| 轨 | 口径 | 语义 |
|---|---|---|
| paper（模拟盘） | **前瞻** | 真实按信号走的成绩（受防御禁入场影响，样本受限） |
| ranking（排行榜） | **半前瞻** | 快照 TopN 未来 N 日收益（评分 KILL 的直接验证面） |
| replay（战法回放） | **in-sample** | `_replay_metrics` 回放撮合——只能证引擎一致性，不能证前瞻 |

**已校准**：模拟盘 46 笔 vs 回测引擎对照（F1，10-18）：剔越界价后 37 笔 P 43.9% vs A 41.5% ⇒ **基本吻合**（回测引擎的撮合模拟可信）。⚠️ 该对照在 BK-33 修复前做 ⇒ 修复后应复跑一轮（低成本高价值）。

## 七、结论

1. **体系是自洽的**：预登记 → 影子 → 拍板 → 月度复检的闭环真实存在且在运转（SCRIPTS 队列、SIGNAL_STATUS、影子期起算日都是机制不是口号）；
2. **结论要分层引用**：KILL/PARTIAL 是**相对判据**（可信度高）；绝对胜率数字受 BK-33/36 偏差影响（引用打折）；
3. **最优先的三个动作**：P-1 复跑（BK-33 后口径全量月度复检一轮）、P-3 影子期时钟机械化、P-5 BK-41 顺手修；
4. **诚实边界**：本审视基于静态阅读 + 少量实测；shadow_decay 两口径与 BucketStats 分桶细节未逐行核——引用本结论时保留这条边界。
