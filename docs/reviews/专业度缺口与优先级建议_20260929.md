## 三、三处缺口

### 缺口 1：业绩口径（基准错配）★ 建议优先做

**问题**：全项目所有对比基准都是**沪深300**，但持仓/信号偏 **20–50 亿中小盘** ⇒
阴跌市里中小盘跌得比 300 多 ⇒ **"跑赢沪深300"仍可能绝对亏损**，且超额被**风格暴露污染**。

**为什么是根**：它让"复盘"无法回答最该回答的问题——**我到底做得怎么样**。
日报里那句"空仓对照：沪深300 近 5 日 ±X% → 空仓超额 ±Y%"（`daily_report.py`）
本身就是错的基准：**你空仓的对照不该是大盘股指数**。

**★ 落地形态（已核实数据依赖，修正了原设想）**

原设想是"构造等权池"，**但实测不可行**：等权池需要**全市场日线历史**，
而线上只有 870 只（这正是 A2 已研判"暂缓"的那个问题）⇒ 换方案：

```
基准 = 中证1000 指数（它就是中小盘等权风格的代表，且只需**一条线**）
落地：① 回填中证1000/中证500 指数日线（复用现成 backfill_index / backfill_history 通道）
      ② 日报 + 周复盘同时报三个口径：
         绝对收益 ｜ 对沪深300 超额 ｜ 对中证1000 超额
```

**★ 核实到的约束（决定成本）**：`backtest_prices` 里**只有 `sh000300` 有历史（752 行）**；
`sh000905`（中证500）/`sh000852`（中证1000）/`sh000001`/`sz399006` **全部无数据**；
但已有 13 个 ETF 各 752 行 ⇒ **回填通道是通的，只是没填指数**。

**成本**：**0.5 天开发**（回填加 2 个指数 + 报表双口径）+ **1 晚回填**（指数只有几条线，很快）

**验收标准**：
- 日报/周复盘出现"绝对 / 对300 / 对1000"三口径，且**数值可复核**（对 300 的超额与现值一致）；
- 回填后 `sh000852` 行数 ≈ 752（与 300 对齐）

**风险**：中证1000 指数与"你的实际持仓风格"仍不完全等价（你的票更小、更集中）
⇒ 要在文案里标注"这是**风格参照**，不是精确基准"。

### 缺口 2：闸门 `ready==3` 的联合期望值未验证

**问题**：`ready==3` = A 主力吸筹 + B 不追高 + C 市况允许，是**当前唯一的买入入口**。
三者**各自**有依据，但**组合起来**的胜率 / 期望收益 **没测过**。

| 条件 | 现有依据 |
|---|---|
| A 主力吸筹 | 有回测依据（+1.1pt）|
| B 不追高 | 阈值设定 |
| C 市况允许 | 19.5 年四态验证 |
| **A+B+C（ready==3）** | **未验证** ⚠️ |

**为什么重要**：等于**用一个未经联合验证的规则开仓** —— 各部件合格 ≠ 组合合格
（项目自己的方法论铁律里就有"因子显著≠可交易"）。

**落地形态（按项目铁律）**：
1. **预注册**：判据写死进脚本头（模板 `scripts/reversal_edge_check.py`），
   含：T+5/T+20 超额口径、对照基准（用缺口 1 的中证1000）、最小样本、簇去重
2. **攒样本**：`gate_snapshot_history` 现仅 **5 行** ⇒ 样本严重不足
   ⇒ 需要**日批持续落库**（确认每天写入）+ 等样本量达标
3. 达标后才谈"要不要给 `ready==3` 的候选加权重/推送"

**成本**：开发 **≤0.5 天**（写脚本 + 确认落库）；**但结论要等样本** ⚠️
⇒ **不能靠开发加速**，越早开始落库越好

**验收标准**：脚本产出 n≥30 簇 / 分年分解 / 复利净值（项目三重检验铁律）

### 缺口 3：绩效归因按入场理由分组

**问题**：现在知道"**执行率**多少"，不知道"**哪种入场理由赚/亏、哪种理由最该被禁**"。

**为什么重要**：用户框架原话——"复盘要区分**逻辑错 / 时机错 / 执行错**"。
执行率只覆盖"执行错"这一种。

**落地形态**：
```
按 ① 主力阶段（mainforce.phase）② 战法（已证伪，作对照）
   ③ 闸门状态（ready 1/2/3）④ 放弃理由分组
各自算 T+5/T+20 超额（对中证1000），输出"哪种理由的期望最差"排行
数据源：coach_alerts（80 张）+ mainforce_state + 缺口 1 的基准
```

**成本**：**0.5–1 天**（纯聚合）
**依赖**：缺口 1（基准）
**验收标准**：任意分组下 `n` 与分组和 = 总数；超额口径与缺口 1 一致

## 四、优先级建议

| 优先级 | 事项 | 成本 | 依赖 | 收益 |
|---|---|---|---|---|
| **P0** | **缺口 1：基准双口径**（回填中证1000/500 + 报表改口径）| 0.5 天 + 1 晚 | 无 | **复盘第一次能回答"我做得怎么样"**；且是缺口 2/3 的**共同前置** |
| **P1** | **缺口 2：先落库、后验证**（写预注册脚本 + 确认 `gate_snapshot_history` 每日写入）| ≤0.5 天 | 无（基准可后补） | 让**唯一买入入口**走上"可被验证"的轨道；**样本要等，越早越好** |
| P2 | 缺口 3：绩效归因分组 | 0.5–1 天 | 缺口 1 | 从"执行率"升级到"哪种理由最差" |

**建议顺序**：`P0 立即做 → P1 立即起跑（落库不等开发）→ P2 随后`。

## 五、明确**不做**的（避免重复讨论）

| 不做 | 原因 / 出处 |
|---|---|
| **再加仪表类功能** | 2026-09-29 已交付 10 项；边际收益趋零，会引开对 §3 的注意力 |
| **A2 价格源扩全市场** | 已研判**暂缓**：用户无创业板/科创板购买资格 ⇒ 无标的可做（见 A2 文档 §8）|
| **VIX → 仓位联动** | 项目已复核否决（与 NQ 重叠 Jaccard 0.52，并入后 10 日差 2.53→2.05pt 稀释）|
| **金十「沪深资金体量拆解」/ 南向资金** | 数据已有（东财四档 + `mainflow_history`）、预测力已否、展示已覆盖（`scan_index_vs_mainflow`）|
| **北向资金恢复/替代源** | 断供 + 自有资金流无预测力，**双重否定已定论** |
| **构造等权池做基准** | 需全市场日线历史 ⇒ 与 A2 同一约束；用中证1000 指数替代（一条线，成本低）|

## 六、一句话

> 工作台能准确告诉你「**市场是什么样**、**你有没有守纪律**」，
> 还不能可靠回答「**你的方法到底赚不赚钱**」。
> 补齐路径不是加功能，而是**换对基准（P0）→ 让入口可被验证（P1）→ 归因到理由（P2）**。
