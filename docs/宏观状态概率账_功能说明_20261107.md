## 一、一句话定位

**每个交易日，把当天已入库的宏观证据按四类判据打一遍分，归一化成一个互斥分布，连同"哪条证据支持/缺失"一起存进数据库，供日后复盘。**

```
证据（thesis_evidence 已抄好的 6 个品种）
   ↓ 每类 6 条判据逐条比对
四类得分率 = 命中条数 / 可评估条数
   ↓ 归一化
{"soft": 0.375, "stag": 0.25, "rec": 0.375, "overheat": 0.0}
   ↓
macro_regime_class（每日一行）+ macro_regime_events（分布变化留痕）
```

**四类**：`soft` 软着陆 / `stag` 滞胀 / `rec` 衰退 / `overheat` 过热。

**首日真实结果**（`date=2026-11-06`）：

```
软着陆 38% / 衰退 38% / 滞胀 25% / 过热 0%
```

> **重要**：这里的数字**不是统计意义上的概率**（没有校准、没有频率学含义），
> 是「各类判据与当日证据的吻合度」归一化后的相对权重。
> 请读作「今天证据更像软着陆和衰退、各占一半」，**不要**读作「有 38% 的概率软着陆」。

## 二、功能点清单

| # | 功能点 | 位置 | 说明 |
|---|---|---|---|
| 1 | 四类互斥分布 | `compute()` | 纯函数：输入证据字典，输出 `dist`；不连库、不调 LLM、不读全局状态 |
| 2 | 判据打分 | `_RULES`（每类 6 条） | 阈值见下方「判据速查」；`stag` 与 `overheat` 在油价/10Y 上同阈值，靠美元、铜、纳指区分 |
| 3 | 缺失证据处理 | `compute()` | 缺项传 `None`、**不进分母**；缺数据 ≠ 不满足 |
| 4 | 证据不足状态 | `evidence_status` | 可评估类别 < 2 时返回 `insufficient`、`dist=None`，**不拿均分冒充结论** |
| 5 | 证据组装 | `features()` | 从 `thesis_evidence` 取当日快照，回溯 **5 个快照行**算 5 日变化 |
| 6 | 每日落库 | `snapshot()` | `macro_regime_class` 按 `date` 主键 upsert，同日重跑覆盖 |
| 7 | 分布变化留痕 | `snapshot()` | `macro_regime_events` append-only，记录 `old_dist / new_dist / delta(pp) / reason` |
| 8 | 只读接口 | `load()` | 读某日（默认最新）；零网络；返回中文名 `dist_cn` |
| 9 | 日批任务 | `task_macro_class` | 注册名 `macro_class`，排在 `thesis_resolve` 之后，每日自动跑 |
| 10 | 单测 | `backend/test_macro_regime_class.py` | 19 项断言：Σ=1 / 缺证据 / 全缺 / 单类不足 / 可复算 / 不改入参 / 默认日期口径 |

### 判据速查（以 `backend/app/macro_regime_class.py::_RULES` 为准）

| 证据 | 软着陆 | 滞胀 | 衰退 | 过热 |
|---|---|---|---|---|
| 布伦特 5 日 % | ≤ +2 | ≥ +5 | ≤ −5 | ≥ +5 |
| 美 10Y 5 日 bp | ≤ +5 | ≥ +15 | ≤ −15 | ≥ +15 |
| 美元指数 5 日 % | \|v\| ≤ 1.0 | ≥ +1.0 | ≥ +1.5 | ≤ −1 |
| 铜 5 日 % | ≥ −2 | ≤ −2 | ≤ −5 | ≥ +3 |
| 纳指 5 日 % | ≥ 0 | ≤ −2 | ≤ −5 | ≥ +3 |
| VIX 水平 | ≤ 20 | 20~28 | ≥ 28 | ≤ 18 |

## 三、什么作用

### 3.1 补的是哪块缺口

项目里已有三套相关能力，各自缺一角：

| 已有 | 输出 | 缺口 |
|---|---|---|
| `stagflation` | 单个状态位 + 2 日滞回 | 没有「过热」态；只有一个标签，看不出"有多确定、次可能是什么" |
| `llm.scenarios` | LLM 给的情景概率 | **不可复算**，只能当叙事，无法证伪 |
| `thesis_tracker` | 假设 + 证据快照 | 记录的是"某个具体假设对没对"，不是整体宏观环境 |

本模块补的是：**一个可复算、可证伪、带证据明细的"当日宏观环境分布"**。

### 3.2 三条实际用途

1. **复盘时能还原"当时怎么想"**：`support_json` / `contradict_json` 记着哪几条证据支持、哪几条缺失，`per_class_json` 记着每类命中数与得分率。半年后回看某次判断，不用靠回忆。
2. **把"模糊"显式表达出来**：首日 `软着陆 0.375 / 衰退 0.375` 并列，本身就是信息——说明当天证据在两类之间无法区分。单个状态位做不到这件事（它必须选一个）。
3. **给未来的验证留样本**：分布每天落一行，攒够样本才能谈"这套判据有没有预测力"。**注意：现在 N<30，不校准、不下这个结论。**

### 3.3 不接的地方（硬约束，不是保守）

```
✗ market_regime（评分权重）    ✗ trade_gate（准入）
✗ position_sizing（仓位上限）  ✗ 模拟盘
✗ position_hint（仓位提示文字）
```

**分类层可以接，动作层不能接。** `regime 判市减仓`、`Top50 买入`、`试错仓` 都已是 `FAIL/KILL`，再让一套未校准的分类去动仓位，等于把未验证的东西接到已经证伪的链路上。

### 3.4 与 `stagflation` 的关系

**并行观察，不合并。** 一个是状态位 + 滞回，一个是当日分布；合并需要先证明两者长期一致，目前没有证据。观察期至少 4~6 周。

## 四、怎么用（当前可用的全部操作）

### 4.1 什么都不用做

`macro_class` 已挂进日批，跑在 **GitHub Actions 云端**，排在 `thesis_evidence` 之后。日批日志里会看到：

```
宏观分类: 软着陆 38% / 衰退 38% / 滞胀 25% / 过热 0%（v2026-11-07.1·数据日 2026-11-06）
```

证据不足时（合法状态，不是报错）：

```
宏观分类: 证据不足（可评估类别 <2）· 数据日 2026-11-06 · ...
```

### 4.2 查已落库的数据

本地与服务器连的是同一个库，**本地就能查，不必登服务器**（也省流量）：

```bash
cd backend
python -c "
import sys; sys.path.insert(0,'.')
from dotenv import load_dotenv; load_dotenv()
from app import macro_regime_class as mrc
r = mrc.load()
print(r['date'], r['dist_cn'], r['evidence_status'], r['observed_period'])
"
```

服务器上把 `python` 换成 `.venv/bin/python`（工作目录 `/www/wwwroot/stock-scoring-v2/backend`），
**前提是服务器已部署本模块**；未部署时直接用本地即可。

看多日序列：

```sql

FROM macro_regime_class ORDER BY date;

SELECT date, old_dist, new_dist, delta_json, reason
FROM macro_regime_events ORDER BY date, id;
```

## 五、注意事项

### A. 使用边界（最容易误读的三条）

1. **当前只落库、不出界面**。没有 API 端点、没有前端组件，`load()` 是唯一读口。11-14 核对通过前，不要给它接 UI。
2. **数字不是校准概率**。是"证据吻合度的相对权重"，没有 Brier / 命中率背书。N<30 之前**不做校准**，也不要对 0.375 与 0.38 的差别做任何解读。
3. **不进任何决策链**（见 3.3）。这是设计约束，不是暂时没接。

### B. 数据与时点（本项目已在此栽过多次）

4. **`date` 必须是「数据所属交易日」，不是运行日**。
   曾经用"今天"作默认值，周六手动跑一次就写出 `date=2026-11-07`（不存在的交易日），而 `load()` 是 `ORDER BY date DESC`，伪日期永远排第一，且**不报错**。
   现默认走 `latest_completed_trading_day()`。**手动传 `day` 时也要传交易日。**
5. **`observed_period` ≠ `date`**。`observed_period` 是实际用到的证据快照日。日批没跑 / 周末时 `features()` 会**回退到最新一份**证据并如实标出，这时两者会差一天——**这是如实，不是 bug**，但读数据时要看 `observed_period` 才知道用的是哪天的行情。
6. **回溯用「快照行」不是自然日**。`thesis_evidence` 只在日批写一行，跨周末/长假时"5 个自然日"可能只对应 1 行。代码取 `LIMIT 5 ORDER BY date DESC`。
7. **历史不足 5 行时算不出变化量**。`features()` 要求 `len(rows) >= 5` 才取最旧那份做基准，否则 5 日变化全是 `None`，只剩 VIX 一条可评估 → 各类 `avail < 2` → `insufficient`。新环境或证据表被清后属正常现象。

### C. 计算口径（改代码前必读）

8. **缺失不进分母**。把缺失当 0 会让"没读到铜价"变成"铜没涨"，直接把衰退判错。改 `_RULES` 或 `features()` 时不要破坏这一条。
9. **`insufficient` 时 `dist` 必须是 `null`**，不许填 `{0.25, 0.25, 0.25, 0.25}` 冒充均匀分布。
10. **可评估类别 < 2 就不给分布**。只剩一类可评时给 100%，会把"其余都没数据"伪装成"高度确定"。
11. **Σ=1 靠末位补残差**。四舍五入的误差补到 `dist` 最后一个键上，别对第 4 位小数过度解读。
12. **改任何阈值必须递增 `SCORER_VERSION`**（当前 `2026-11-07.1`），否则不允许覆盖历史行。版本号是"同一份证据能否复算"的前提。
13. **可复算是硬要求**：`compute()` 必须保持纯函数。给定同一份 `evidence` + 同一 `scorer_version`，任何人都要能推出完全相同的 `dist`。**不要**把 LLM、全局状态、当前时间塞进去。

### D. 日批与运维

14. **`macro_class` 必须排在 `thesis_evidence` 之后**（它读的就是那一行快照）。顺序错不会崩，只会静默回退到前一日、慢一天。
15. **`scripts/daily_batch.py` 的两个硬约束**：执行顺序看 `DEFAULT_ORDER`（不是 `TASKS` 字典顺序）；`TASKS` 与 `DEFAULT_ORDER` 必须一一对应，模块级 assert 会拦截错配（历史上 `risk_calendar` 曾注册却漏排单，导致静默断档）。
16. **「证据不足」不是 WARN**。周末、数据未积累都会这样，日志里当合法状态输出；写成 WARN 会让人以为日批挂了。
17. **失败不抛**。观察器缺一天不影响主链，`task_macro_class` 的异常只回一行 `WARN`。
18. **`macro_regime_events` 是 append-only**。分布变化只追加，不回头改历史行；`reason` 必填，`created_by` 目前只有 `rule`（人工覆盖通道留着但没启用）。
19. **`MRC_MIN_EVIDENCE`** 可覆盖"单类至少几条可评估证据"的门槛（默认 2），改动会改变历史口径可比性，调之前先想清楚。

### E. 流量与本地开发

20. **零新增数据源**。证据全部来自 `thesis_evidence`（由 `task_thesis_evidence` 从 `macro_daily.panel` 抄好），本模块不发起任何外部行情请求。
21. **本地开发期间不额外耗流量**：日批跑在云端 Actions，本地开着服务、前端反复热更新都不会触发它。手动试跑也只读本地数据包和已有库表。

### F. 已知偏差与过期说明（别被旧文字带偏）

设计文档 §三/§四/§六 是**设计意图**，第一版实现有四处与之不同。**以实现为准**，
日后要按验收标准收口时，改的是代码不是文档：

1. **`contradict_json` 存的是「缺失」，不是「反证」**。
   设计文档 §4.1 写"当日反证的证据（进入/证伪分离存储）"，实现是：

   ```python
   support    = {c: d["support"] ...}   # 命中判据的键
   contradict = {c: d["missing"] ...}   # 值为 None / 无法转 float 的键
   ```

   **有值但没命中判据的键（真正的反证）没有单独存**，只能从 `per_class_json`
   的 `avail - hit` 反推。想按"反证"用之前，先修实现或明确按"缺失"语义读。

2. **`insufficient` 的触发条件更严格**。设计文档 §三 写"全部类都 < 2 → insufficient"；
   实现是 **"可评估类别数 < 2 → insufficient"**（只剩一类可评时也不给分布，
   因为给 100% 会把"其余没数据"伪装成"高度确定"）。见注意事项 10。

3. **`Σ dist = 1` 没有写入断言**。设计文档 §六.1 要求"写入时断言，不符合拒绝落库"；
   实现靠**末位补残差**（见注意事项 11）保证和为 1，没有独立断言。

4. **验收标准 4 / 5 目前是约定，不是代码强制**：
   - 事件写入包在 `try/except` 里，失败只打一行日志，不保证"任何 dist 变化必有事件行"；
   - `scorer_version` 只做记录，**改阈值不递增版本号不会被引擎拦下**。

   这两条靠纪律维持，改动 `_RULES` 时务必手动递增版本号。

5. **模块顶部 docstring 已过期**：`macro_regime_class.py` 开头仍写
   "本模块只做离线计算 + 落库，**不接日批**……第 3 步之后再谈"。
   那是挂日批之前的说明，**当前已挂进日批**。判断现状以
   `scripts/daily_batch.py` 的 `TASKS["macro_class"]` 为准，别被旧注释误导。
