> 缘起：一份外部评估提出「把四套各自为政的宏观类别合成一张互斥穷尽、Σp=1 的概率账」。

## 一、先纠正一个事实：这两套根本不是同一种东西

| 维度 | `scenario_watch` | `llm.scenarios`（`flash/llm.py`） |
|---|---|---|
| 回答什么 | 「我登记的那个磨底推演，**现在被证伪了吗**」 | 「**今天**可能怎么走」（叙事假设） |
| 情景定义 | **固定 3 个**：基准（磨底）/ 熊市加深 / 提前修复 | LLM 自由命名 2~3 个 |
| 概率 | **无** | 有（2026-11-07 起强制 Σ=100） |
| 判定方式 | **确定性规则**：`bear = 油价≥120 或 10Y≥5.3 或 上证<3500` | LLM 推断 |
| 可证伪 | **是**（触发器事前写死、每日判命中） | 否（每次自由生成，无法与上次对齐） |
| 时间窗 | 6~8 周（磨底推演） | 当日 |
| 数据源 | 既有观察器（零新源） | 快讯 + 宏观面板 |
| 落库 | `scenario_watch` 表 | `flash_analyses.output_json` |

**关键点：`scenario_watch` 的 55%/20%/25% 只写在注释里**（用户当初推演时给的），
`evaluate()` 从头到尾**不产出任何概率**。所以「给它加概率」不是补全，是改造。

## 二、结论：**不合并**，做「分工 + 防混淆」

### 为什么不让 `scenario_watch` 吸收 LLM 概率

`scenario_watch` 的价值**恰恰在于它没有概率**：

- 触发器事前写死 ⇒ 每天能回答「命中/未命中」，**可回测、可审计**
- 一旦引入 LLM 给的分，同一条规则会在不同日子得到不同的 p，
  **「事前冻结」这个性质就没了**，它也就退化成第二个 `llm.scenarios`

**给确定性体系套主观数字，是降级不是升级。**

### 为什么不让 `llm.scenarios` 承担「推演证伪」

它每次调用都重新生成情景，**前后两次的情景名可能完全不同**（"基准/AI 回调/滞胀" ↔ "软着陆/债务危机"），
连"同一个情景"都无法追踪，更谈不上证伪。

### 所以：两套都留着，但必须让人不混淆

| 用途 | 用哪个 | 能否用于决策参考 |
|---|---|---|
| 想看「我登记的推演有没有被证伪」 | `scenario_watch`（观察器区） | 可以，但仍是观察结论 |
| 想看「今天市场在想什么」 | `llm.scenarios`（诊断卡） | **仅参考**，不可证伪，不入决策链 |
| 想看「世界处在哪个宏观状态」 | 目前**没有**（`stagflation` 是单状态位，不是分布） | — |

## 三、具体改动（最小集，纯文案 + 一处提示词）

### 1. 推送文案加来源前缀

`flash/wechat.py` 把 `scenarios` 当「情景」直出，与 `scenario_watch` 的「情景」同名不同义。
→ 改成 **「当日推演」**，并把刚修好的 `probability_numeric` 带上。

### 2. `_prev_digest` 同步

`flash/llm.py` 里把上一次情景塞进 prompt 的那段，同样加前缀，
避免 LLM 自己把两套混为一谈。

### 3. 提示词加一句边界

在输出格式上方写明：「`scenarios` 是**当日叙事假设**，不是对未来 N 日的预测概率，
不要与推演记分卡（scenario_watch）混为一谈。」

### 4. 文档登记

本条写进 `开发文档.md` 的「已证伪/不做清单」：
**「不给 scenario_watch 加概率」** —— 理由是它会摧毁可证伪性。

## 四、与「四分类概率账」的关系（如果将来要做）

三者**层次不同，不冲突**：

```
四分类概率账（若做）  ← 世界状态分布：软着陆 / 滞胀 / 衰退 / AI泡沫 + unknown
        ↑ 输入：macro_daily 证据
scenario_watch        ← 单次推演的证伪记分卡（6~8 周，固定 3 情景，无概率）
llm.scenarios         ← 当日叙事假设（自由命名，有概率但不能追踪）
```

**如果做四分类账，它是新的一层，不是替代上面任何一个。**

但前提没变（见 P0 的教训）：**先把 `Σp=1` 变成硬约束，再谈新建。**

## 五、验收标准

改完后应满足：

1. 用户在推送/卡片上能一眼分清「推演记分卡」与「当日推演」
2. `scenario_watch` 表**仍然没有**概率列（这是有意为之，不要"顺手补上"）
3. `llm.scenarios` 的概率仍然是 Σ=100（`test_scenario_probs.py` 9/9）
4. 两处文案里不出现孤立的「情景」二字指代 `llm.scenarios`
