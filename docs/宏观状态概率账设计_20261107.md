# 宏观状态概率账（`macro_regime_class`）设计

> 前置：`97806a9b`（情景概率 Σ=100）+ `a1e35ecc`（情景体系不合并）。
> 本文只做**设计**，不落代码；写代码前请先过 §一 那个问题。

## 一、先回答：概率从哪来？

这是这个功能能否成立的前提。三条路：

| 方案 | 概率来源 | 可复算 | 可证伪 | 评价 |
|---|---|---|---|---|
| A | **LLM 打分** | ❌ | ❌ | **直接否决**——与 `thesis_tracker` 铁律②（裁决权不在 LLM）冲突 |
| B | **规则打分 → 归一化** | ✅ | ✅ | **推荐** |
| C | 人工填 | ✅ | ⚠️ | 只在"覆盖"场景用（带 reason 留痕） |

**采用 B（规则打分）+ C（人工覆盖）**，理由：

> 给定同一份证据和同一套阈值，**任何人都能推出同样的分布** ⇒ 这才是可复算的。
> 不可复算的概率，和 `llm.scenarios` 一样只能当叙事。

**核心约束：分布必须是证据的函数，不是判断的函数。**

## 二、四类的定义

默认四类（**可配置，改枚举须在此留痕**）：

| 类 | 含义 | 与 `stagflation` 的关系 |
|---|---|---|
| `soft` 软着陆 | 通胀回落、增长放缓但不失速 | 近似 `正常` |
| `stag` 滞胀 | 油价 + 长端同升、增长停滞 | **等价** `滞胀交易` |
| `rec` 衰退 | 需求塌陷、风险资产杀跌 | 近似 `衰退前夜` |
| `overheat` 过热 | 需求强、通胀再起、商品与股指同涨 | **新增**（`stagflation` 没有这一态） |

**注意**：`stagflation` 只有 3 个实态 + `数据不足`，**这里不是它的复制品**——多出 `overheat`，
且**输出的是分布不是状态位**。**两套并行观察，不合并**（同 `a1e35ecc` 的结论）。

## 三、证据与判据（第一版）

证据全部来自 `macro_daily.panel`，**复用 `thesis_tracker._EVID_ASSETS` 已抄的 11 个品种**，零新数据源。

| 证据 | soft | stag | rec | overheat | 口径 |
|---|---|---|---|---|---|
| 油价（brent）5 日变化 | ≤+2% | **≥+5%** | ≤−5% | ≥+5% | 相对 5 交易日前 |
| 美 10Y 5 日变化 | ≤+5bp | **≥+15bp** | ≤−15bp | **≥+15bp** | 绝对 bp |
| 美元（dxy）5 日 | 稳 | ≥+1% | **≥+1.5%** | ≤−1% | 避险时美元升 |
| 铜 5 日 | ≥−2% | ≤−2% | **≤−5%** | **≥+3%** | 需求代理 |
| 纳指 5 日 | ≥0 | ≤−2% | **≤−5%** | ≥+3% | 风险偏好 |
| VIX 水平 | ≤20 | 20~28 | **≥28** | ≤18 | — |

**打分方式**：

```
每类得分率 = 该类别命中条数 / 该类别**可评估**条数
（缺失的证据不进分母 —— 缺数据 ≠ 不满足）
```

**归一化**：

```
可评估条数 < 2 的类 → 该日不参与归一化，标 class_insufficient
全部类都 < 2      → evidence_status = "insufficient"，dist = null（不强行给）
否则              → dist[c] = score[c] / Σ score，Σ dist = 1（容差 1e-6）
```

**★ 这条是整套设计里最容易被写错的地方**：把缺失当 0 会让"没读到铜价"变成"铜没涨"，
直接把 `rec` 判错——与 `policy_bottom_watch` "缺失 ≠ 不满足"是同一条纪律。

## 四、表结构

### 4.1 `macro_regime_class`（每日一行）

```sql
CREATE TABLE macro_regime_class (
    date              TEXT PRIMARY KEY,
    dist_json         TEXT,      -- {"soft":0.45,"stag":0.25,"rec":0.20,"overheat":0.10}
    evidence_status   TEXT,      -- ok / insufficient
    support_json      TEXT,      -- 当日支持各类的证据明细（可追溯到品种+数值）
    contradict_json   TEXT,      -- 当日反证的证据（进入/证伪**分离**存储）
    observed_period   TEXT,      -- ★ 数据所属期（防"发布日 ≠ 数据期"）
    scorer_version    TEXT,      -- 判据版本；改阈值必须换版本号
    updated_at        TEXT
);
```

**`observed_period` 为什么必须有**：CPI 11 月中旬公布的是 **10 月**数据，
对应的是**当时的油价环境**。若只用 `date`（跑批日），自动采集会把 10 月 CPI
当成 11 月的环境读数，机械地往 `stag` 搬概率 —— 这是本项目踩过四次的
"写入时刻 ≠ 数据所属时刻"的同型错误。

### 4.2 `macro_regime_events`（append-only 留痕）

```sql
CREATE TABLE macro_regime_events (
    id           SERIAL PRIMARY KEY,   -- SQLite: INTEGER PRIMARY KEY AUTOINCREMENT
    date         TEXT,
    old_dist     TEXT,
    new_dist     TEXT,
    delta_json   TEXT,        -- {"soft":+5,"stag":-5}，单位 pp
    reason       TEXT,        -- 必填
    trigger_event TEXT,       -- 什么事件/哪条证据推动的
    created_by   TEXT,        -- rule / manual
    created_at   TEXT
);
```

**双库兼容**（`thesis_tracker.py:208` 的写法）：

```python
pk = "SERIAL PRIMARY KEY" if db.is_postgres else "INTEGER PRIMARY KEY AUTOINCREMENT"
```

**JSON 一律存 TEXT 列**（SQLite 不认 `JSONB`）。

## 五、与现有模块的接线点

| 环节 | 接哪 | 说明 |
|---|---|---|
| 证据采集 | **复用** `thesis_tracker.collect_evidence()` | 已抄 11 品种，`missing` 列表现成 |
| 日批挂载 | `daily_batch.py` 的 `task_thesis_evidence` **之后** | 同一批证据，不重复拉 |
| 读侧 | 新端点 `GET /api/system/macro-class` | 只读，60s 缓存 |
| 前端 | 观察器一行（默认收起） | 与「市场底清单」同级，不进主区 |
| 校准 | **不做**（N<30） | 见 §七 |

**★ 不接的地方**（这是硬约束，不是保守）：

```
✗ market_regime（评分权重）      ✗ trade_gate（准入）
✗ position_sizing（仓位上限）    ✗ 模拟盘
✗ position_hint（仓位提示文字）
```

**理由**：`regime 判市减仓` 已经是 `FAIL/KILL`（vs 永远满仓 −0.30pt/20 日），
`Top50 买入` 也是 `FAIL/KILL`，`试错仓` 三次被冻结。**分类层可以接，动作层不能接。**

## 六、验收标准

1. `Σ dist = 1`（容差 `1e-6`）—— 写入时断言，不符合直接拒绝落库
2. `evidence_status = insufficient` 时 `dist` 必须为 `null`（**不许填 0.25×4 冒充均匀**）
3. **可复算**：同一份 `support_json` + 同一 `scorer_version`，重跑得到完全相同的 dist
4. `events` 表 append-only：任何 dist 变化必须有对应事件行，`delta` 之和与 `new−old` 一致
5. 改阈值必须递增 `scorer_version`，否则不允许覆盖历史

## 七、第一版明确不做

| 不做 | 原因 |
|---|---|
| 校准（Brier / 命中率） | N < 30，出任何结论都是噪音（同 `thesis_tracker` 铁律③） |
| 与 `stagflation` 合并 | 先并行观察 4~6 周，看两者是否长期背离 |
| 动作映射 | 见 §五 硬约束 |
| LLM 参与打分 | 铁律② |
| 自动搬运概率 | 第一版只记当日分布，不做"事件 → Δ 转移"；转移表需要先有 ≥20 个真实事件样本 |

## 八、落地顺序（建议）

1. 建两张表 + `compute()` 纯函数（可单测，输入 evidence、输出 dist）
2. 单测：缺证据 / 全缺 / 单类不足 / Σ=1 断言
3. 挂日批（`task_macro_class`），**先只落库不展示**，跑 5 个交易日
4. 人工核对 5 天的 dist 是否与"当天盘面常识"一致 —— **不一致先改判据，再上界面**
5. 加只读端点 + 观察器一行

**第 4 步是关键闸门**：如果规则算出来的分布与常识明显背离，说明判据错了，
**不要着急上界面**——那会让用户对一套还没验证的东西建立信任。

## 附：与「四分类账」原始提案的差异

原始提案主张直接新建账本并接 discriminant 仪表盘。本文的三处修正：

1. **概率必须可复算**（规则打分），不采用 LLM 打分
2. **`insufficient` 是独立状态**，不是第五类概率（更不是"均分 25%"）
3. **先并行观察，不合并** `stagflation`——合并需要先证明两者长期一致
