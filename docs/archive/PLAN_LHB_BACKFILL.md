## 1. 要解决什么（现状实测，2026-10-14）

| 侧 | 现状 | 判断 |
|---|---|---|
| **事件侧** `lhb_history` | **2026-05-06 ~ 2026-10-13，8,460 行 / 2,438 只（约 5 个月）** | ★ **唯一瓶颈** |
| **收益侧** | `data/zzshare_daily.db`（本地 SQLite 4.2GB）：**2005-01-04 ~ 2026-09-24 / 16.7M 行 / 6,123 只**，含 `pre_close/factor/high_limit/is_st` —— `lhb_edge_check` v2 已在用（**零 egress**） | ✅ 已备好 |
| 解析/写入 | `app/mainforce/lhb.py::fetch_day_list(date)`（zzshare `lhb_list`）+ `save()`（`ON CONFLICT(code,date)` 幂等）；调度 `lhb_refresh_loop` 每日 17:45 | ✅ 可复用 |
| 消费方 | 诊断卡/详情页风险标签（`recent_summary`）、日报 `_lhb_summary`、预登记检验 `scripts/lhb_edge_check.py` | 仅回填**数据**即可，不动消费方 |

**两个具体痛点**：① `lhb_edge_check` 的 5 个月窗口跨不了完整市况 ⇒ 结论被迫停在
PARTIAL（覆盖率问题已由 v2 解决，剩的是**样本期**）；② 任何"LHB × 个股信号"的交叉
假设当前**没有样本**（实测 2 观测）。

## 2. 目标（一句话）

把 `lhb_history` 从 5 个月扩到 **N 年**（N 由用户定，见 §3 成本），使
① 龙虎榜回避信号可**长窗口定案**；② 交叉假设（须**另立**预登记）具备样本基础。

|---|---|---|---|---|---|---|
| ~~小~~ | ~~2023-01-01~~ | — | — | — | — | ❌ **源无数据**（实测 0 行） |
| ~~建议~~ | ~~2019-01-01~~ | — | — | — | — | ❌ **源无数据**（实测 0 行） |

## 4. 设计要点（6 条纪律）

1. **复用生产解析，禁止另写**：逐日调 `mainforce.lhb.fetch_day_list(date)`（它内部已做
   `lhb_list` 包装与字段归一）⇒ 回填结果与日批**同口径**；**直接写现有 `lhb_history`**
   （不建新表 —— 避免"第二事实源"，同 `displayMeta` 的既有教训）。
2. **断点续传**：独立进度表 `lhb_backfill_progress(date, n, done_at)`（**不用**
   "表内该日计数 > 0"判断 —— 防写半日被误判完成，同 `mf_edge_backfill` 先例）；
   逐日 upsert + 每 20 日打印 + 3 次重试（退避 2s/4s）+ 失败清单。
   ★ **非交易日返回空 ≠ 失败**：`trade_days()` 取的日子都是交易日；若某日返回 0 行，
   记 progress（n=0）并在日志标注（zzshare 偶尔对老日期返回空，需人工看清单）。
3. **顺带修复旧行 NULL**：`circ_mktcap`（上榜日流通市值）是 2026-10-11 才入库的
   ⇒ 现有 5 个月里 10-11 之前的行该列为 NULL（风险标签对科创板/北交所需回退）。
   回填走 `fetch_day_list` 会带上 `circ_price` ⇒ **这些旧行顺带被补齐**（一举两得）。
4. **一致性闸（必过才能用于检验）**：与现有窗口（**2026-05-06 ~ 2026-10-13**）
   **逐日逐票**对齐，比对 `net_buy / quote_change / circ_mktcap`：**一致率 ≥ 95%**
   （学 `mf_edge` 的 99.0% 先例）；不一致样本要**打印前若干条**（便于判断是源漂移还是解析 bug）。
5. **不做**：不富化 `seats_json`（`lhb_detail` 逐股调用，慢；回填不碰）；
   不改 `lhb_edge_check` 的任何判据（回填后**复跑同一脚本**即可，它的覆盖率门已由 v2 处理）；
   不接入生产推送；不引入第二个数据源。
6. **风险与限定（写进结果页）**：zzshare 匿名限流（节流 + 重试）；历史字段可能缺
   （`up_reason`/题材/换手 在老日期可能为空 ⇒ NULL 并披露）；退市股名称可能取不到
   （`name` 缺失不阻断，只影响展示）；**回填不改任何生产参数**。

## 5.5 ★ **实施规格 v1.1（冻结，2026-10-14 —— ★ v1.0 跑前实测修订，留痕见 §8）**

> ★★ **v1.1 修订原因（实测，非推测）**：v1.0 按用户拍板"2019 起"冻结；随后**冒烟测试
> 与逐点探测**发现 **zzshare `lhb_list` 的覆盖起点 = 2025-01-02**
> （2024-12-31 → 0 行；2025-01-02 → 80 行；2023/2024 各探测点全 0）
> ⇒ **2019 不可达是数据源限制，不是我们的成本限制**。
> ⇒ 现实范围改为 **2025-01-02 ~ 2026-05-05**（~320 交易日）。

1. **范围**：回填 **2025-01-02 ~ 2026-05-05**（不含已有窗口，避免无谓请求）；
   **一致性闸模式**取已有窗口的 **最近 12 个交易日（~2026-05-06 起）**做**只读比对**（不写入）。
   ⇒ 完成后 `lhb_history` 覆盖 **2025-01-02 ~ 2026-10-13（约 21 个月）**，
   事件量预计从 8,460 → **~2.5-3 万（×3）**。
2. **解析**：一律调 `app.mainforce.lhb.fetch_day_list(date)`（生产函数，禁止另写）；
   `date` 由脚本补（与生产 `refresh()` 的 `it["date"] = d` 完全一致）；`seats = None`
   （**不**触 `lhb_detail`）。
3. **写入**：`lhb_history` 批量 upsert（**多值 `ON CONFLICT (code,date) DO UPDATE`，
   50 行/语句**；语义与生产 `save_rows` 逐行版**逐字段一致**：`name/net_buy/quote_change/
   up_reason/concepts/turnover_ratio` 直接覆盖，`circ_mktcap` 与 `seats_json` 用
   `COALESCE(EXCLUDED, 旧值)` ⇒ 不抹掉已有富化）。**不建新表**。
4. **进度/断点**：新表 `lhb_backfill_progress(date PRIMARY KEY, n INTEGER, done_at TEXT)`
   （Supabase；**0 行也记**并被标为 `empty`，与"失败"区分；失败不记 ⇒ 重跑自动补）。
5. **限速与重试**：每请求间隔 **0.5s**；单日解析失败重试 3 次（退避 2s/4s）；
   DB 写入重试 3 次；每 20 日打印进度（含累计行数/耗时/预计剩余）；结束打印失败清单。
6. **一致性闸（门）**：对 12 个重叠交易日，逐日**按 code 对齐**比对
   `net_buy / quote_change / circ_mktcap` 三字段，字段级一致率 **≥ 95%** 才算过；
   不一致时打印前 5 条样本（`code + 两侧值`）便于判定是源漂移还是解析缺陷。
7. **验收（6 条，见 §6）** 全过才用回填数据跑检验；`lhb_edge_check.py` **判据一行不改**。

## 6. 验收清单

- [ ] **一致性闸 ≥ 95%**（重叠段字段级比对）
- [ ] `circ_mktcap` 补齐：2026-10-11 之前的旧行 NULL 比例显著下降（打印前后对比）
- [ ] `lhb_edge_check.py` 复跑：从"窗口 5 个月"变为"窗口 N 年"，判定状态**如实报告**

## 7. 明确的非目标

- **不是**"把龙虎榜变成买入信号"（它是**回避侧** PASS、且次日开盘不可交易）；
- **不是**交叉假设的检验（LHB × 吸筹∧三绿 等**必须另立预登记**：唯一组合、冻结判据、
  样本闸、α 调整 —— 本项只负责**把数据备齐**）。
- **不再追求"深度历史"**：源（zzshare `lhb_list`）实测只到 2025-01-02 ⇒ 若将来需要更长
  历史，必须换源或另找数据（届时**另立**设计稿，不在本项范围内）。

### 9.2 复跑既有检验（判据一行未改）—— ★ 结论：**维持"仅作回避参考"原判**
1. **`lhb_edge_check.py`（收盘入场口径）**：big_buy T+5 **+1.16%**（45.0%，n=4,609）
   vs big_sell **−3.08%**（32.6%，n=3,311）⇒ diff **+4.24pct**、聚类 bootstrap（416 簇）
   95%CI **[+3.40, +5.08]**、P=0.0000 ⇒ **PASS**；分年同向（2025 / 2026）。
2. **`lhb_executability_check.py`（次日开盘口径 = 可执行终验）**：diff 收窄至 **+0.69pct**、
   95%CI **[−0.09, +1.45]（跨 0）**、P=0.0411 ⇒ **PARTIAL（未达 GO）**。
   绝对收益（扣 0.30%）：**big_buy 净 −0.52%（胜率 41.4%）⇒ 多头侧不成立**；
   big_sell 净 −1.21% ⇒ **空头/回避侧明确**。
