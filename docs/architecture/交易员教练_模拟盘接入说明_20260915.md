## 1. 一句话定位

**教练不是一个选股工具，而是一套"纪律执行系统"。**
它的目标不是"选出更好的股票"，而是把用户**临场决策**（看到浮亏想再等等、看到涨了想追）改写为**事前决策**（开仓那一刻就把"什么时候走"写死），并度量"用户有没有照做"。

> 简报 §3.2 原话：教练 KPI 是"本周劝住几次操作"，不是"建议胜率"。

## 2. 四条设计红线（评审结论，不可逾越）

| # | 红线 | 落地方式 |
|---|---|---|
| ① | **事前无权**：LLM 不能决定任何事实 | 判定与数字全部由 `rules.py` 代码生成；LLM 只做措辞，且**输出禁止出现任何数字**（含复述规则数字）→ 含数字即丢弃 |
| ② | **不放大 egress** | 30s 轮询**只读全市场行情内存缓存** `routers/market._cache`，零额外网络请求；需读 K 线的重规则（ret20 / price_pos）只跑低频路径 |
| ③ | **只读模式下也保留** | 挂在 `asyncio.create_task(coach_loop())`，**不被 `RENDER_READ_ONLY` 关闭**——只读生产环境恰恰最需要纪律提醒 |
| ④ | **先定标尺再谈提升** | 执行一致性口径在 `audit.execution_consistency` 顶部写死（分母 = 已决策，未响应单列） |

## 4. 数据模型

### 4.1 `coach_plans`（入场剧本，预承诺退出计划）

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `code` / `name` | 标的 |
| `position_id` | 关联 `paper_positions.id`（模拟盘仓位） |
| `plan_date` | 剧本日期（= 成交日） |
| `entry_price` | 成交价 |
| `stop_loss` | 止损价（v2 = 介入价 ×(1 − `WARFARE_STOP_PCT_V2`)） |
| `review_date` | 强制评估日（第 N 个交易日，N 读 `rules.yaml`） |
| `trail_trigger_pct` | 移动止损触发浮盈（%） |
| `exit_conditions` | JSON：止损 / 强制评估 / 移动止损 / 提前退出 四条件 |
| `status` | `open` / `closed` / `abandoned` |
| `actual_exit_date` | 实际离场日 |
| `actual_exit_reason` | 实际离场原因（`stop_loss` / `expire` / `manual` / `abandon` …） |
| `abandon_reason` | 主动放弃理由（必填） |
| `followed` | 是否按剧本离场：`1` / `0` |
| `closed_at` | 关闭时间 |

唯一约束：`UNIQUE(code, plan_date)`（幂等：同标的同日只写一条）。

### 4.2 `coach_alerts`（教练建议 + 执行回写）

| 字段 | 含义 |
|---|---|
| `dedupe_key` | `日期|规则|标的`，唯一索引（防 30s 轮询重复推送） |
| `rule_id` / `label` / `severity` | 规则标识 / 中文名 / 三档 `alert`·`warn`·`info` |
| `code` / `name` | 标的（市场级规则为空） |
| `message` | 规则原文（含全部数字） |
| `numbers_json` | 数字快照（审计用） |
| `pushed` | 是否已推企微 |
| `executed` | 执行回写：`yes` / `no` / NULL（未响应） |
| `abandon_reason` | 放弃理由（`no` 时必填） |
| `outcome_pct` / `outcome_date` | T+5 结果回填 |

> 建表做了**零 DDL 探测优化**：先查 `to_regclass` 三对象是否已存在，全在则直接返回——避免 `CREATE TABLE IF NOT EXISTS` 触发 Supabase schema cache 全量重载（egress 元凶 + DDL 取表锁）。

## 5. 运行流程

```
【开仓】paper_trading 成交确认
   └─ write_plan()  → 写 coach_plans（止损 / 第3日复核 / 移动止损 / 提前退出）
                       ★ 把"临场决策"变成"事前决策"，这是教练核心机制

【盘中】coach_loop（30s，asyncio.create_task，只读缓存）
   ├─ coach_tick()：light 规则求值 → 落库去重 → 仅新触发且 push=true 的推企微
   │     └─ explainer.explain_batch()：补一段"人话解说"（禁数字，fail-open）
   ├─ 关键时点 10:30 / 14:45：推"教练体检卡"（每票一行，企微着色）
   └─ 盘后（交易日内 15:40-24:00 幂等）：daily_close_job()
         └─ 全量（含 heavy）求值落库 + T+5 结果回填

【平仓】paper_trading._close_position
   └─ close_plan() → 关剧本；followed = 1 当且仅当 exit_reason ∈ {stop_loss, expire}

【放弃】用户在前端点"放弃剧本"（模拟盘持仓行）
   └─ abandon_plan() → status='abandoned'，abandon_reason 必填，followed=0
```

## 6. 九条规则

阈值集中在 `rules.yaml`，`push` 控制是否推企微（**第一周仅 2 条推送，其余只落库攒样本**，逐周放开防警报免疫）。

| # | 规则 id | 中文名 | 严重度 | 判据（阈值） | 第一周推送 |
|---|---|---|---|---|---|
| 1 | `stop_loss_hit` | 止损触发 | alert | 现价跌破止损位 | ✅ |
| 2 | `hold_3d_review` | 持有满 3 日强制评估 | alert | 持有 ≥ 3 个交易日（对齐退出 v2） | ✅ |
| 3 | `loss_over_7pct` | 浮亏超 7% | warn | 浮亏 > 7% | ✗ |
| 4 | `crowded_trim` | 拥挤赛道借反弹减仓 | warn | 近 20 日涨幅 > 30% | ✗ |
| 5 | `distribution_cut` | 高位 + 主力出货（不等 7% 直接砍） | alert | `price_pos > 0.75` 且命中主力出货 | ✗ |
| 6 | `gate_no_add` | 环境不支持加仓 | info | regime ∈ {neutral_bearish, defensive} | ✗ |
| 7 | `gate_reduce` | 减仓条件命中 | warn | 10Y > 5% 且 DXY > 100；或两融净减 + 情绪寒冷(<30) | ✗ |
| 8 | `gate_add` | 加仓条件命中 | info | 涨跌比 > 0.8 且跌停 < 10 家，**需连续 2 日确认** | ✗ |
| 9 | `emotion_fuse` | 当日浮亏超阈值（情绪熔断） | warn | 当日浮亏 > 2% → **LLM 闭嘴**，只输出规则原文 | ✗ |

> 数据源：行情 = `routers/market._cache`；两融/情绪 = `flash.margin_sentiment`；出货 = `mainforce.overlay`；regime = `backtest.market_regime` 缓存。
> 持仓 = `paper_positions`（模拟盘，标 `[模]`）+ `user_portfolio`（真实持仓，标 `[真]`）合并；真实持仓无止损字段时默认止损 = 成本 × 0.92。

## 7. 两个 KPI（口径务必看清分母）

### 7.1 执行一致性 `execution_consistency(days)`

- 统计范围：近 N 天**已推送**（`pushed=1`）的建议。
- **已决策** = `executed ∈ {yes, no}`；**未响应** = `executed IS NULL` → **单列，不进分母**。
- 执行率 = `yes / 已决策数`；放弃率 = `no / 已决策数`。
- 为什么不用"建议胜率"当 KPI：教练的价值是**劝住冲动**。

> "没看见" 与 "看见了但放弃" 是两回事，混算会虚高执行率。

### 7.2 预承诺执行率 `plan_execution_rate(days)`

- **已结算** = `status='closed'` + `status='abandoned'`（主动放弃也是结算，`followed=0`）。
- 执行率 = `followed=1 的数量 / 已结算数`。
- `followed=1` 当且仅当 `exit_reason ∈ {stop_loss, expire}`（与 `write_plan` 的 exit_conditions 对齐）；`manual` / `take_profit` / `abandon` 均视为未严格按剧本。

## 8. 绩效归因（`GET /api/paper/attribution`）

对**已平仓**的模拟仓位做 5 维切片，复用 `_strategy_stat` 口径（成交 / 胜率 / 均盈亏 / 盈亏比 / 累计 / 均持仓）：

| 维度 | key | 回答的问题 |
|---|---|---|
| 按战法 | `by_strategy` | 哪类信号最赚钱 |
| 按退出原因 | `by_exit_reason` | 利润来自止盈，还是被止损拖累 |
| 按持有天数 | `by_hold_bucket` | ≤2 / 3-5 / 6-10 / 11-20 / >20 天，拿多久最优 |
| 按置信度 | `by_confidence` | 高置信信号是否真的更赚（读 `confirmation_json`） |
| **按剧本执行** | `by_plan_followed` | **守纪律 vs 不守纪律**（教练闭环核心，join `coach_plans.followed`） |

每组按成交数降序。前端「模拟盘 → 归因」Tab 展示，`by_plan_followed` 用 accent 高亮框标注。

## 9. API 清单

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/coach/alerts?limit=` | 建议历史（含执行状态 / 放弃理由 / T+5 结果） |
| POST | `/api/coach/alerts/{id}/execute` | 执行回写 `{executed: yes\|no, reason?}`；`no` 必填理由 |
| GET | `/api/coach/consistency?days=` | 执行一致性 KPI |
| GET | `/api/coach/abandon-reasons?limit=` | 放弃理由清单（高频 = 最易失守纪律点） |
| GET | `/api/coach/plans/execution-rate?days=` | 预承诺执行率 KPI |
| GET | `/api/coach/plans?position_ids=` | 批量查剧本（模拟盘持仓展示） |
| POST | `/api/coach/plans/{id}/abandon` | 主动放弃剧本 `{reason}`，理由必填 |
| GET | `/api/paper/attribution` | 模拟盘 5 维绩效归因 |

全部 JWT 保护。路由函数均为普通 `def`（无假 async）。

## 10. 前端入口

- **`/coach` 教练 Tab**（`CoachView.vue`）
  - 执行一致性 KPI 卡（执行率 / 已决策 / 未响应 / 放弃率，UI 明示"分母=已决策、未响应单列"口径）
  - 预承诺执行率 KPI 卡（执行率 / 已结算（已平仓 + 放弃）/ 持仓中 / 按剧本离场）
  - 建议历史（severity 三档配色、规则原文、T+5 结果回填）
  - 执行回写（✓ 已执行 / ✗ 放弃须填理由，前后端双校验）+ 放弃理由清单
  - 顶部标注「**规则引擎生成，LLM 不参与决策**」

- **`/paper` 模拟盘**（`PaperTrading.vue`）
  - 待确认 / 持仓中 / 已平仓三表均加「教练」列 → 点击「剧本」展开 `CoachPlanDetail`
  - 剧本详情：状态徽章、止损 / 复核日 / 移动止盈触发 / 开仓日、退出条件逐条
  - `open` 状态可「✗ 放弃剧本」（必填理由）；`closed` / `abandoned` 显示结果
  - 「归因」Tab：5 张维度表

## 11. 配置开关一览

| 开关 | 默认 | 说明 |
|---|---|---|
| `COACH_ENABLED` | `on` | 总开关；`off` 完全不评估 |
| `COACH_EXPLAINER` | `on` | LLM 翻译层；`off` 回退"只推规则原文" |
| `rules.yaml` → `rules[].enabled` | 见文件 | 单条规则开关 |
| `rules.yaml` → `rules[].push` | 仅 2 条 true | 是否推企微（其余只落库攒样本） |
| `rules.yaml` → `rules[].params` | 见文件 | 各规则阈值（改阈值不改代码） |
| `rules.yaml` → `plan.trail_trigger_pct` | 15.0 | 移动止损触发浮盈 |
| `rules.yaml` → `plan.price_pos_cut` | 0.75 | 提前退出筹码位置阈值 |

推送走企微分类通道 `coach`（自建应用优先，群 webhook 兜底），`force=True` 不受业务开关限制。

## 12. 已知限制 / 后续

1. **剧本历史缺口**：`coach_plans` 2026-09-13 才上线，此前已平仓的仓位在归因里显示为「无剧本」——属正常历史数据，新仓位会逐步填充 `by_plan_followed`。
2. **第一周只推 2 条**：`loss_over_7pct` / `crowded_trim` / `distribution_cut` / 三条 gate / `emotion_fuse` 仅落库，需逐周放开积累样本。
3. **退出原因集中于超期**：当前样本 `exit_reason` 只有 `timeout_no_trigger` + `expire`，退出 v2 下无止损/止盈触发；需更长样本才能让归因维度丰满。
4. **LLM 翻译层是"锦上添花"**：任何故障（开关 / 熔断 / LLM 不可用 / 输出含数字）都 fail-open 回退规则原文，规则提醒永不缺席。
5. **W3-4 计划**：模拟盘跑 4 周 + 对照审计（规则 vs 规则+LLM）；真实持仓接入最早 W5+。
