## 0. 30 秒上手

**目录**

| 路径 | 是什么 |
|---|---|
| `backend/app/` | FastAPI 后端（评分引擎 / 主力行为 / 矛盾扫描 / 调度器 / LLM 报告） |
| `frontend/src/` | Vue3 工作台（榜单页 / 个股详情 / 观察池 / 持仓雷达 / 交易员简报） |
| `scripts/daily_batch.py` | **唯一计算入口**（日批任务表：`--list` 看全部） |
| `scripts/*_check.py` | 预登记检验脚本（信号能否进决策链的"法庭"） |
| `backend/data/pack/` | 本地数据包（klines ~200 万行 / 指标），**零 egress 读** |
| `data/zzshare_daily.db` | 本地全市场日线库（4.2GB / 6123 只 / 2005 起），**研究工作优先用它** |

**三条运行通道**（搞清楚谁真正在跑，是排障第一课）

1. **Render**（API + 轻量循环）：`RENDER_READ_ONLY=1` ⇒ **`_heavy()` 包装的重循环全部不启动**
   （见 `flash/scheduler.py` 的 `_heavy` 定义与「清扫 ②」留档）。
2. **GitHub Actions**：`backend-pack`（打包）→ `workflow_run` 接棒 `daily-batch`（20:43 后跑完）。
3. **cron-job.org**：19:00 北京触发 pack（GitHub 自带的 `schedule` 只是兜底，实测常晚 4~7h）。

**本地常用**

```bash
python scripts/daily_batch.py --list                    # 看任务表
python scripts/daily_batch.py --tasks <name>            # 单跑一个（补跑/调试）
python scripts/<某>_edge_check.py --json                # 预登记检验（判据写在脚本头）
cd frontend && npm run dev                              # 前端
```

## 3. 工程约定（动手清单）

**3.1 新增一个信号/因子（标准动作）**
1. **先预登记**：判据、样本门槛、GO/DOWNGRADE/KILL 阈值**写死在脚本头**，注明日期；
2. **口径同源**：生产与检验共用同一个函数（例：`lhb.bucket_of` 与预登记脚本逐字一致，有断言）；
3. **接进日批**：注册 `edge_verify.SCRIPTS` ⇒ 月度自动复核（**别写"没人调用"的脚本**）；
4. **只做展示**：未过检验前不进决策链；过检验后也要想清楚落地形态（例：LHB 验出
   "信息在空头侧" ⇒ 落地为**风险标签**，不做买入提示）。

**3.2 egress 纪律**
窄列（不要 `SELECT *`，尤其避开 `seats_json` 这类大字段）｜分块 + 重试（>1000 行）｜
pack/本地库优先（零 egress）｜进程内缓存 + TTL｜"主路径只允许读缓存"（抓取交给后台预热）。

**3.3 日期键**
所有"每日一行"的表：键 = **交易日**；守卫用 `rules.is_trading_day()`（**不要 `weekday() < 5`**）；
日批/循环**显式传** `_batch_trading_day()` / `latest_completed_trading_day()`（不传 ⇒ 内部取运行日 ⇒ 错位键）。

**3.4 兜底闸 > 逐点修复**
写入侧容易被绕过时，优先加**自愈闸**（`data_gap` / `data_hygiene` 范式）：即使漏一处也不会积累。

**3.5 ★ 修之前先核实"这条路径线上是否在跑"**
`_heavy()` 里的循环在 READ_ONLY 下是**死代码** ⇒ 修在里面等于没修。
已两次踩到（`score_snapshot_loop` 的时序守卫、`gate-watch` 的"待修"）。
**动作**：`grep -n '_heavy(' backend/app/flash/scheduler.py` 确认该 loop 是否被包住。

**3.6 验证要用真实函数 / 真实数据**（三条翻车教训）
| 教训 | 现象 | 正确做法 |
|---|---|---|
| monkeypatch 污染取样 | 测出"8 只票差异完全相同"（荒谬但看着合理） | 同一脚本里做过补丁又要真实采样 ⇒ **先留原函数引用** |
| 文本匹配查"残留" | 被自己写的**文档字符串**（引用了反例写法）误报 | 用 `ast` 精确解析代码，不要文本 grep 结论 |
| 管道缓冲 | `python x.py \| Select-Object -Last N` 在长任务上"无输出" ⇒ 像卡死 | `python -u` + **不加管道**，让输出实时流 |

**3.7 破坏性操作**
DB 删除/改键：**先 dry-run 报告 → 只做可解释的最小动作 → 复跑复核归零**
（样板：`scripts/cleanup_holiday_keys.py` 的分表策略 + 只删重复 + 孤儿改键不删）。

## 5. 下一阶段（来自外部开源调研的启示）

> 结论一句话：**增量在"呈现层"（让已验证的东西更好用），不在"更多功能"。**
> 外部项目解决"看什么"；本项目已在解决"凭什么信"——别为了对齐它们的**功能清单**，
> 稀释本项目的**证伪成果**。

**P1 · 个股"一页纸 AI 诊断"**（对标 PanWatch 决策书 / daily_stock_analysis 仪表盘）
- 目标：把详情页十几个散落标签（评分/主力阶段/连续净流入/闸门就绪/龙虎榜风险/财报断层）
  合成 3 段式结论（现状 / 风险 / 还差什么）。
- 硬约束：**LLM 只做聚合与表述，不产生新信号**；每条结论必须能追溯到已有字段；
  底部固定「非投资建议 + 各信号检验状态」。
- 验收：① 任一结论可点回原始字段；② 关掉 LLM 时页面完全可用（降级为事实）；
  ③ 不含任何"建议买卖"的话术（**机械拦截**，不只靠 prompt）。

> ✅ **已落地（2026-10-11）**：`backend/app/stock_diagnosis.py`（`build_facts` 取 5 组既有事实 +
> `diagnose` 只让 LLM 复述编号事实）+ `GET /score/diag/{symbol}`（**两段路径**，避开 `/{symbol}`
> 通配吞路由）+ `StockDetail.vue` 卡片（**事实先渲染、AI 按需点按钮**，12h 进程缓存）。
> 三条约束的落地方式与验收见「变更记录」；**各信号检验状态写在后端 `SIGNAL_STATUS`（唯一事实源）**。
> ⚠️ 已知边界：评分事实取"盘后口径"（`ranking_live` 精算池 top1000 → 否则 `ranking_history` Top50），
> 池外个股**如实披露为缺失并指向页面顶部的实时分**（不编数、不换口径）。

**P2 · 自然语言问询入口**（对标 TSP AI 助手）
"某只票现在怎么样 / 今天该注意什么" → 路由到既有结构化接口 + LLM 摘要。
约束：只读、不触发重算、不落库、不推送。
