# 记分簿（Thesis Tracker）说明

> 最后更新：2026-10-31
> 代码：`backend/app/thesis_tracker.py` + `scripts/thesis_cli.py`
> 表：`thesis_registry` / `thesis_events` / `thesis_evidence`

---

## 一、一句话定义

**给判断装一个记账本**：事前登记概率 → 事中记录证据 → 事后机器/人工裁决 → 全程计算校准。

**它不预测，只记账。** 记完账，你才知道自己的 65% 到底值多少个准确率。

---

## 二、它解决四个具体痛点

### 1. 事后合理化（"我一向觉得会加息"）

**没有登记时**：三个月后回看，你只会记得"我当时就觉得要加"，而记不起当时其实只有 55%。

**有登记时**：`thesis_events` 里躺着 `register: p=0.65`，无法篡改。

### 2. 不知道自己准不准

**核心问题**：你喊 65% 的那些事，实际兑现了几次？

- 如果喊 65% 的事兑现了 80% → **你系统性低估自己**（可以更激进）
- 如果只兑现 50% → **你系统性过度自信**（该打折）

**没有这个数据，你只能凭感觉调仓位。**

### 3. 无法区分"信息错"和"推理错"

判断错了有两种可能：

| 类型 | 表现 | 改进方向 |
|---|---|---|
| **信息错** | 当时不存在能判对的信息 | 无解，接受 |
| **推理错** | 信息够了，但推理链断了 | 可以改进 |

**有了登记 + 证据，事后能分清是哪一种。** 例如 10 月那次：
- 信息是够的（FedWatch 92.8% 的 hold 定价摆在那）
- **是推理错**（把"点阵图中值 4.1%"误读成"每场都要加"）
- ⇒ **这条可以改进**，下次看到"中值承诺"要知道它不等于"每场都加"

### 4. 无法量化"我 vs 市场"

**这是"FedWatch 折扣系数"的唯一来源。**

你现在拍脑袋说"市场 84% 太高了，我给 65%"——**这个 20 个点的折扣，有没有依据？**

- 如果历史上你在"高一致性定价（>80%）"时反向打折的胜率是 60% → **折扣有依据**
- 如果只有 45% → **你只是在逆势，不是有 alpha**

**没有配对记录，这个数永远算不出来。**

## 三、**不需要每天抓数据**（这是最常被误解的一点）

### 3.1 记分簿本身每天零请求

| 环节 | 频率 | 说明 |
|---|---|---|
| **登记** | **一次性** | 一条假设登记一次，之后不再动 |
| **修订** | 事件驱动 | 只在你知道新信息时改，**不是每天** |
| **裁决** | **deadline 那天一次** | 12/9 决议后判一次，判完就结束 |
| **校准计算** | **零请求** | 只读已 resolved 的行，不需要实时数据 |

**⇒ 一条假设从登记到裁决，全程最多 3 次数据交互（登记、可能的修订、裁决）。**

### 3.2 `p_market` 只在登记那一刻取一次

表里有 `market_as_of` 字段，就是干这个的：

```json
"p_market": 0.844,
"market_source": "fedwatch",
"market_as_of": "2026-10-28"
```

**登记后不要更新它。** 理由：

- 更新 = **事后挑时点**（你会不自觉地选对自己有利的那个时点）
- 校准的意义是「**同一信息时点上，谁更准**」，不是「谁最终对」

**⇒ 所以「每天都抓 FedWatch」不仅不需要，还会破坏这个功能。**

### 3.3 什么时候才需要额外数据

| 时机 | 需要什么 | 是否必需 |
|---|---|---|
| 登记时 | 当时的 FedWatch 概率 | **必需**（一次性，手工抄一行快讯即可） |
| deadline | 决议结果 / 点阵图 | **必需**（一次性，手工录入） |
| **中途失效检查** | FedWatch 是否跌破阈值 | **可选** |

**只有当你想让 `invalidation_early`（如"CPI 后 FedWatch 跌破 65% → 转分支"）自动报警时，才需要中途查。**

**这是可选的**——不做的话，你会在看快讯时自己注意到。

### 3.4 如果真要做自动检查，成本也很低

**不需要新接口**。项目已经在抓金十快讯（`jin10_tidy`），而 FedWatch 概率**就在快讯正文里**：

```
据CME"美联储观察"：美联储12月会议加息25个基点的概率为82.6%
```

**一条正则就能抽出来**：

```python
m = re.search(r"12月会议.*?加息25个基点的概率为([\d.]+)%", text)
```

**成本：0**（快讯本来就在抓，不增加任何请求）。

**⇒ 结论：这件事的边际成本接近零，但它不是必需的。**

## 四、现在有什么（截至 2026-10-31）

### 4.1 两张表

```
thesis_registry    假设登记簿（一条假设一行，claim 不可改）
thesis_events      append-only 状态流转（register / revise / evidence / resolve）
```

**关键字段**：

| 字段 | 作用 | 为什么必要 |
|---|---|---|
| `nature` | `prediction` / `decision` | **只有 prediction 进 Brier**，decision 是过程评分 |
| `backfilled` | 是否回填样本 | **永久排除统计**（回填必然美化登记人） |
| `resolution_rule` | 结构化裁决条件 | 机器可判，不靠回忆 |
| `resolution_source` | `auto` / `manual` | 诚实标注哪些必须人工 |
| `p_market` + `market_as_of` | 市场同期定价 + 时点 | 配对比较的唯一依据 |

### 4.2 CLI

```bash
python scripts/thesis_cli.py list                     # 看所有假设
python scripts/thesis_cli.py show  --id 1             # 看单条（含全部修订记录）
python scripts/thesis_cli.py register ...             # 登记
python scripts/thesis_cli.py revise --id 1 --p 0.29   # 修订（必须带 reason）
python scripts/thesis_cli.py resolve                  # 裁决（deadline 后跑）
python scripts/thesis_cli.py stats                    # 校准统计（N<30 只报流水账）
```

### 4.3 当前样本

```
#2  resolved_win  [回填]  p=0.87   2026-09-16 FOMC 加息      ← 永久排除统计
#1  open                  p=0.29   2026-12-09 FOMC + 点阵图  ← 第一条有效样本
```

**`#1` 的现状**：

```json
claim      "12/9 加息 25bp 且 2027 点阵图中值 ≤4.1%"
p_mine     0.29      （2026-10-31 从 0.65 修订，口径修正）
p_market   0.844     （2026-10-28 快照）
deadline   2026-12-10 03:00
status     open
```

**修订记录完整可查**：`old_p=0.65 → new_p=0.29`，含 reason 和 trigger。

## 五、怎么用（日常操作手册）

### 5.1 什么时候登记

**只有同时满足这三条才登记**：

1. **离散**：有明确的发生/不发生（不是"长期看好 AI"这种）
2. **有 deadline**：某年某月某日某时揭晓
3. **可机器或明确规则裁决**：能写成 `{"field": ..., "op": ..., "value": ...}`

**不满足就别登记**——那些属于 `scenario_watch`（连续状态）或干脆是信仰。

### 5.2 什么时候修订

**只在两种情况**：

| 情况 | 例子 |
|---|---|
| **口径修正** | 发现 `p` 和 `claim` 不对应（如 `#1` 那次） |
| **新信息** | CPI 数据出来，显著改变判断 |

**必须带 `--reason` 和 `--trigger`**，否则拒绝执行。**这是防裸改的唯一手段。**

### 5.3 什么时候裁决

**deadline 之后跑 `resolve`**：

- `resolution_source=auto` 的字段自动判
- `manual` 的字段会提示"待人工录入"
- 判完写 `status=resolved_win` / `resolved_lose`

### 5.4 什么时候看统计

**N < 30 时只报原始流水账**（哪条对、哪条错、当时概率多少）。

**不要看"校准结论"**——4 条样本算出来的 Brier 没有统计意义，只会骗自己。

## 六、三条铁律（为什么它不会变成自欺工具）

### 铁律 1：claim 和 resolution_rule 登记后不可改

**只能新增修订记录**（`p` 可以改，`claim` 不行）。

**为什么**：允许改 claim = 允许"事后把错的改成对的"。

### 铁律 2：裁决权不在 LLM

`resolve` 由规则表达式执行；LLM 只做文本抽取（如从声明里抽 `hawkish` 标签），**且抽取结果必须带原文引用**。

**为什么**：LLM 给人写成绩单，必然偏向"看起来有洞察"。

### 铁律 3：没有 deadline 和失效条件的"观点"不许登记

**"长期看好 AI"进不了登记簿**——它不是假设，是信仰。

**为什么**：无法裁决的东西记进来，只会稀释统计分母。

## 七、样本门槛（什么时候才能下结论）

| 指标 | 需要多少样本 | 现在 |
|---|---|---|
| 原始命中流水账 | 1 条即可 | ✅ 有 `#1` |
| **配对比较**（Brier_mine vs Brier_market 符号检验） | **20~30 条** | ❌ 差得远 |
| 条件化分析（"高共识时反向打折更准"） | 50+ 条 | ❌ 很远 |
| 校准曲线（按概率分桶） | **100+ 条** | ❌ v1 不做 |

**⇒ 现在的正确用法是：登记、留痕、等着。** 不要指望它立刻告诉你什么。

**按每月 1~2 条真实判断的产出速度**：
- 20 条 ≈ 一年
- 100 条 ≈ 四年

**这意味着：第一年内，你只能看到"流水账"，看不到"结论"。** 要有这个觉悟。

## 八、和三个近亲的边界

| 系统 | 管什么 | 判定方式 |
|---|---|---|
| **记分簿（本文档）** | 离散、带 deadline、可裁决的**概率命题** | 事前登记，事后裁决 |
| `scenario_watch` | 连续情景倾向（基准/加深/修复） | 每日重算，无终态 |
| `contradiction_validations` | 观点间矛盾的事后验证 | 事件驱动 |
| `edge_verify` | 策略/信号的预测力 | 判据冻结，月度跑 |

**四者不互相吸收。** 记分簿可以在周报里**引用**其他三者的读数作为证据，但表结构上零耦合。

## 九、FAQ

**Q：是不是又要加一个看板页面？**
A：不是。v1 只有 CLI 和两张表。周报、决策卡、前端页面都是**12/10 拿到第一个真实样本之后再决定**——用功能自己的哲学决定功能自己的 roadmap。

**Q：是不是每天都要抓金十的 FedWatch？**
A：**不是。** 详见 §三。登记时抄一次，deadline 判一次，中间不需要。只有想做"失效条件自动报警"时才需要中途查，而那是可选的、成本接近零。

**Q：能提高我预测的准确率吗？**
A：**不能。** 它只告诉你准不准，不让你更准。**认识自己的偏差，是改进的前提，但那一步要靠你自己。**

**Q：`p_market` 抓不到实时数据怎么办？**
A：手工抄一行快讯即可，填 `market_as_of` 标明时点。**没有 `p_market` 不阻塞登记**，只是这条不进配对统计。

**Q：裁决时点阵图数据哪来？**
A：**必须人工录入**。金十的 `long-pictures/details` 接口有 `rateDta`（可自动判利率），但**没有任何结构化点阵图数字**。

**Q：为什么 `#2` 那条回填样本不能算？**
A：因为它的结局已知。回填样本必然是"挑那些已知结果的判断"——**这正好是防自欺要防的事**，只是换了个发生形式。

**Q：LLM 能不能帮我自动登记？**
A：可以提议，但**默认 `pending`，人工拍板才激活**。LLM 不能给自己写成绩单。

## 十、一句话总结

> **记分簿不会让你下一次判断更准，它只会在三个月后告诉你：该信谁、该在什么样的定价一致性下反向打折、以及你的直觉值多少个百分点的权重。**

**而它现在只有 1 条有效样本。** 在 12/10 之前，它唯一的作用是**把那条 0.29 钉在墙上**——让你没法事后说"我早就觉得会加"。
