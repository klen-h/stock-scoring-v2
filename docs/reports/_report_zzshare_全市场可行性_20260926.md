## 1. 实测结果（三条，都通过）

| 验证点 | 结果 | 耗时 |
|---|---|---|
| ① `stock_basic(exchange='ALL')` | **5587 只**（SZSE 2910 / SSE 2330 / BSE 347）—— 含创业板/科创板/北交所 | 1.1s |
| ② `daily(trade_date='20260924', limit=6000)` | **5569 行**，**未被截断**，11 个字段（含 `pre_close`/`pct_chg`） | **1.3s** |
| ③ `updown_distribution(date1='20260924')` | 返回 dict：全市场涨跌幅**档位分布** + `DT`(跌停15)/`SJZT`(52)/`XDJS`(下跌4306)/`SZJS`(上涨1119) | 0.4s |

**②是决定性的**：**一次请求拿全市场一天**（不是一只一次）⇒
**750 个交易日 ≈ 750 次请求 × ~1.3s ≈ 16 分钟**（不含限速等待）。

⇒ **上一轮我判断的"扩池 egress 与工作量显著"是错的** —— 按"单股 × N 只"估的算法不成立，
zzshare 有"按天整市场"的高效路径。**此处自我更正。**

## 2. 附带解决三个既有问题（价值超出"扩池"本身）

| 既有问题 | zzshare 的解法 |
|---|---|
| **宽度序列的 841 池偏差** | `updown_distribution` 直接给**全市场**口径（1119 涨 / 4306 跌），
无需自算、无池子偏差 ⇒ **① 报告里的"偏差标注"可升级为官方口径** |
| **生存者偏差** | `stock_basic(list_status='D')` 可取**退市股** ⇒ 现有 810 池只含在市股，
天然带生存者偏差（回测会系统性偏乐观）|
| **样本期太短（只有 1-2 个周期）** | README 称日线 **2005 年至今** ⇒ 若按"按天整市场"路径可拉更长历史
（**待验证老日期可用性与限速**），理论可覆盖多轮牛熊 ⇒ **"独立样本仅个位数天"可能被彻底解决** |

## 3. ★ 修正我上一轮的一个数字：家数缩放系数 **0.25 → ~0.13**

以 09-24 为基准（同一天三种口径）：

| 口径 | 上涨占比 up_ratio | 跌停家数 |
|---|---|---|
| 实时快照 3236 只 | 0.2421 | 11 |
| 本地 841 池 808 只 | 0.2124 | **2** |
| **zzshare 全市场 5569 只** | **0.206**（1119/5425）| **15**（DT）|

⇒ ① 结论**被强化**：`up_ratio` 是比例量，三口径 0.206/0.212/0.242 **接近，可迁移** ✓
⇒ 但家数缩放应相对**全市场 5569**，不是实时快照 3236：
`2 / 15 = 0.13` ⇒ **缩放系数 ≈ 0.13~0.15**（此前用 0.25 偏大 ⇒ `limit_down>=5` 偏松，
应约 `>=3`）。⚠️ 若改用 zzshare 官方口径，则**不需要缩放**（直接用 DT/涨停家数）。

## 4. 约束与风险（必须先明确）

| 约束 | 说明 |
|---|---|
| **存储** | 全市场 5569 × 750 天 ≈ **420 万行**（3 年）；20 年 ≈ 2800 万行。
⇒ **只能放本地 SQLite/文件，绝不能进 Supabase**（项目库 500MB 硬限 = 超限即全站只读）|
| **复权** | 长历史必须用 `adj='qfq'`（或 `factor` 字段自算），否则跨除权日收益失真 |

| **口径差异** | 扩池后回测池（5569）≠ 生产扫描池（810）⇒ 结论需标注"全市场 vs 生产池"，
不能直接当作生产预期 |
| **老日期可用性** | daily 对 2005~2023 的数据是否同样"按天可拉"——**未验证**，是下一步要测的 |

# 附：老日期可用性 + 复权补测（2026-09-26 第二轮）

## A1. 老日期全部可用（9/9），且有**强证据**

| 日期 | 行数 | 耗时 | 字段数 |
|---|---|---|---|
| 2006-01-04 | **1348** | 2.4s | 11 |
| 2008-01-02 | 1527 | 22.2s（含一次网络超时重试）| 11 |
| 2012-01-04 | 2319 | 2.5s | 11 |
| 2015-06-01 | 2733 | 3.2s | 11 |
| 2018-01-02 | 3463 | 3.7s | 11 |
| 2019-01-02 | 3557 | 3.9s | 11 |
| 2021-01-04 | 4194 | 4.2s | 11 |
| 2023-01-03 | 5178 | 5.0s | 11 |
| 2026-09-24 | 5569 | 2.7s | 11 |

**强证据**：行数曲线 `1348 → 1527 → 2319 → 2733 → 3463 → 3557 → 4194 → 5178 → 5569`
**完美对应 A 股上市公司数量的历史增长** ⇒ 证明它按**当时的市场**返回，不是拿现在的名单去套。

⇒ **2006 年起即可用 ⇒ 样本期可从 3 年扩到 20 年**（多轮牛熊）。

⇒ **附带消除生存者偏差**：按天查询天然包含**当时存续、事后退市**的股票
（比 `stock_basic(list_status='D')` 更彻底）。

## A2. ★ 复权：**`adj` 参数在"按天模式"下无效**（关键坑）

```
adj=None : 000001.SZ close=11.3
adj=qfq  : 000001.SZ close=11.3   ← 完全相同
adj=hfq  : 000001.SZ close=11.3   ← 完全相同
```
⇒ 单日快照的 `close` 就是当日实际成交价，`adj` 不产生效果。**不能靠 `adj` 做长历史复权。**

**解药**：`fields='all'` 返回 18 字段，**含 `factor`**：

| 字段 | 样例（000001.SZ @2026-09-24）|
|---|---|
| `factor` | **148.086182** |
| `high_limit` / `low_limit` | 12.49 / 10.22 |
| `is_st` / `turnover_rate` | 0 / 0.537839 |

⇒ 复权收益自算：`ret_t = (close_t × factor_t) / (close_{t-1} × factor_{t-1}) − 1`
（`factor` 为累积复权因子；跨除权日不失真）。**这是按天路径拉长历史的唯一正确姿势。**

## A3. 单股 vs 按天：按天完胜

- 单股 20 年（`limit=1000`）只返回 **1000 行**（20050104~20090219）⇒ 有 1000 条硬上限，需分页 ×5+
- **按天一次 5569 行、无条数限制** ⇒ 成本：`交易日数` 次请求（而非 `股票数 × 页数`）

## A4. 耗时与限速实测

| 规模 | 预估（均值 5.5s/次，含 0.6s 间隔）| 中位数口径（~3.7s）|
|---|---|---|
| 3 年（750 日）| **~77 分钟** | ~54 分钟 |
| 10 年（2500 日）| ~4 小时 | ~3 小时 |
| 20 年（5000 日）| **~8.5 小时**（过夜可完成）| ~6 小时 |

⚠️ 实测出现**一次网络超时**（2008 那次 22.2s，SDK 自动重试成功）⇒ 回填脚本**必须带重试 + 断点续传**
（否则 5000 次里任何一次失败都会中断整夜任务）。

## A5. 结论（可行性判定）

| 项 | 判定 |
|---|---|
| 老日期可用性 | ✅ 2006 起 + 行数符合当时市场 |
| 按天拉全市场 | ✅ 一次 5569 行、无条数限制 |
| 复权 | ⚠️ `adj` 无效 ⇒ **必须用 `fields='all'` 的 `factor` 自算** |
| 生存者偏差 | ✅ 自动消除 |
| 样本期 | ✅ 可扩到 20 年（5000 交易日）|
| 耗时 | ✅ 3 年 1 小时 / 20 年 8.5 小时（过夜任务）|
| 稳定性 | ⚠️ 需重试 + 断点续传 |
| 存储 | ⚠️ **只能本地**（3 年 ≈ 420 万行；20 年 ≈ 数千万行）|
