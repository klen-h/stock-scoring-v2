# 第 1 步 ① 历史宽度序列 —— 产出与偏差

> 2026-09-26。只读 + 离线。产出 `_breadth_history.json`（749 个交易日）。

---

## 1. 产出

`_breadth_history.json`：749 个交易日 × `{date, n, up, down, up_ratio, limit_up, limit_down}`。

**口径对齐 `_market_breadth_now`（market_regime.py:331）**：
- `pct = close / 上一交易日 close`（同股按 date 排序的 LAG，自动跳过停牌）→ **收盘口径**
- `up = pct>0`，`down = pct<0`，`up_ratio = up/(up+down)`（不含平盘）
- `limit_up = pct>=9.9`，`limit_down = pct<=-9.9`
- 只统计 6 位纯数字**个股**，排除 sh000300 等指数

## 3. 两个偏差（必须标注，否则 ② 会踩）

### 偏差 A：池子偏置（841 只 ≠ 全市场 ~5400）

`backtest_prices` 只有 **841 只**（评分候选池 + 权重风格），非全市场。证据：
- 微盘崩盘日 `2024-02-07` 池子 up_ratio = 0.64（明显偏高，因池子里微盘股占比低）。

### 偏差 B：早期覆盖

`min n = 8`（2023-08-23 起步），但 **覆盖 <300 只的只有 4 天**；2023-08 之后绝大多数时间 ~800 只
（median=798，max=810）。⇒ 仅最早 4 天不可信，影响极小。

## 5. 给第 1 步 ②（nb 序列化）的**口径转换规则**

**这是 ① 最有价值的结论：**

| `_nb_condition_raw` 的判据 | 能否直接迁移到历史池子？ |
|---|---|
| `up_ratio < 0.40` | ✅ **可直接迁移**（比例量，偏差仅 0.03） |
| `limit_down >= 20 且 > limit_up` | ❌ **不可直接迁移**（绝对家数，池子只占全市场 1/4）|

**家数阈值的转换**：池子样本数 ≈ 全市场 × 0.25（808/3236），且涨停占比几乎一致（1.4%），
⇒ 家数阈值按 **×0.25 缩放**：`limit_down >= 20` → 池子口径约 **`>= 5`**。

⚠️ 这是**经验缩放**（基于单日对比），不是严格推导 ⇒ ② 落地时应把缩放系数作为
**可调参数**（默认 0.25），而不是写死。

## 6. 一句话结论

> 历史宽度序列**方向可信、up_ratio 可迁移、家数阈值需 ×0.25 缩放**。
> ② 可以在此序列上做 nb 序列化，但家数判据必须换成池子口径的缩放阈值。

## 7. 补查：841 池到底是什么（决定所有结论的适用边界）

### 7.1 构成

```
沪主板 600/601/603/605 = 422  ｜  深主板 000/001/002/003 = 388
科创板 688 = 0  ｜  创业板 30x = 0  ｜  北交所 = 0  ｜  B股 = 0
ETF/指数 = 31（HOLDINGS_MAP 里的行业/宽基 ETF + sh000300）
```

### 7.2 来源（代码证据：`backend/backfill_history.py:142`）

```python
def _collect_strategy_codes(days: int = 30) -> list:
    """提取需回填的个股代码（含名称，去重）：
    1. strategy_results 中全部战法选股；
    2. 近 days 天 ranking_history 中出现过的评分股票。"""
```

⇒ **池子是“结果导向”的：不是主动选全市场，而是「系统历史上选中过 / 上榜过的股票」。**
日批 `task_backfill` → `backfill_lagging()` 就是按这个清单增量回填
（外加 `backfill_etf()` 的 `HOLDINGS_MAP` 与 `backfill_index()` 的 sh000300）。

|---|---|
| ∩ `strategy_results` | **810 / 810 = 100%** ✓（第一来源） |
| ∩ `mainflow_history` | 810 / 810 = 100% ✓（mainflow 用同一池子） |
| ∩ `ranking_history` | 442（子集）✓（第二来源“近 30 天上榜股”） |

### 7.4 ★★ 两个重大含义（必须写进后续所有结论的边界）

**含义 A：零创业板 / 零科创板 ⇒ 9.9 阈值完全适用，但风格暴露极大**
- 好消息：810 只**全是 10cm 主板** ⇒ 本报告用的 `pct >= 9.9` 涨停阈值**没有 20cm 失真问题**
  （上一轮担心的“创业板 20cm 不适用 9.9”在这个池子里不存在）。
- 代价：系统**从未在创业板/科创板验证过任何战法** —— 而 A 股题材/弹性主要在创业板。
  810 只 ≈ 主板 3000+ 只的 **27%**，且是“被选中过的”那 27%。

**含义 B：池子会自我固化（选择偏差 + 循环依赖）**
- 没被战法选中、没上过评分榜的股票 ⇒ 永远不进池 ⇒ 永远无数据 ⇒ **永远无法被回测检验**。
- ⇒ 第 0 步的 1049 个样本、本报告的 841 池，都只在“系统历史上选过的股票”上成立。
- ⇒ **重扫的 universe 选择因此成为一个必须显式决策的问题**：
  沿用现有池（可比性好，但继承选择偏差）vs 扩展到全市场（能发现池外机会，但与生产口径不一致）。
  **这是 ② 之后、③ 之前的必答题，不能默认。**

### 7.5 一句话

> 841 池 = **「战法选股 ∪ 近 30 天上榜股」+ ETF/指数**，即“系统自己选过的股票”。
> 它解释了所有偏差的来源（微盘少、零创业板、绝对家数被稀释），
> 也意味着**任何只在池内做的回测，都继承了同一套选择偏差**。
