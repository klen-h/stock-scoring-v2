# stock-scoring-v2 · A 股评分与盯盘工作台（**个人研究用**）

> ⚠️ **这不是投资软件，也不打算变成投资软件。**
> 本项目是**个人研究与决策辅助工具**：不接实盘、不做自动交易、不构成任何投资建议；
> 所有输出仅供研究参考，据此操作的盈亏**自负**。如果你在找"能直接上手用的开源盯盘/量化工作台"
> （TSP、QuantDesktop 一类），本项目**定位不同** —— 它更像一套"**给自己的信号做证据审查**"的装置。

---

## 一、这是什么

一句话：**把"每天该看什么、该不该动手"从感觉变成可检验的规则 + 有出处的结论。**

- **已有能力**：三维评分（技术/资金/基本面，权重随市况切换）、主力行为（阶段/筹码/资金流）、
  买入闸门就绪度、矛盾扫描（L1/L2/L3 + 验证闭环）、龙虎榜风险标签、财报断层、宏观规则引擎、
  模拟盘、交易员教练、日报/简报/观察池/持仓雷达、个股「一页纸诊断」与「事实问答」。
- **真正的独特之处**：**信号必须过"预登记检验"才能进决策链** —— 判据先写死、样本门槛、
  覆盖率门、按日聚类 bootstrap、**次日开盘可执行性检验**、月度自动复核。
> ⚠️ **2026-10-11 预登记结果**：评分 Top50 在防御/禁买市此后 5/10 日跑输可取价池等权
> −1.43/−2.21pt（P<0.0001）⇒ 评分当前**不构成买入依据**；"回避侧价值"验证中
> （`PLAN_SCORE_EDGE.md` / `PLAN_NEXT.md`）。
  已被它砍掉的东西比加进去的更有价值（例：`flow_consec` 首验即 FAIL；战法体系 24 格矩阵 19 负）。
  详见 [`开发文档.md`](docs/architecture/开发文档.md)。

## 二、三条产品红线（**不可动摇**）

| # | 红线 | 为什么 |
|---|---|---|
| **R1** | **不做实盘**：不接券商 API、不自动下单；只有模拟盘 | 风险与合规不对称；项目的终点是"决策质量"，不是"成交回报" |
| **R2** | **信号不进决策链**，除非通过预登记检验 | 90% 的"看起来有效"是噪音；未检验的信号只能以"事实/参考"形态展示 |
| **R3** | **判据先写死再看结果**，禁止事后调参 | 事后调参 = 自我欺骗（覆盖率不足时**禁止**判 KILL 就是这条的产物） |

> 另有 3 条**工程红线**（egress 预算 / 日期键一律交易日 / 文案与口径由后端下发），
> 以及各条背后的真实事故，见 [`开发文档.md`](docs/architecture/开发文档.md) §1。

## 三、⚠️ 数据会出网的地方（**LLM 披露清单**）

**先说结论**：**自托管 ≠ 数据不外流**。数据库、数据包、策略都在你自己的机器/账号里，
但下列功能会**调用外部 LLM API**，把文本发到第三方服务器（2026-10-11 全仓 grep 统计）：

| 功能 | 会送出的内容（含**你的持仓**的已标出） |
|---|---|
| 每日大盘日报 | 指数/板块/资金/情绪/宏观等市场摘要 + **持仓矛盾影响** |
| 交易员简报（盘前/盘后） | 候选清单、**持仓**、闸门与资金数据 |
| 战法诊断 / 复盘分析（`llm.analyze_with_llm` / `run_review_llm`） | 板块簇、宏观面板、**持仓明细** |
| 盘中异动解读 | 大盘状态序列、未兑现疑虑、**你的持仓** |
| 矛盾报告综述 | 当日矛盾条目（含个股/板块/指标） |
| 教练解释（"为什么"） | 触发该建议的相关数据 |
| 系统自洽性审查（先知雷达） | 当日**系统自身**的全部提示汇总 |
| 个股「一页纸诊断」 | 该股的结构化事实（评分/主力/闸门/龙虎榜/财报） |
| 个股「事实问答」 | 同上 + **你输入的问题原文** |

⇒ **送出的都是聚合摘要（行情/指标/资金/持仓/快照），不是整库导出**，但不保证逐字段脱敏；
是否接受由你决定。**想一点都不出网**：把 `.env` 里的 `LLM_*` / `LLM_FREE_*` 指向
**自建/本地的 OpenAI 兼容端点**即可（不配置 LLM 也不影响使用：相关功能会**自动降级**为
纯规则/纯事实输出）。用量与熔断状态可在后端 `/api/flash/status` 查看。

## 四、明确**不做**（别按这些提需求）

实盘对接（QMT / easytrader）、因子 DSL / 平台化、桌面端、为"毫秒级扫描"换技术栈、订阅制推送。
理由见 [`开发文档.md`](docs/architecture/开发文档.md) §5「明确不做」——多数与本项目的**证伪成果**直接冲突。

## 六、免责声明

1. **不构成投资建议**：本项目全部输出（评分、标签、闸门、AI 解读、问答）都是**研究过程的中间产物**；
2. **数据不保证准确**：数据来自公开第三方源（腾讯/东财/zzshare/新浪等）与本地缓存，
   可能有延迟、缺失或错误；**关键决策请自行交叉验证**；
3. **LLM 输出可能有误**：AI 部分只做"事实聚合与表述"，但**模型仍可能出错或误解**；
   涉及 AI 的结论请对照页面上的「依据（可追溯）」与「各信号检验状态」；
4. **盈亏自负**：使用本项目产生的任何交易决策与后果，由使用者自行承担。
5. **外部观点卡是二手解读**：「李大霄视角」等外部大 V 观点卡来自另一项目（xiaopage）的
   **LLM 结构化解读，非本人原文**，不进入本项目任何决策链（R2），仅供研究对照。
