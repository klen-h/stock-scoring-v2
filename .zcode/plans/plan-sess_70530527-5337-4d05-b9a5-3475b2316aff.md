# 交易计划（买点跟踪 + T+1 验证）实施计划

## 一、功能定位
评分高 ≠ 立即买。这是"择时"工具：记录"在什么价位、因为什么理由、预期怎么走"，系统自动跟踪验证，形成「判断→记录→验证→复盘」闭环。重点 T+1 视角（A股买入次日才能卖）。

## 二、核心数据结构（localStorage key: `trade_plans`）
```js
{
  id: 'tp_1700000000000',          // 唯一ID
  code, name,
  // —— 交易计划三要素（用户填）——
  buy_price: 12.5,                 // 买点价位
  stop_loss: 11.8,                 // 止损价
  target: 13.8,                    // 目标价
  reason: '回踩MA20缩量企稳',       // 买点理由
  expected: '企稳反弹至13.8',       // 预期走势
  created_at: 1700000000000,
  // —— 自动跟踪字段（系统填）——
  status: 'waiting',               // waiting/hit/targeted/stopped/expired
  hit_at: null,                    // 触及买点时间戳
  t1_close: null,                  // 触及次日"收盘"（次日首次刷新价近似）
  max_high_after_hit: null,        // 触及后最高价
  min_low_after_hit: null,         // 触及后最低价
}
```

## 三、状态机（核心逻辑，每次刷新判定）

```
waiting（等待买点，价格在买点上方）
  │
  ├─ 现价 ≤ buy_price → hit（触及买点，T+1 跟踪开始）
  │
  └─ 现价 > target×1.05 → expired（涨过头，没给机会）〔可选，防误判默认关闭〕

hit（已触及买点，跟踪中）
  │
  ├─ 现价 ≥ target → targeted（达目标，验证成功 ✓）
  ├─ 现价 ≤ stop_loss → stopped（破止损，验证失败 ✗）
  └─ 持续更新 max_high_after_hit / min_low_after_hit

targeted / stopped / expired（终态，可删除或保留复盘）
```

**T+1 逻辑**：hit 后，若跨自然日（hit_at 的日期 ≠ 今天），把当天首次刷新价记为 `t1_close`（近似收盘价）。
**诚实说明**：实时接口无历史分时，T+1 用"次日首次刷新价"近似，UI 标注"次日刷新时点近似价"。精确回填需 K线接口（二期）。

## 四、盈亏比（计划质量指标）
```
预期盈亏比 = (target - buy_price) / (buy_price - stop_loss)
```
- ≥ 2：绿色（高质量计划）
- 1~2：黄色（及格）
- < 1：红色（盈亏比不合理，不值得做）

## 七、状态机细节（关键）
- **waiting 的"距买点"**：(现价-buy)/buy×100%。正=还没到（继续等），负=已破（理论上应已 hit）
- **created 时现价已 ≤ buy**：立即变 hit（用户可能基于当下价设的买点）
- **T+1 跨日判定**：`new Date(hit_at).toDateString() !== new Date(now).toDateString()` → 记录 t1_close
- **终态保留**：targeted/stopped 不自动删，留作复盘。用户可手动删除或归档
