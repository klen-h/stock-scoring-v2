## ★★ 真 bug：持仓状态卡在「行情 13:09」（同日快照同步被拒）

用户报："今天的工作台的持仓状态（4 只 · 风险 1 / 机会 1）一直卡在行情 13:09"。

### 线上实测（21:56）

```
/api/score/batch/portfolio-radar:
  as_of               = 2026-11-26 21:56    ← 计算时刻（正常）
  quote_as_of         = 2026-11-26 13:09    ← 数据时刻（卡住）
  quote_from_snapshot = False               ← 竟标成"实时"
  quote_data_date     = 2026-11-26
```

而 `market_snapshot` 表里：
```
saved_at  = 2026-11-26T18:22:46+08:00
data_date = 2026-11-26
stocks    = 5260 只
```

**价格差是实打实的**（内存 13:09 vs 快照收盘）：
```
601398 工行      9.19  →  9.23
000628 高新发展  43.34 →  44.66
000429 粤高速A   13.83 →  13.80
```

### 根因：`tencent.sync_snapshot_if_newer()` 只比「数据日」不比「时刻」

```python
new_d = meta["data_date"]   # 11-26（18:22 写的收盘快照）
cur_d = _cache["data_date"] # 11-26（13:09 的盘中实时）
if cur_d and new_d <= cur_d:
    return False            # ← 同日直接拒绝，不管快照晚 5 小时
```

**三层防线同时失效**（这是这个 bug 最值得记的部分）：

| 防线 | 为什么没拦住 |
|---|---|
| `stock_cache_refresh_loop` 盘中刷新 | 15:00 后本就不刷新（设计如此） |
| `sync_snapshot_if_newer` 非交易时段采纳 | **同日 `<=` 拒绝**（本次真因） |
| 行情陈旧巡检 | 按 `data_ts` 的**日期**比，13:09 日期=今天 ⇒ 不报警 |

⇒ 用户看到"行情 13:09"且**非快照标记**，以为数据是实时的。

### 修复（`tencent.py`）

同日改比时刻，跨日逻辑保持原样：

```python
if cur_d and new_d < cur_d:
    return False                       # 库里更老，绝不回退
if cur_d and new_d == cur_d:
    new_ts = _parse_ts(meta.get("saved_at"))
    cur_ts = float(_cache.get("data_ts") or 0)
    if not new_ts or (cur_ts and new_ts <= cur_ts):
        return False
```

- 18:22 快照 > 13:09 内存 ⇒ **采纳**
- 08:45 盘前快照 < 13:09 盘中内存 ⇒ **不采纳**（不回退）
- 跨日逻辑不变

顺手改了日志文案：同日打印 `13:09 → 18:22`（原来会打印 `11-26 → 11-26`，看着像没变）。

### 验证

```
① 同日 18:22 vs 13:09 → 采纳，from_snapshot=True，price 9.19→9.23 ✓
② 同日 08:45 vs 13:09 → 不采纳，price 保持 9.19 ✓
③ 跨日 11-26 vs 11-25 → 仍采纳 ✓
④ 跨日反向 11-25 vs 11-26 → 不回退 ✓
317 passed · 卫生门 ✓ · 导出对账 ✓
```

⚠️ **必须部署/重启才生效**：线上进程内存仍是 13:09，重启时 `restore_market_snapshot()`
会读 18:22 的快照并置 `from_snapshot=True`，前端随即显示"11-26 收盘（快照）"。
不重启就只能等下一个交易日盘中刷新覆盖。

### 教训

`data_date`（数据所属交易日）是**天粒度**，无法区分同一天里的"盘中价 vs 收盘价"。
凡是"要不要采纳更新数据"的判断，同日必须下沉到时刻比较。
这与 11-25 的"盘中值=监测，收盘值=决策"是同一个问题的两面。
