**根因（为什么今天静默）**：现有指数规则是**绝对涨跌幅**口径（`_INDEX_WATCH`：现价 vs 昨收，
上证 -1.5%/-2.5%）。今天早盘冲高 +1.2%、午后回落到 -0.5% ⇒ 离 -1.5% 差得远，**永不触发**；
而「攻势没守住」的信息全在**从日内高点的回撤**里 —— 该维度此前无人度量。

**实现**（`backend/app/flash/intraday_alerts.py`）：
1. `_index_reversal_alert(quotes)`：`peak=(high-prev)/prev` ≥ 门槛 **且**
   `drop=(price-high)/high` ≤ -门槛（双条件缺一不可 ⇒ 不把低位窄幅震荡误报成回落）；
   门槛 上证 +0.8%/-1.5%、创业板指与科创50 +1.5%/-2.5%（高波动指数按倍数加严）；
   回撤超门槛 1.5 倍 = 🔴
2. **请求零增长**：新增 `_index_watch_quotes()` 拉一次喂两条指数规则
   （`get_index()` 无缓存层，各拉一遍会翻倍）
3. **唯一带 LLM 解读的规则**（用户三想法的落地）：prompt = 触发事实 +
   `format_a_share_context`（大盘状态序列；9-23 刚加，其注释里恰好写着「看不到日内冲高回落」）
   + 未兑现矛盾（`load_contradictions(resolved=0)`）+ 持仓 ⇒ 回答三问：
   **回踩还是反弹失败 / 印证或证伪哪条疑虑 / 对持仓意味着什么**。
   `call_llm(tier="fast")`；不可用则**降级模板**（保证一定有声音）
4. 防骚扰沿用既有机制：key=`idxreversal:{指数名}`，每类每档每日一次 ⇒ LLM 上限 6 次/日
5. 顺带修正 `scheduler.py` 过时注释（原写「30 分钟 / 1 个请求」，9-19 已提速为 3 分钟 / 3 个）

## 🔬 冲高回落形态预测力检验 ⇒ **NO EDGE**（`6d38674`）
**动机**：上一步只验了阈值频率（会不会天天响），**没验**「响了有没有预测力」。
**工具**：新增 `scripts/reversal_edge_check.py`（判定标准**预先定死**，防事后挑格子 ——
沿用项目研究脚本纪律）；`backtest_prices` sh000300 全历史 **748 根日线**
（2023-08-23..2026-09-22）；该表**无 sh000001** ⇒ 用沪深300 代量级。入场点 = 触发日收盘。

| 组 | n | T+1 均值 | T+1 胜率 | T+5 均值 |
|---|---|---|---|---|
| A 冲高回落（触发） | 110 | +0.19% | 51.8% | +0.57% |
| B 冲高守住（**最相关对照**：同为冲高日） | 127 | +0.09% | 52.4% | +0.35% |
| D 没冲高 | 510 | −0.01% | 50.2% | +0.02% |
| C 全样本 | 747 | +0.03% | 50.8% | +0.16% |

⇒ A−B：T+1 **+0.10pct**、T+5 +0.22pct ⇒ 主判定 **NO EDGE**。
**结论（与直觉相反）**：『冲高回落 = 派发看跌』**不成立** —— 该形态本身不携带看跌信息。

**⇒ 最重要的产出是改了 LLM prompt 语义**（`_reversal_llm_note`）：prompt 里**显式写入**
该检验结论 + 禁止 LLM 据此给减仓/看跌建议，定位改为「**盘面结构提示**」。真调 LLM 对比：
- 旧 prompt：「弱势反弹失败…不加仓、不追高、跌破日内低点则减仓」← 方向性建议，数据不支持
- 新 prompt：「攻势逐步被消化、未改变防御基调」+「**该形态不构成对持仓的操作依据**」+「无需动作」
⇒ 防住「把无预测力的形态当交易信号用」（同白名单负期望那类错误）。

**副发现**（仅记录；n=16 噪声大，不设规则）：A 组内**触发日收绿**的样本 T+1 **+0.88% /
胜率 81.2%**，但 T+5 转负（−0.13% / 37.5%）⇒ 疑似短线超跌反弹、一天即衰竭。
**局限**（已写入脚本）：①日线 low 是**触发上限**口径（3 分钟轮询实际更少）②相邻触发日
样本重叠（独立样本 <110）③样本期仅 3 年、未跨市况 ④多重比较（4 个持有期）
⇒ 以**预登记的 T+1 主判定**为准。

### ② 持仓雷达（`0bd6a9c`）
**动机**：所有看板以**全市场**为主语（榜单/观察池/矛盾/盘中警示），持仓只在 LLM prompt
与教练止损里出现 ⇒ 能答「156 只候选」，答不出「我手里那几只怎么样」。
**实现**：`backend/app/portfolio_radar.py` + `GET /api/score/batch/portfolio-radar` +
前端「我的持仓」tab。**全部复用既有单一事实源、不重算全市场**：
| 维度 | 来源 |
|---|---|
| 持仓 | `user_portfolio` + `portfolio_scope.portfolio_where()`（多用户隔离，与教练/日报同口径）|
| 现价/日内高低 | `tencent._cache` 内存行情（**零请求**；缺失才批量补一次）|
| 主力阶段 | `state.load_latest()`（含 `phase_cn`）|
| 闸门就绪 | `trade_gate.evaluate + summarize`（唯一事实源）|
| 战法命中 | `scoring._load_signal_map()` |
| 是否在观察池 | `gate_snapshot_history` 日批快照（**不重算** 39.8s 全池）|
| 评分/排名 | `ranking_live` 日批榜单（**不实时精算**）|
| 板块风险 | `load_contradictions(resolved=0)` 的 `*_samples` ∩ 持仓行业 |
`alerts` 每条都指向**既有模块的既有结论**，不引入新判据（防第五套口径）；定位＝状态
展示与提示聚合，**非买卖信号**。

### ★ 性能（实测驱动，通用教训）
初版**每次** 31~41s（非冷启动）⇒ 逐段计时定位：`scoring._load_signal_map` **16.9~20.7s**
（`strategy_results` 大 JSON + 无索引）、`load_contradictions` 6s（也是 `trade_gate.evaluate`
首只 7.7s 的真凶）、`gate_snapshot_history` payload 1.5~4.5s、`ranking_live` 1.2~2.1s。
**四步修**：① `_load_signal_map` 加 10 分钟进程缓存（日频 ⇒ 安全，**观察池 live 路径同时受益**）
② `portfolio_radar` 三处缓存（TTL 匹配数据频率：快照 30min / 矛盾 15min / 榜单 10min / 持仓 1min）
③ **single-flight**（实测"预热与请求并发"时 call1=31.3s ⇒ 并发调用立即返回上次结果或 warming 占位）
④ `scheduler.portfolio_radar_warm_loop` 后台预热（只读 ⇒ 只读模式保留）。
**结果**：热缓存 **1.28~2.61s**；冷启动窗口请求 **0.00s** 返回 warming 占位（前端显示"正在准备"）。

### ① 信号总线（`7a9e377`）
**动机**：~10 个独立推送入口（`health` / `intraday_alerts` / `scheduler` 各 loop /
