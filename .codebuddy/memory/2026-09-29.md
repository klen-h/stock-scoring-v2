## ★★ 竞价看板「一会一个、一会三个」= **真 bug**（名单来源写错），已修

**用户**："盘中的竞价看板「一会一个、一会三个」也是正常的吗？"
⇒ 我前一天的答复（"竞价窗口内开盘价逐步到位"）**只答对一半**：那只解释 9:15–9:25 的小波动，
   解释不了"**盘中**还在跳"。本轮查清并修复。

### 一、真因：名单来源在开盘前后**整批切换**

`routers/market.py` 的 `gaps`（= 面板上的 `count` / `avg_gap` / `Top5`）原来遍历 `limit_up_codes`：

```python
limit_up_codes = [c for c, s in stocks.items() if (s.get("change_pct") or 0) >= 9.5]
```

它筛的是**行情缓存里的「当日涨幅」**：

- 开盘**前**：行情缓存还是上一交易日快照 ⇒ 筛出的是「**昨**日涨停」（与面板文案相符）；
- 开盘**后**：`change_pct` 变成当日 ⇒ 筛出的是「**今**日涨停」！

⇒ 同一份代码在开盘前后筛出**完全不同的名单**，且盘中名单**随涨停家数一路变**
⇒ `count / avg_gap / Top5` 必然乱跳（用户看到的"一会一个、一会三个"）。

★ **旁证**：`avg_gap = -7.44%`（"昨日涨停股今日平均高开 -7.44%"）在正常市场极罕见 ——
  它实际算的是「**当日涨停股**的开盘涨幅」（当日涨停多为低开后拉板 ⇒ 开盘普遍很负）。

★ **正解就在上方 ~30 行**：`prev_limit` 是**由历史收盘算出的真正「昨日涨停名单」**
  （`d_prev` 相对 `d_prev2` 涨幅 ≥9.5%，同函数内已用于 `money` 赚钱效应）—— 它当天**恒定**。

### 二、修法（`routers/market.py` 3 处 + 前端 1 处）

1. `for code in limit_up_codes:` → `for code in prev_limit:`
2. `"limit_up_total": len(limit_up_codes)` → `len(prev_limit)`
   （昨日新加的分母必须同源，否则"11/40"的分母是"当日涨停家数"、分子是"昨日涨停股"= **不同日**）
3. 新增 `"covered"`：`closes` 里 `d_prev` 有值的股票数（让前端能解释"数字偏少"）
4. 前端：给"竞价看板 · 昨日涨停"加 hover，写明**口径与两条边界**（见下）

### 三、★★ 本轮拿到、以后会反复用到的数据事实

**实测**：`limit_up_total(prev_limit) = 11`（与用户看到的"11 只"完全吻合）、`covered = 839`；

### 二、本轮改动（3 处，都在后端）

1. **`main.py` `/api/health` 增 `build` 字段** = `RENDER_GIT_COMMIT` 前 7 位
   （回退 `GIT_COMMIT`，都没有则空串）——**以后一次 curl 就知道线上是哪版**，
   不必再用"某端点存不存在"反推（本轮为此取证了十几步）。
2. **`health.py` 抑制留痕**：每次静默打一行
   `[health] 已抑制企微推送（东财板块，原因：静默源）—— 页面通知照常`。
   ⇒ 诊断口诀：**用户仍收到推送、而日志里没有这行 ⇒ 推的不是这份代码**。
3. **新增总开关 `WECHAT_SOURCE_ALERTS`**（默认 `1`；设 `0` = 所有「数据源告警/恢复」都不推企微，
   只留页面通知铃铛）。东财的静默**不依赖**该开关。已在 `.env.example` 注明。

### 三、学到的方法（下次直接用）

- **判断"线上有没有某功能"**：用 `git log -S "<新代码里的字面量>" --oneline -- <路径>` 定位引入提交，
  再 `curl` 线上端点看字段/路由是否存在 ⇒ 卡出线上版本区间；配合
  `git merge-base --is-ancestor <提交> <线上已知包含的提交>` 判断先后。
- **本项目部署会滞后**（`render.yaml` 写了 `autoDeploy: yes`，但实际可能几天没跟上；
  免费版每次部署会清空 `backend/data/` ⇒ **`data/` 里的旧文件还在 = 期间没部署过**，
  这是判断"最近有没有部署"的免费信号）。
- ⚠️ 排查中踩到的坑：PowerShell 里传含中文/`%`/`in` 的 `python -c` 极易被解析坏
  （`%` 撞 psycopg2 占位符、`position(x in y)` 被 PowerShell 当运算符）⇒ 改用
  `'\u4e1c\u8d22'` 这类**转义写法**或临时脚本文件。

**验证**：`py_compile` 通过；三场景实测（豁免 0 次 / 对照 2 次 / 开关=0 后 0 次新增）全部符合；
`read_lints` 0 error。**需部署**后端才生效（部署后 `curl /api/health` 能看到 `build`＝新提交）。
