## ⚠️ zzshare 401 事故排查（2026-09-21 13:52 日批，[17/22] 财报扩展）
**现象**：用户贴日批日志——龙虎榜同步成功（292s）后，"财报扩展周同步（仅周一）"报
**zzshare 401 鉴权失败**（提示检查 ZZSHARE_TOKEN / 个人中心 Token 是否变化）。

**排查（逐项排除，全部现场验证）**：
| 假设 | 结论 |
|---|---|
| .env 里 token 失效 | ✗ **有效**（663ee9...，64 字符，现场调用成功）|
| 系统环境变量有旧 token 顶掉（`_load_env` 用 `setdefault`，环境变量优先）| ✗ User/Machine/Process 三级**都是空** |
| 两个 worktree 的 .env 不一致（ssv-flow5 旧值）| ✗ 两边同值同长度 |
| 匿名不可用（Actions 缺 secret ⇒ 空 token）| ✗ **匿名完全可用**（market_style + finance_stock 都成功）|
| 财报类接口必须 token | ✗ 匿名调 finance_stock 也成功 |
| 服务端/网络瞬时故障 | ✓ 现场重测 5 接口 + 财报接口**全绿**，401 无法复现 |

**结论**：**一次性的、运行环境相关的失败**，最可能是①那次日批的进程环境里存在
失效 token（某终端 export 过旧值 / Render 变量带引号），或②服务端瞬时风控。
**行动**：重跑验证；若复现，在**同一终端**打印 `os.environ.get('ZZSHARE_TOKEN')` 前缀
定位；顺手检查 Render 变量是否有引号/空格；GitHub Secrets 补 token（待办仍在）。

### ★★ 根因找到（2026-09-21 下午，用户自述配置方式）
用户在 **Render / GitHub Secrets 的 Key-Value 界面**里，把 **`ZZSHARE_TOKEN=663ee9…`
整串填进了 Value**（`.env` 整行粘贴的习惯）⇒ 环境变量值 = `ZZSHARE_TOKEN=663ee9…`
（**长度 78** = 64 + 前缀 14）⇒ SDK 把整串当 token 发出 ⇒ **401** ✓✓
（本地 `.env` 文件整行写是对的，两者格式易混——这是本次事故的本质。）
**加固**：`zzshare_client.get_api()` 加**宽容清洗**（剥 `ZZSHARE_TOKEN=` 前缀 + 引号/空白，
并打印修正提示）⇒ 即使误配置也能工作；正确配置（纯 64 位 hex）不受影响。
已验证：模拟 78 长度误配置 ⇒ 打印告警 + 调用成功 ✓。
**待用户改**：Render 环境变量 + GitHub Secrets 的 Value 只填 64 位 token（改完重跑日批）。

**★ 顺手加固（重要）**：`zzshare_daily.run_daily` 加**「全失败不写库」守卫** ——
否则 401 时会写一行全 `_error` 的垃圾数据占住 date 主键 ⇒ 补跑被"已存在"跳过 ⇒
**该交易日永久缺失**（同体检报告"数据不全比没有更糟"的判据设计；部分失败仍写）。
**表检查**：`zz_daily_snapshots` 只有 9-18 一行（测试数据），无垃圾行 ⇒ 今天日批
在 zz_finance 处中断，zz_daily 尚未跑过。⚠️ **不要手动补写 9-21**（现在 14:1x 未收盘，
会存盘中残片且占住主键 ⇒ 晚上正式日批写完整版）。
