## 部署容量评估（阿里云轻量 2核2G 是否够用）
- 实测本机后端进程（`run.py` 的 uvicorn 子进程，PID 612，2026-09-05 08:42 启动、非交易时段）**Working Set ≈ 100–106 MB**；reloader 父进程另占 ~15 MB。生产单进程（无 --reload）约 ~100 MB 常驻。
- 关键规模参数：`CACHE_POOL_SIZE = 500`（按市值前 500 只）、`CACHE_KLINE_COUNT = 500`（每只 500 根日线）、`MIN_SCORING_KLINE_COUNT = 250`；scheduler 共 29 个 asyncio 常驻 loop（多数 sleep 轮询，I/O 密集）。
- 结论：2核2G **能跑**，但 2G 余量偏紧——盘后 15:15–16:30 多任务叠加（评分快照 / K线缓存刷 500 只 / 战法全量扫描 / 指标刷新 / 回测价格回填 / 日报 / 矛盾扫描）内存峰值可能到数百 MB 且 Python 不保证完全释放。**推荐 2核4G**（活动价约 165–199 元/年，比 2核2G 贵约 100 元/年）。若坚持 2核2G：必加 2G swap、DB 外置 Supabase 或本地 SQLite（同机不装 MySQL/PG）、uvicorn 单进程单 worker、关 --reload、监控内存。
- 阿里云轻量要点（已核）：CPU **不限制性能**（100%，Xeon 8269CY 2.5GHz，非突发实例）；2核2G3M 活动价约 61–108 元/年（限购 1 次）；大陆地域+域名需 ICP 备案（IP:端口 直连可免）；公网 IP 不支持更换/到期不保留；不支持 IPv6；仅一块数据盘、快照随实例释放 → `backend/data/` 必须自备份。
- 取舍建议：项目价值在"调度器 7×24 常驻"；若交易时段总有一台电脑常开且能内网/Tailscale 访问，`DEPLOY.md` 方式〇 本机部署零成本且性能更好；若要随时随地浏览器访问、不依赖个人电脑，则上云值得（一年几十到两百元）。
- 未来风险：手册第八章 P2「回测样本扩到 2 年」会显著吃内存/CPU，2核2G 会吃力。

## 重活外迁 GitHub Actions 的可行性评估（用户方案：Render 0.1CPU 只查表，定时任务跑重活）
- 结论：**方向可行**，但两个任务的性质完全不同，不能一刀切。
  - `refresh_indicator_cache`（app/scoring/indicator_cache.py，`INDICATOR_POOL_SIZE=300`）：**纯 DB 读 kline_cache + CPU 算指标 → 写 DB，不需要外网行情源**。最适合外迁，零网络风险。
  - `refresh_kline_cache`（app/scoring/kline_cache.py，`CACHE_POOL_SIZE=500`×500根）：**必须外网访问腾讯行情**（且池子为空时会先 `refresh_all_stocks` 拉全市场）。外迁到海外 runner 有 WAF/风控风险，是主要卡点。
  - 两个函数都是 `codes=None` 自取池、结果全部 `db.upsert` 落库 → **天然幂等**，重复跑无害；且都能像 `scripts/trigger_daily_report.py` 那样用"读 .env + sys.path.insert(BACKEND_DIR) + import app 模块"的方式做薄封装，无需改架构。
- 卡点：① Actions cron 是 best-effort，会延迟甚至丢事件，且 cron 用 UTC、仓库 60 天无活动会禁用；② runner 在海外，腾讯/东财对机房 IP 风控更严 + RTT 从 ~20ms 涨到 ~200-300ms（串行循环被放大）；③ 必须给 Render 侧加 env 开关关掉对应 scheduler loop，否则双跑；④ Actions 容器不持久，`backend/kline_cache.json`/data/*.json 每次冷启动为空 → 每次全量重拉，反而加剧风控；⑤ 私有仓库 Free 计划 2000 分钟/月，估 10-20min/次 × 22 天 ≈ 440min，够用但余量不大；⑥ Actions 无 A 股交易日判断，节假日会白跑；⑦ 失败要自己配 `if: failure()` 推企微，否则丢失 scheduler 现有的 `_notify_failure` 告警。
- 关键认知：这两个刷新循环是**串行 for 循环（Python GIL，单线程）**，4 核对它没有加成；真正的提速来自"不再被 Render 0.1 CPU 配额限流"。想用满 4 核需改多进程/线程池。
- 环境利好：requirements.txt 用的是 `psycopg2-binary`，ubuntu-latest 上 `pip install` 无需装 libpq-dev，开箱可用。
