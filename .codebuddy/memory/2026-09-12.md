## 📏 egress 精确测量工具（新增 `scripts/egress_probe.py`，**未提交**）
起因：用户看到 Supabase 面板 09-11 = **691MB**，怀疑"每次 push/部署 → Render 重启耗流量"。
代码事实（`main.py` lifespan）：**重启几乎不吃 Supabase 流量** —— 后端包 31.7MB 走 **GitHub Pages**（Render 磁盘临时，所以每次重启都重下，但记在 Pages 账上）；Supabase 侧只有 `market_snapshot` 单行 ~0.34MB + DDL/水位 + 各 loop 首轮，**合计 ≤1MB/次**。691MB 的真实原因：① 面板按 **UTC** 切天，"11 Sep" 覆盖北京 09-11 08:00→09-12 08:00（含 19:00 打包、21:03 日批#8、23:48 日批#9、凌晨 3 次 push 部署 + 研究脚本实测）；② **研究脚本治理前每次整表 ~90MB**（`c43a163` 修复）。
工具设计：`snapshot --tag X` / `diff --from X --to Y` / `top` / `list` / `widths`；数据源 = `pg_stat_statements`（累计 calls/rows）+ `pg_stat_statements_info`（重置检测）；字节 = Δ行数 × 表的「平均过网行宽」（`pg_column_size` 抽样 200 行，比 length() 更接近压缩过网字节）。快照落 `backend/data/egress_probe.json`（该目录 gitignore）。
**两条防误判口径**：写入语句（INSERT/UPDATE/DELETE）不计出口流量；只选部分列的语句估计值是**上限**（输出带 ≤）。
- 基线：`before` @2026-09-12 01:58，累计 2,686,119 调用 / 51,586,119 行，`stats_reset=2026-08-20 14:51 UTC`（正好等于面板统计周期起点）。
- 待办：**用户 push 或 Render Manual Deploy 后取 `after` 并 diff** → 得到"一次部署的精确 MB"（预测 ≤1MB；测量期间最好别开前端页面，否则会把页面流量算进去）。
- 累计归因（20 Aug ~ 12 Sep，读语句 ≈ 11.15GB，面板 16.24GB，差额=未解析表名/上限高估/top300 之外的语句）：`kline_cache` 单只 ≤2017MB（303,864 次，周一包陈旧 bug，09-12 修）· `flash_news` 整表 1269MB（镜像退役）· `mainflow` 整表 ≤899MB（版本门控）· `backtest_prices` 单只 891MB（列裁剪+缓存）· `flash_analyses` ≤843MB（since 下推）· `flash_reviews` 666MB（since 下推）· `tracking_state` ≤322MB（缓存）· `macro_history` 166MB（缓存）· **尚未治理的下一批候选**：`stock_industry ⋈ stock_finance_zz` ≤165MB（75 次/126 万行，每次约 1.7 万行）、`strategy_results` ≤104MB、`stock_finance_zz` ≤81MB、`etf_close` 62MB（6,560 次）。
