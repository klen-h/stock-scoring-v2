## ✅ \"本地 68.8 vs 后端 72.6\" + \"K 线只到 9 日\" 定位与修复（041d552 已推送）
- **实锤**：000567 海德股份 前端包 kline-pack-latest（09-10 18:00 生成，123 根）末根 **09-09**；后端包 backend-pack.db（09-10 20:30 生成，752 根）末根 **09-10**。→ 本地图少一根、本地评分用 09-09 口径，后端用 09-10 → 差 3.8 分。**不是前后端评分引擎口径分歧**。
- **根因**：前端包 739/1534 只（48%）末根停在上一交易日，791 只正常；后端包 1425/1431 正常。同一接口（腾讯 fqkline qfqday）、同一交易日，唯一差异是**拉取时刻**——腾讯复权序列收盘后是**逐只**补齐的，18:00 那一轮近半数还没补完，20:30 那轮基本齐全。（另有 5 只 extremes 是停牌股：如 605577 末根 09-08，属正常。）
- **修复两处**：① `generate-kline-pack.py` 新增 `refetch_stale_lastbar()`：对末根 < 池内最新交易日的股票补拉（最多 2 轮，复用 WAF 冷却/退避；>90% 都落后则判定"当日数据未发布"跳过），kline-data.yml 前端 job 超时 60→90 分钟；② 前端 `loadLocalKline` 加**包新鲜度门**：本地包日期 < `expectedPackDate()`（工作日 15:00 前算上一工作日）→ 返回 null 回退后端接口（否则"旧本地压过新后端"）。
- 备注：前端包日期=**生成日**（非末根日期），所以停牌股不会误触发新鲜度门；节假日 18:00 也会生成当日包（包日期=节日当天）→ 门不误判。
- **002452 本地榜上有、后端榜没有 —— 是「两阶段候选池」截断（非数据问题）**：002452 在两包里都有（末根都到 09-10、流通市值 62.04 亿过 50 亿门槛）；后端单只精算 **69.8 分**（技术 64.4/资金 58.5/基本面 76.7/成长 72.2/质量 88.0），但 `/batch/top?limit=200`（池 1561）里没有它。本地复算简化分：**第 352/1561 名（61.6 分）** → `_batch_with_precise_top` 的候选池 = 简化分前 `limit+margin`（limit=50 → 前 100）→ **它从未被精算过**，所以永不入榜；前端本地是"包内全量精算后排序"，所以它上榜。简化分只看 动量+换手+PE（当日 -3.07% → 动能弱），而它的高分来自基本面/质量（PE、ROE、毛利率），简化分不参与 → 出现"精算 69.8 / 简化 61.6"的错位。
- **修法（待定）**：A 放大候选池（margin 50→~400，覆盖简化分前 ~450）——改动最小，代价是每次精算数 100→450（结果有 3 分钟缓存）；B（推荐）日批在 Actions 全量精算榜单落库/pack，后端直接读，与前端本地口径完全一致；C 前端以本地全量精算为准。
