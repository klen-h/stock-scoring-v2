### 2. 宏观分数切风格回测（`scripts/macro_style_backtest.py`）

**照用户原意，未做任何优化**：score>0 买创业板、score<0 买上证50，逐日切换。

**窗口**：国家公告打钩起点 2026-10-26 起，14 个决策日。

| 指标 | 结果 |
|---|---|
| 策略累计 | **-3.46%** |
| 对照：一直持上证50 | **+0.26%** |
| 对照：一直持创业板 | -7.60% |
| 切换次数 | **8 次 / 14 日** |
| 加成本（单边0.05%） | -4.31%（再差 0.85pp） |

**分组命中率**（rel = 创业板 − 上证50）：

- **score > 0（预测成长强）：命中 3/8 = 38%**，rel 均值 **-0.462pp** ⇒ **不成立**
- score < 0（预测权重强）：命中 3/6 = 50%，rel 均值 -0.688pp ⇒ 方向对但等于硬币

**判定 FAIL**：策略跑输最简单的"什么都不做、一直持上证50"。

### 3. 核心判断（比结论本身更重要）

**宏观分数的设计目的是"描述当前宏观环境"，不是"预测明日风格"。**

- 它日间波动极大（+18.2 → +0.2 → -2.9 → +19.8 → -14.5 → -17.8 …），
  正负交替几乎随机 ⇒ 用它做择时必然高换手；
- 8 次切换 / 14 个决策日 = **两天一次**，成本就能吃掉大部分差异；
- ⇒ **若回测无效，首先该怀疑"用途错配"，而不是"分数算错了"。**

### 4. 局限

样本仅 **14 个决策日**、单一行情片段（震荡下行 + 权重护盘）。
这是"这段时间发生了什么"，**不是统计结论**。换市况可能完全反过来。

**③ 11-12 那次（`d872789e`）不改分**
`evaluate_rules` 实际只加了两个展示字段：
```python
"name": RULE_NAMES.get(rule["id"]) or rule["id"],

```
`value` / `direction` / `strength` / `contribution` **一行没动**。
`_tx_parse` / `_parse_quote_time` 改的是时间解析，也不改分。

### ★ 真正需要注意的（不是"重测"，是"别踩"）

**① 想拉长回测窗口就会跨版本**
v1/v2/v3/v4 混在一起**不可比**。要跑全量 51 天，必须按版本分段，
或只用 v4 段（10-12 起，约 25 天）。**现在 14 天的结论不受影响。**

**② `RULES_VERSION` 靠人工 bump，没有强制约束**
改了阈值忘了改版本号 ⇒ 历史快照标着同一版本、实际口径不同 ⇒
**回测被污染且无法察觉**。
⇒ 建议（未做）：给 `RULES` 配置算个指纹（hash）写进快照，比人工版本号可靠。

**③ 10-26/27/28 三天 `rules_detail` 为空**（10-29 起才 21 条）
`direction.score` 正常（18.2 / 0.2 / -2.9，独立算的），
但那三天**做不了逐规则归因**（`rules_triggered` 里有值，`rules_detail` 没有）。

**④ 别把两套体系搞混**
- `direction.score`（`macro_daily`，51 天）= 规则加权分，**回测用的就是它**
- `macro_regime_class`（6 天，`scorer_version=2026-11-07.1`）= 制度概率分布（soft/stag/…）
后者跟这个回测无关；它 11-07 那次版本变更也不是"宏观分数改规则"。
