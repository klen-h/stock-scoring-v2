## 🧭 决策：缺口②（跨 tab 深链 / 选中态）**不做完整版**，只做「零成本通道路」

**用户问**：缺口②成本中等，建议做吗？

**核实后纠正了我自己上一轮的估计（上轮说「成本中等」= 低估）**：
1. `ScoreRank.vue:1152` `activeTab = ref('top')` = **纯进程内 ref、零 URL 联动** ⇒ 加深链要
   **新引入 `useRoute` + 双向同步**（现在只 import 了 `useRouter`，仅用于 push）；还会引入
   **新行为**（刷新后停留在某 tab），可能反而干扰。
2. **`switchTab` 带异步副作用链**：`switchTab('watch')` → `loadGateWatch().then(loadWatchPrices)`
   ⇒ 「定位到某行 + `scrollIntoView`」必须**等数据到位**才能做 ⇒ ★ **真正的复杂度在异步时序，
   不在 DOM**（加 `:id`/`:ref` + 高亮 class 本身只要几行）。
3. ★ **关键：「差什么」悬停就能看到** —— top 的 `3/3` 标签 `title` 里**已经**有 3 条判据的
   ✓/✗ + `hint` + 建议仓位 ⇒ 「切过去定位那只票」的边际收益只剩**省一次视觉搜索** ⚠️

5. **URL 深链对单用户系统价值 ≈ 0**（不会把 `?tab=watch&code=002709` 发给别人，也不会存书签）。

**⇒ 结论：值「通道路」，不值「深链机制」。**

## 🔥 线上内存实测 ⇒ 找到真根因并修复（用户 2026-09-24 提供首次线上读数）

**用户贴的读数**（诊断端点 + `memory_watch` 趋势首次真实数据）：
```
RSS 366.7MB / 500MB（73.3%）｜峰值 365.8MB｜线程 10
已知缓存 359.88MB｜**未归类仅 6.8MB**
占用最多：strategies._PRICES_CACHE 234.09MB（808条）｜flow._FLOW_MAP_CACHE 107.55MB（1条）
         store._SNAP_CACHE 7.58MB（2条）｜tencent._cache 6.52MB（3条）
趋势（24 次，跨重启）：78.4 → 79.2 → 79.2 → 81.9 → 82 → 83.8 → 83.9 → 83.9%
```

**★★ 三个关键结论**：
1. **不是泄漏，是「两个大缓存的设计上限太高」** —— **未归类仅 6.8MB** ⇒ 几乎全部内存都在
   已知模块级缓存里 ⇒ **没有框架层泄漏、不是 RSS 高水位** ⇒ **修缓存 ＝ 修问题**。
2. **我上轮的判断错了**：我曾怀疑 `tencent.KLINE_CACHE`（本地 209 条/13MB）是头号 ——
   线上它**根本没进榜**（`tencent._cache` 仅 6.52MB）⚠️ **本地量级不能外推线上**。
3. **起点基线就 78%**（重启即高）⇒ 缓爬 +5.5pt 到 84%+ 再 OOM ⇒ 与监控图锯齿吻合。

**★ 根因：同类缓存「写了两遍、只修一遍」**
| | `backtest/data.py`（**正确样板**）| `backtest/strategies.py`（**线上炸的**）|
|---|---|---|
| 条数上限 | 200 ✓ | **无** |
| 取用时清过期 | 过期即 pop ✓ | **只当 miss，条目留着占内存** |
| 单条上限 | >900 根不缓存 ✓ | **无** |
| 淘汰 | 满 200 丢最旧 1/4 ✓ | **无** |

⇒ `strategies.py` 是 `data.py` 的**残缺版**。key 是 `(code, start)` ⇒ **同一只股票的不同信号日
各自缓存一整段 bars**（数据高度重叠）⇒ 只增不减；且 `_PRICES_TTL` 只是**逻辑过期**（命中判断
`now - ts <= TTL`），过期仍占内存 ⇒ 唯一释放时机 = 回填后的 `invalidate`（**每天一次**）
⇒ 形态就是「**每天从 0 涨到 ~808 条 = 234MB，回填时清空**」= 监控图的锯齿 ✓

**★ 修法（`backend/app/backtest/strategies.py`，对齐 data.py 成熟做法）**：
新增 `_PRICES_CACHE_MAX = 200` / `_PRICES_BAR_MAX = 900` + `_prices_cache_get()`（**过期即 pop**）
+ `_prices_cache_put()`（单条 >900 不缓存 + 满 200 丢最旧 1/4）；两处读、两处写全部改走新入口。
**语义零变化**（缓存只加速，miss 即回源 pack/DB）⇒ 最坏只是回测多花点时间（低频手动操作）。

**验证 10/10**（打桩，未触网）：条数上限 len=200｜单条 >900 不缓存、=900 仍缓存（边界）｜
过期取用返回 None **且条目被物理删除**｜新鲜命中返回**同一对象**｜淘汰丢最旧｜invalidate 清空。
**外推：234MB → ≤56MB（省 ~178MB）⇒ 366MB → 约 190MB（38%）** ✓

**⚠️ 剩余（107MB，本轮未动）**：`mainforce/flow._FLOW_MAP_CACHE` = **整表资金流的 Python 表示**
（8.4 万行 × 9 字段，单条 107MB）。服务路径**真的需要**（`mainforce/state.py:197` 全池主力状态、
`gate.py:152` 批量闸门）⇒ **不能简单删**；要优化得改数据结构（dict 列表 → 紧凑结构）或分层的
「近 N 天」小 map，属**中等风险改动**，留待评估（评分冻结期不轻动）。
