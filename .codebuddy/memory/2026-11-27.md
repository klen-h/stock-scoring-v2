## ★★ 行情缓存 11 小时零刷新，且系统无法自证原因

用户："还是有问题：持仓状态（4 只 · 风险 1 / 机会 1）行情 09:37，盘面速览 也有问题"

### 线上实测（20:09，已收盘）

```
/api/market/refresh-status:
  stock_count = 5260
  last_update = 2026-11-27 09:37:59    ← 11 小时前
  total_codes = 14997

/api/score/batch/portfolio-radar:
  as_of = 20:09 | quote_as_of = 09:37 | quote_from_snapshot = False

/api/market/overview → style.as_of = '11-27 09:37'，同样冻结
```

### 关键排除项（缩小范围）

| 观察 | 结论 |
|---|---|
| `limit_age_sec = 91.8`（涨停 rt_k） | **进程活着、调度在跑**，不是整体挂死 |
| `from_snapshot = False` | 不是快照恢复态（进程没重启，或重启后没切快照） |
| `stock_count = 5260` 不变 | 缓存内容没被替换，也没被清空 |

⇒ **只有 `_cache["stocks"]` 这一条链冻结**，其它数据源（rt_k）正常。

### 决定性实验：手动 force 触发也无效

```
GET /api/market/trigger-refresh  → {"status": "refreshing"}
轮询 refresh-status 18 次 × 10s（共 180s）：
  last_update 始终 = 2026-11-27 09:37:59
```

⇒ 不是"调度循环没调用"，是 **`refresh_all_stocks` 内部提前退出**。

### 根因候选：三条**静默退出**路径（全都不留痕）

```python
# ① 内存高压（mem_guard ≥70%）
if guard("refresh_all_stocks"):
    return _cache.get("stocks") or {}

# ② 刷新不完整（< 旧池 90%，宁陈旧勿清空）
if len(stocks) < _old_n * 0.9:
    return _cache["stocks"]

# ③ 异常（被 scheduler 捕获只 print 一行）
```

三者都 `return 旧缓存`、**都不更新 `last_update`**、**都没有可查询的痕迹**
⇒ `refresh-status` 只能回答"上次成功是什么时候"，**回答不了"为什么没成功"**。

⚠️ 无法从外部断定是哪一条（拿不到服务器日志）。但无论哪条，**静默是共同病根** ——
这和 11-24"盘前占位包假 0"、11-17"scheduler 静默"是同一类：
**系统错了但不说话，比错本身更难查。**

### 修复：加 `_refresh_state` 诊断（治本）

`tencent.py`:
```python
_refresh_state = {
  "last_attempt_ts", "last_result",   # ok/skip_mem/incomplete/error
  "last_detail", "fail_streak", "last_ok_ts",
}
def _mark_refresh(result, detail=""): ...
```

插桩 4 处：`guard` 跳过 / `_incomplete` / 成功 / 异常。
另外在 `refresh_all_stocks` **入口**记 `last_attempt_ts`（不写 result）。

`cache_meta()` 暴露全部字段 → `/api/market/refresh-status` 直接返回。

**判读法（关键设计）**：
- `last_attempt` 在前进、`last_result` 不变 ⇒ **卡在 `_cache["lock"]` 上**（锁死形态）
- 两者都不动 ⇒ 根本没被调用（调度循环挂了）
- `last_result = skip_mem` ⇒ 内存高压
- `last_result = incomplete` ⇒ 拿到只数不够（WAF/限流）
