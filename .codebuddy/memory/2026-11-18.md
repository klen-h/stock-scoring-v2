# 2026-11-18

## ★★ 交易计划自动模拟闭环（`cfcc6fcf`）

用户看了交易计划表后说："**不需要我手动上车，自动用模拟仓模拟**。"

### 问题起点

交易计划页显示「达目标✓」，但那个状态机是**纯价位推演**：
```
waiting → hit → targeted/stopped   （只拿现价跟三个价位比）
```
**全程不检查有没有真的买** —— 用户没上车，"达目标✓"就是纸面推演，不是验证。

### 实现：完整模拟成交闭环

```
waiting（等买点）
   ↓ 触及买点 → 自动建模拟仓（t_sim_positions，按建议股数、触发价成交）
holding（模拟持仓中）
   ↓ 触及目标/止损 → 自动平仓 + 记账盈亏
targeted / stopped
```

**① 取消 `plan_type` 门槛**

`should_auto_build()` 不再区分 `trial` / `t_build` —— 原先"trial 只提醒"的前提是
"可能有真实资金后果"；现在全程模拟、不碰 `user_portfolio`，让用户手动上车
反而制造错觉。**总开关 `T_AUTO_BUILD=0` 保留**。

**② 修掉一个死路（关键）**

原实现建仓后置 `filled`，而 trigger 循环只查 `status='waiting'`
⇒ **后面的目标/止损永远不会触发**，模拟仓建了就没人管。
改成置 `holding`，查询改 `IN ('waiting','holding')`，buy 信号只在 `waiting` 生成
（否则每 60s 重复推"到达买点"，幂等虽防重复建、防不了刷屏）。

**③ 平仓记账**

`t_sim_positions` 幂等补列：`close_price / close_date / close_reason / pnl / pnl_pct`。

新增 `close_sim_by_plan(plan_id, price, reason)`：
- **按 plan_id 而不是 code** —— 避免误平同一只票另一条计划的仓
- 盈亏以开仓 `cost × shares` 算，**不用 buy_price**（否则带一个假成本偏差）
- 并发重复调用只记一次（`db.execute` 影响 0 行 ⇒ None）

推送里会写：`模拟仓已平 300股 11.10→11.40，盈亏 +90.00 元（+2.70%）`。

**④ 前端**

交易计划页加「模拟仓」列：持仓时显示股数/成本，平仓后显示盈亏；
状态标签补 `holding → 模拟持仓中`；说明文字明确
**「达目标✓」只是价位验证，以模拟仓盈亏为准**。

### 重要边界：历史不补

福能（11.97，买点 11.10）、渤海（4.72，买点 4.59）买点早已过去，
**不会回溯补仓** —— 日线最低价到过买点不等于能以买点成交（项目纪律：不拿近似冒充精确）。
它们的「达目标✓」仍是纸面结果，新逻辑只对**上线后**触及买点的计划生效。

云南铜业（12.76，买点 12.71）若在 ±2% 内且未破位，后续会自动建约 500 股模拟仓。
