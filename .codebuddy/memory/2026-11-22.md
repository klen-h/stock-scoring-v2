## 复盘页布局修复：右下大面积空白

用户贴截图（盘后·复盘段）：执行一致性 / 三时段复盘对账 / 明日准备 三卡，
右下角完全空着，"优化一下布局"。

### 根因：三张卡被塞进两列 grid，第 4 格空着

```
<div class="grid grid-cols-1 xl:grid-cols-2 ...">
  ① 执行一致性        ← 第 1 格
  ② 三时段复盘对账    ← 第 2 格（2026-11-14 加进来时插错位置）
  ③ 明日准备          ← 第 3 格
                       ← 第 4 格 = 空
```

而且三时段块自带 `mt-3`（grid 内加 margin 会与 `gap-y-4` 叠加，本来就不该有）。

### 修法：恢复 2026-09-26 的原意图

```vue
<div class="grid grid-cols-1 xl:grid-cols-2 gap-x-4 gap-y-4 items-stretch">
  <div>执行一致性</div>     <!-- 今天做得对不对 -->
  <div>明日准备</div>       <!-- 明天要做什么 -->
</div>
<!-- 三时段对账移到 grid 之后，全宽独立一行 -->
<div v-if="reviewSummary" class="bg-card ...">…</div>
```

**为什么这样分**：
- 「执行一致性 ↔ 明日准备」是**语义相配的一对**（结论 + 行动），
  2026-09-26 用户就是这么定的，两卡等高（`items-stretch` + `h-full`）。
- 「三时段复盘对账」信息量最大（三段时间线 + 近 15 日趋势柱状图），
  全宽后柱状图才有宽度铺开，不再被挤在半栏里。

### 顺带的两个小优化

1. 三个时段框原先完全同款，宽屏分不清 ⇒ 加左侧色条
   （盘前蓝 / 盘中红 / 盘后紫，与时段按钮同色系）：
   ```js
   const SEG_BORDER = {
     premarket: 'border-l-sky-500/60',
     intraday: 'border-l-rose-500/60',
     postmarket: 'border-l-violet-500/60',
   }
   ```
2. 趋势柱状图 `h-10` → `h-12`（全宽后有空间，柱子更好读）。

### ⚠️ 踩点记录：卡片间距来自**父容器 `space-y`**，不能给卡片加 `mt`

盘后 template 内所有卡片（`bg-card`）都**没有 `mt`** 却有均匀间距
⇒ 间距由外层 `space-y-*` 提供。
所以把三时段块移出 grid 时，原 `mt-3` 必须**去掉**（否则叠加成双倍间距）。

**判断方法**：改动前先扫一遍同级卡片的 class —— 如果它们都没有 `mt`/`mb`，
说明间距是父容器给的，新卡片跟着同级走即可。

验证：`pnpm build` 17.95s ✓、294 passed ✓、导出对账 ✓。

## ★★ 配色纠正："命中"必须用红色（全站 A 股语义）

用户："命中颜色应该是红色。"

### 根因：写死了西方配色，与项目语义色相反

```js
// tailwind.config.js
rise: '#ef4444'   // 红 = 好/涨
fall: '#22c55e'   // 绿 = 差/跌
```

**项目早就有这套语义色**，教练页执行率用的就是 `text-rise`。
但复盘卡写成 `hit: 'text-emerald-400'`（绿=好）、`miss: 'text-rose-400'`（红=差）
⇒ **同一页面里"盈亏红=赚"和"命中绿=好"并存**，用户要在两套心智模型间切换。

### 改动清单（统一为 rise=红=好 / fall=绿=差）

| 位置 | 原 | 现 |
|---|---|---|
| Workbench 摘要行 命中/打脸 | emerald / rose | `text-rise` / `text-fall` |
| `verdictCls()` hit/miss | emerald / rose | `text-rise` / `text-fall` |
| 趋势柱状图 ≥50% | `bg-emerald-500/60` | `bg-rise/60`（低于 50% 用 `bg-fall/60`）|
| 执行一致性主数字 | `text-emerald-400` | `text-rise`（对齐教练页）|
| `FlashPhaseCard.verdictTone` 命中/打脸 | emerald / rose | `bg-rise/20 text-rise` / `bg-fall/20 text-fall` |
| `MacroEnvCard` 方向色（＋/－、组得分） | 涨绿跌红（反） | 涨 `text-rise` / 跌 `text-fall` |

趋势图图例同步写明：**红=命中率≥50%，绿=低于 50%，灰=未到 T+5 验证期**。

### ⚠️ 约定（后续改配色先看这条）

- 表示"好坏/涨跌"**一律用 `text-rise` / `text-fall`**，不要硬编码 `emerald`/`rose`/`red`/`green`。
- `emerald`/`rose` 在项目里仍有大量使用，多数是**历史遗留**；
  遇到与"红=好"冲突的地方可以顺手对齐，但不要为了统一而大面积改动。
- "计数类"数字（已执行 N 条）用中性色更合适，不必强行染红。

验证：`bg-rise/60` 等自定义色 + 透明度已被 Tailwind 正常生成
（构建产物核对：text-rise 3、text-fall 3、bg-rise 4、bg-fall 4）。
build 19.93s ✓、294 passed ✓、导出对账 ✓。

## 11-20 暴跌日：数据核实 + 暴跌后统计（用户贴市场分析问"收获"）

### 一、项目数据核实（与外部分析对照）

```
market_emotion_daily 2026-11-20
  as_of 09:25（早盘口径）: up 69 / down 4901 / limit_up 3 / limit_down 20
  收盘口径:              close_up 257 / close_limit_up 30
  verdict:               冰点
```

自算（`backtest_prices` 1099 只，close vs 前收）：
```
上涨 76 · 下跌 1016 · 平 7 · 平均涨跌 -3.79%
```

外部分析说"仅 313 只上涨、超 5200 只下跌" ⇒ **与项目 close_up=257 同量级，可信**。

**★ 最有价值的一条：指数假象的量化**
```
沪指 -1.23%   vs   全市场个股平均 -3.79%   ⇒ 差 3 倍
下跌占比 92.4%
```
权重股（银行/两桶油）拉抬指数，掩盖了广度崩塌。
**⇒ 任何"沪指跌 3% 才减仓"式的指数风控，在这种结构里完全失效。**

### 二、回测：全市场平均跌幅 ≤ -3.5% 之后怎么走

（`backtest_prices` 2022 至今，宽度≥800 只）

| 指标 | 值 |
|---|---|
| 样本 | **仅 5 天**（⚠ 统计意义有限）|
| 当日均值 | -5.84% |
| **T+1** | **+0.61%**（基准日均为 +0.060% ⇒ 10 倍）|
| T+3 | +0.88% |
| T+5 | -0.12% |
| **T+1 上涨概率** | **仅 40%** |

**⇒ 关键洞察：期望值为正，但胜率不到一半。**
典型的"少数大反弹 + 多数继续跌"——均值被少数大涨拉高。
**"低开抄底"是胜率 40% 的赌注，不是策略。**

11-20 在历史跌幅排位里是**第 4 名（-3.79%）**，前面更惨的有：
2025-04-07 -9.27%、2024-10-09 -7.85%、2026-03-23 -4.62%。
⇒ 外部分析"周五只跌了一半英伟达映射"在**跌幅量级上成立**。

### 三、方法论沉淀（可复用）

1. **"跌了一半"是可检验的定量说法** —— 把"跌了/没跌"换成"已消化比例"，
   才能决定周一是否还有下跌空间。这段分析最专业的地方就在这。
2. **跨市场传染系数**：`A50 夜盘跌幅 / 纳指跌幅`（本例 0.85/5.28 = 0.16）
   ⇒ 可直接算，比"外资没恐慌"这种定性判断硬得多。
3. **看指数必须配广度**：指数 +1.2% 而 92% 个股下跌，是"被买出来的面子"。
4. **这段分析的通病仍是"无失效条件"**：
   "周一低开几成定局"—— 什么情况会高开？没写。
   与 11-16 中信建投研报同一毛病（不可证伪 ⇒ 只能当情绪读数）。

### 四、可落地的系统观察器（尚未实现）

- **广度-指数背离**：指数涨/微跌 但 下跌家数占比 > 80% ⇒ 告警
  （数据已有：`market_emotion_daily` 的 up/down）
- **暴跌后统计**：把上面那段回测固化成观察器，每次冰点日自动给出
  "历史同组 T+1 分布"，避免临场拍脑袋
- ⚠️ 样本仅 5 天，做观察器时要**明示 n**，不能当强信号

## ✅ 已实现：广度-指数背离观察器（用户："可以"）

### 遇到的第一个问题：项目没有指数日线

```
market_snapshot          → 个股收盘快照（stocks_json），不是指数
market_tail_snapshot     → 只有 idx_json，且仅当天尾盘
其他表                    → 无任何指数日线
```

**⇒ 改用自算市值加权收益**（比"上证50 vs 全市场"口径更自洽）：

```
equal_pct = avg(stock_facts_wide.chg_pct)                    ← 个股体感
cap_pct   = Σ(chg_pct × float_cap_yi) / Σ(float_cap_yi)      ← 指数想表达的
gap_pp    = cap_pct − equal_pct
```

**口径校验（关键）**：11-20 算得 `cap_pct = -1.44%`，当日沪指 **-1.23%** ⇒ 吻合。
`stock_facts_wide` 覆盖 ~2813 只（比 `backtest_prices` 的 1099 只更全）。

### 实现

| 位置 | 内容 |
|---|---|
| `backend/app/breadth_divergence.py` | `compute()` 纯函数 + `classify()` 分档 + `snapshot()` |
| `backend/app/routers/system.py` | `GET /api/system/breadth-divergence` |
| `frontend/src/api/modules/system.js` | `getBreadthDivergence()`（30s）|
| `frontend/src/views/Workbench.vue` | 观察器卡内「广度背离」块（风格分化之后）|
| `backend/tests/generated/test_breadth_divergence.py` | 7 例 |

**分档**（阈值可用环境变量覆盖）：
```
gap ≥ 2.0pp 且 down_ratio ≥ 80%  ⇒ severe  「严重背离·指数假象」
gap ≥ 1.0pp                      ⇒ mild    「轻度背离·大市值抗跌」
gap ≤ -1.0pp                     ⇒ reverse 「反向背离·权重拖累」
其余                              ⇒ none    「一致」
```
**severe 必须同时满足 gap 和广度** —— 只有 gap 大（少数股跌、多数涨）不算
"个股在杀"，否则会夸大风险。

### 11-20 实测判定

```
severe 严重背离·指数假象
加权 -1.44% / 等权 -4.18% / gap +2.74pp
2813 只中 2600 只下跌（92%）
```

近 20 日 gap 序列里 **2.74 是极值**（次高 11-19 的 1.35，中位约 0.77）。

### 设计要点（后续改这个模块先看）

- **纯观察器**：不进 `market_regime` / 评分 / 准入门槛（与 `tell_watch` 同纪律）
- **日频**：数据来自日批快照 ⇒ 收盘后才有当天值，**盘中不更新**（卡上标 `截至`）
- `compute()` 抽成纯函数便于单测，不依赖库
- `chg_pct` 为 NULL / `float_cap_yi ≤ 0` 的行**剔除**，不能按 0 参与（0=持平会稀释均值）
- 空数据返回 `ok=False`，**绝不返回 0**（0 会被读成"完全一致"）
- 前端与「风格分化」**并行**拉取（`Promise.allSettled`），老库上串行各等 1~3s

**301 passed**、build 16.83s、卫生门 ✓、导出对账 ✓。
