### 关键的方法论修正（踩了两个坑）

**坑① 绝对涨跌被 beta 淹没**
首版用 `up_pct * dst_pct * sign > 0` 判定，命中率 0.48（=随机）。
原因：A 股板块联动极强，"上游大涨"往往是全市场普涨日，下游跟着涨
⇒ 成本传导（负相关）被 beta（正相关）覆盖，**测出来的是大盘不是传导**。
⇒ 改**去 beta**：两边各减当日全板块均值，只比超额。阈值也随之从 3% 降到 1.0-1.5%。

**坑② `no_edges` 漏标，独立板块被连成一条 10 跳假链**
`独立板块` 里 11 个不相干的板块（综合/园区/公交/教育…）按节点顺序
被自动连成"链"，贡献 98 个纯噪声样本。加 `no_edges=True` 标记后消失。

### 顺手用回测否掉的三条边（机制不成立，不是数据调参）

| 边 | 原 sign | 回测 rate | 处置 |
|---|---|---|---|
| `小金属 → 能源金属` | -1 | 0.25 | 删（两者**同层并列**，不是上下游） |
| `化工新材料 → 电子化学品` | -1 | 0.25 | 删（**包含关系**，电子化学品是子集） |
| `油气开采及服务 → 燃气` | +1 | 0.31 | 删（**双刃**：气价对上游是收入、对城燃是成本） |

⚠️ 这三条是"逻辑上明显错"才删的，**没有按数据硬调参**（50 天调参必然过拟合）。

### 功能定位（因此降级）

**关键读法**：均值显著为正（t=3.24）但**胜率低于 50%** ⇒

## ★★ 本地跑起来（用户："我本地开发，先本地跑"）

### 一、★★★ 关键坑：`.env` 的 `DATABASE_URL` 指向**线上 PG**

`backend/.env` 里 `DATABASE_URL=postgresql://...` ⇒ 直接 `python run.py` 会连**线上 Supabase**，
而本轮回补的 177 天题材数据 / 461 天板块数据全在**本地 SQLite**（`backend/data/app.db`）
⇒ 页面会是空的（线上 `topic_rotation` 0 行）。

**第二个坑（更隐蔽）**：PowerShell 里 `$env:DATABASE_URL=''` **等于删除该环境变量**，
于是 `run.py` 的 `load_dotenv()` 又把 `.env` 的 PG 值填回来 —— 看着设了、其实没设。

**正确写法**（`database.py` 只判 `startswith("postgresql://")`，其余全走 SQLite）：
```powershell
cd backend
$env:DATABASE_URL='sqlite:///app.db'   # 必须非空；路径被忽略，固定用 backend/data/app.db
$env:DATA_SOURCE='db'                  # 跳过 run.py 的「数据包新鲜度」preflight
$env:RENDER_READ_ONLY='1'              # 关重活 loop（省外呼，页面浏览不受影响）
python run.py --no-reload
```

## ★★★★ 新增：个股分时盯盘（watch_radar）

### 一、技术地基（先验证再写）

腾讯 `_fetch_tencent` 只解析到 `[51]`，**五档在 `[9]~[28]` 一直没解析**

`bids=[[价,量手]×5] / asks=[[价,量手]×5]`。
⚠️ 必须 `r.encoding="gbk"`，否则中文乱码。

### 二、规格（用户要求明确输出的五项）

**① 功能范围**
```
✅ 突破阻力 / 跌破支撑 / 大额压单(卖) / 大额托单(买)  → 企微即时推
✅ 自动标注当日支撑/阻力
❌ 不给买卖指令、不改评分、不进闸门、不碰模拟盘
❌ 不做回测校准（阈值经验值，推送里必须写明"未校准"）
```

**② 数量上限**：硬上限 **5 只**（`WATCH_MAX_CODES`），超了直接 400 拒绝，
不是"建议"。

**③ 支撑/阻力标注规则**
```
阻力 R = 昨收价        （昨日收盘是最强心理位，昨日的压单会延续到今日）
支撑 S = min(昨收, 近5日最低)
盘口阻力/支撑 = 卖/买五档中挂单量最大的档位价（实时，不落库）
```
例：000725 → R=4.50（11-26 收盘）、S=4.32（近5日低点）。

**④ 提醒触发条件**
```
breakout   现价 ≥ R × 1.003          突破阻力
breakdown  现价 ≤ S × 0.997          跌破支撑
wall_ask   某卖档 ≥ max(20万手, 每分钟均量×3) 且**连续 2 次快照**
wall_bid   同上（买侧）
```
⚠️ **压单必须连续 2 次快照** —— 盘口挂单随时可撤，单次快照的"几十万手"
多是幌骗（spoofing），不设这条会天天误报。

**⑤ 通知方式**：企微 `push_markdown_batched(category="alert")`；
去重主键 `(date, code, kind)` ⇒ 每票每类信号每日 1 条。

```
   阻力（红）/ 支撑（绿）+ 来源标注（昨收 / 近5日低点）
   五档盘口：卖5→卖1 倒序在上、买1→买5 在下，
             量用横条（卖=绿、买=红），超过压单阈值的数字加粗高亮
   今日已触发信号（时间 + 类型 + 详情）
④ 口径与边界：规则随接口下发（status.rules），前端不硬编码
```

### 关键实现点

- **五档柱宽自适应**：`barW = max(2, v / maxVol * 100)%`，`maxVol` 取买卖十档最大值
- **卖盘倒序**：`asks.slice().reverse()` —— 盘口惯例卖5 在上
- **盘中自动扫**：页面常驻时每 60 秒 `scan(silent=true)`，但只在
  `inTrading()`（工作日 9:15-11:30 / 13:00-15:05）才触发，避免周末空转
- **页面扫描 push=false**：看数不推企微，推送只由后端 `watch_radar_loop` 负责
