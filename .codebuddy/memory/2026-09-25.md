## 🌐 本地开发流量纪律（用户问「开发前要不要先 sync_local --force」）

**核实结果**：
- `scripts/sync_local.py` 有 `--force` ✓（不加则本地包 mtime < 20 小时会跳过；加则强制重下
  44.9MB，走 **GitHub Pages 不消耗 Supabase**）
- `backend/.env` **已有 `DATA_SOURCE=local`** ✓（K线/指标/backtest_prices 走本地包）
- ⚠️ **但 `DATABASE_URL` 仍指向线上 Supabase** ⇒ **业务表**（`coach_alerts`/`paper_positions`/
  `ranking_live`/`trader_briefs`/`push_log` 等）**全部打线上** ⚠️
  ⇒ 而工作台恰恰要吃这些表 + **60s 轮询** ⇒ **会有持续 egress**（不是 600MB 级灾难，但会累积）
- `frontend/vite.config.js` 的 dev proxy 默认 `/api → http://localhost:8000`（本地后端）

**已把这一节补进需求文档 §12「本地开发环境与流量纪律」**（含两种起后端模式的流量对比、
包陈旧=静默回退 600MB 的坑、业务表本地化、开发期放宽轮询、验收自检）。
**推荐**：UI 开发用「本地前端 → 线上后端」（proxy target 改线上，本机零 Supabase，代价是调试
流量走 Render）；要断点后端时用「本地前端 → 本地后端 + DATABASE_URL 留空 + sync_local」。
