## ★★★ 路由劫持（`82e69e73`）—— `/market/emotion` 一直在返回竞价面板

用户："竞价看板一闪，是拿到了数据，但是立即消失，变为提示『非当日口径：属于 **—**』"

### 根因（一个字符级错误，藏了约 4 天）

`routers/market.py` 里：

```python
@router.get("/emotion")          # ← 本该属于 market_emotion
@router.get("/auction-panel")
def auction_panel(): ...
```

而真正的 `market_emotion()`（1777 行附近）**一个装饰器都没有** ⇒ **从未被暴露**。

**⇒ `GET /api/market/emotion` 一直返回的是「竞价面板结构」**（`indexes/sectors/llm`），
**没有 `price_date`、没有 `auction`**。

### 完美解释「一闪」

| 时序 | 数据源 | 结果 |
|---|---|---|
| ① `loadPulse()` | `/market/pulse` 的 `blocks.emotion`（**完整**，22 字段） | 看板**渲染出来** ← 用户看到的"一闪" |
| ② `loadEmotion()` | `/market/emotion`（**被劫持**，无 price_date） | 覆盖成空白 + `mmdd(undefined)` = `—` + `isTodayPrice()` 恒 false ⇒ 常驻提示 |

两个数据源先后写**同一个 ref**（`emotion`），后者把前者盖掉。

### ★ 为什么所有既有检查都拦不住

- `compileall`：语法合法 ✓
- `import app.main`：导入成功 ✓
- pyflakes：名字都存在 ✓
- **FastAPI 对重复 path 不报错**（两行装饰器都"注册成功"，请求时按顺序命中前者）

⇒ 这类 bug **在运行时之外完全不可见**。

### 修复 + 防护

1. 摘下 `auction_panel` 上的 `@router.get("/emotion")`，还给 `market_emotion()`
   - 验证：`/api/market/emotion -> market_emotion`、`/api/market/auction-panel -> auction_panel`
2. **新增 `scripts/route_audit.py`** 接进 CI：扫 `app.routes`，同一 `(METHOD, path)`
   指向两个函数即 `exit 1`
   - **已注入验证**：把 `/emotion` 加回去 → 精确报
     `GET /api/market/emotion -> auction_panel / market_emotion`，`EXIT=1`；还原后通过
3. 全项目扫描过一遍：**无其他同类叠加**（255 条 METHOD+path 唯一）

### ★ 这个 bug 的形态值得记住

它不是"写错逻辑"，而是**把 A 的路由挂到了 B 上**，于是 B 正常、A 消失。
**A 消失时不会报 404**（路径还在，只是换了实现）⇒ 前端拿到"合法但错误"的结构，
一路静默到界面上表现为"数据不对"。

**⇒ 这类"缺一个装饰器"的错误，只能靠"查路由表里有没有孤儿函数 / 重复 path"发现。**

## ★★★ 指数 K 线串标的（`cc293180`）—— 一个藏了 10 天的「指数变个股」

用户："① 开盘 vs 昨日关键位 中证500 8.31 / 中证全指 15.64，明显有问题"

### 现象

```
中证500   prev_close=8.31    open=6623.12   support=8.04
中证全指   prev_close=15.64   open=—         support=15.39
```

**8.31 / 15.64 是深市个股的价格，不是指数点位**（真实 6713 / 5207）。

### 根因（链路很长，但每一环都可验证）

1. `key_level_watch.compute()` → `_load_index_kline(code)` → `tencent.get_kline(code)`
2. 日批批量取 K 线时，**某只股票触发腾讯 501** ⇒ `_waf_blocked_until` 置位
3. 之后所有 `get_kline` 走"**WAF 冷却期用缓存**"分支：
   ```python
   db_klines = get_cached_klines(symbol)   # ← 裸 symbol
   ```
4. `get_cached_klines` 读 `scoring.kline_cache` —— **那是个股级缓存，只有裸 6 位代码**
5. 指数代码与深市个股**同码**：
   - `000905` 中证500 ≡ **厦门港务**（8.26）
   - `000985` 中证全指 ≡ **大庆华科**（15.99）
6. ⇒ 指数价被换成个股价，落进 `key_level_watch`

**实证**：`kline_cache` 表里 `000905`/`000985`/`000001` **都存在**，`sh000905`/`sh000985` **都不存在**。

### 为什么只有两只坏、`000001` 没坏

`INDICES` 顺序 = `[000001, 000300, 000905, 000985, 399001, 399006]`。
WAF 在取到 `000001` 时还没被触发（正常返回），到 `000905` 时已在冷却期 ⇒ 走缓存路径。
**⇒ 这是一个"取决于当天 WAF 从第几只开始触发"的间歇性 bug，不是每次必现。**

### 修复

- `INDEX_MAP` 判断**上移**到 `get_kline` 函数开头（算出 `_is_idx`）
- WAF 分支加 `and not _is_idx` ⇒ 指数在冷却期**直接返回 []**，
  由 `_load_index_kline` 继续走东财 / 日批库兜底（这两条都验过是对的）

**验证**（这是"改对了"的证据）：
```
正常：000905→6713.18  000985→5207.16
模拟 WAF 冷却：000905→0 根  000985→0 根  000001→0 根   ← 不再串标
```

- 已重跑 `compute()` 覆盖 11-11 的错误行（8.26→6713.18、15.99→5207.16）
- `auction_panel.suspect` 补**点位量级自检**（`prev_close`/`support` < 100）：
  原判据只看"缺口是否荒谬"，而中证全指 `open` 缺失 ⇒ `gap_pct=None` ⇒ 恒不判可疑
  ⇒ 界面上照常显示 `15.64/15.39`，**一点提示都没有**

### ⚠️ 遗留

- **11-10 及更早的历史行仍是错的**（`compute()` 只能算最新 K 线日，不能指定历史日）。
  只影响回放，且现在有 `suspect` 标记兜底。
- 更早的注释（`key_level_watch.py:316`）**2026-11-05 就写下了**这个现象
  （"`compute()` 的 K 线源存在串标的的既有 bug"），但当时**只加了护栏没修根因**
  ⇒ 又错了 7 天。**★ 教训：写了注释承认 bug 但不修，等于把 bug 转成了"已知的技术债"，
  而它会继续每天污染数据。护栏只能让错误可见，不能阻止错误发生。**

### ③ ★★★ 真 bug：`data_time` 恒为 None（两个根因叠加）
