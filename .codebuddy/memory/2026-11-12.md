### ① 「纳斯达克涨了 3 个多点怎么没显示」—— 数据没错，**是三天前的**

实测同一时刻：

| 来源 | 值 | 时间 |
|---|---|---|
| 面板显示的锁定快照 | `nasdaq=0.56%` | `generated_at=2026-11-11 08:55:22` |
| 实时（腾讯 `hf_NQ` 期货） | **2.62%** | `2026-11-12 00:44` |
| 实时（`gb_ixic` 现货） | 1.85% | `Nov 11 11:44AM EST` |

**两个都对，只是时点不同**。用户看到的 0.56 是 **11-10 收盘**（11-11 早盘锁定的），
而他说"涨了 3 个多点"是 **11-11 盘中**。

⇒ 真问题不是"没算"，而是**界面没说清这是哪天的数据**（见 ③）。

### ② 「今日锁定 · 生成于 08:55」不是新加的

`MACRO_DAILY_WINDOW = (535, 780)`（08:55–13:00）由 `123d7825`（回测系统那次）引入，
**一直存在**。

**为什么用户觉得"之前是实时的"**：`macro_daily` 表 11-05 起才有连续快照 ——
早先定时任务常错过窗口（电脑没开机/服务没跑），前端一直走 `locked=false` 的实时分支。
现在每天稳定锁定，就"突然"都是锁定态了。

### ③ ★★★ 真 bug：`data_time` 恒为 None（两个根因叠加）

界面「数据截至」永远是 `—`，所以用户**没有字段能判断 0.56 是哪天的**。

**根因 A**：`macro._tx_parse` 的 `else` 分支（`us*` / `hk*` / `gb*`）**硬编码 `t = ""`**
```python
else:
    f = val.split("~")
    price, prev = _f(f, 3), _f(f, 4)
    ...
    t = ""        # ← 时间从来没取
```
实测腾讯 `us*` 族 **`f[30] = 2026-11-11 11:43:40`** ⇒ 已改为按日期形态校验后取 `f[30]`。

**根因 B**：`get_macro_snapshot._parse_quote_time` 只认三种格式，**不认新浪美股格式**
`Nov 11 11:43AM EST` —— 它**没有年份**（strptime 必抛）**且是美东时区**（与腾讯的北京时间
直接丢进 `max()` 会差 13 小时）。已补：补 UTC 年 + 按 EST/EDT 换算成北京时间。

修复后 `data_time = 2026-11-12 00:44:25` ✓
