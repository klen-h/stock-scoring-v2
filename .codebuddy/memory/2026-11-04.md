## 001｜服务器 `git pull` 超时 → 用 `git archive` 打包传文件（绕开 git 网络）

**现象**：阿里云北京的服务器 `git pull` 超时（clone 当时能过，pull 卡住）——GitHub 链路不稳定。

**兜底方案（已在本地验证可行）**：
```powershell
# 本地仓库根目录
git archive --format=tar.gz -o ..\src-latest.tar.gz HEAD
```
- 只打包 **tracked 文件** ⇒ **天然排除** `backend/.env`、`backend/data/`、`node_modules`
  ⇒ 解压不会覆盖凭证与运行数据，这是它比 `rsync 整目录` 安全的地方
- 当前包：`D:\stock-scoring\src-latest.tar.gz`，**4.5 MB**，对应 HEAD `759277fa`

**服务器侧**：
```bash
cd /www/wwwroot/stock-scoring-v2
sudo tar -xzf src-latest.tar.gz
sudo chown -R admin:admin .          # sudo 解压会变 root 属主，必须改回
sudo systemctl restart stock-scoring
```

**其它可尝试的**（优先级低于打包）：
1. `git config --global http.postBuffer 524288000` + `http.lowSpeedLimit 1000` + `http.lowSpeedTime 60`
2. 临时换镜像 remote（`https://ghfast.top/` 之类），**只用于 pull，不要用于 push**

⚠️ 以后每次服务器更新若 git 仍不通，就重复「本地 git archive → 上传 → 解压」这条路。

## 004｜黄金换东财 `122.XAU` 现货 + 顶栏精简（`8e7c8fa1`）

**用户线索**：`https://quote.eastmoney.com/q/122.XAU.html`
⇒ 市场号 **122 = 贵金属**，`XAU` 名称为"黄金/美元"。实测 3930.17 / -0.42% / 昨收 3946.63。
（`122.XAG` 白银/美元 49.71 也存在，暂未启用。）

### 关键决定：**单一来源**，而不是"新浪优先、东财兜底"
`gold` 原来 `_PANEL_MAP = ("hf_GC", "hf")`（COMEX **期货**）。
若只加东财兜底，新浪一恢复就会用期货价 3938 顶掉现货价 3930 ——
**同一个键在两种口径间来回跳，而面板只写"黄金"**，没人看得出今天是什么。
⇒ 把 `gold`/`gold_spot` 从 `_PANEL_MAP` 和 `_TX_MAP` 里**彻底移出**，
   放进 `_EXTRA_PANEL_KEYS`（仍参与缺失探测），只由 `_EM_MAP` 的 `122.XAU` 提供。

### 连带修的三处（换源必然带出的口径问题）
1. `flash/llm.py` 两处写死 `COMEX黄金` → `黄金现货(伦敦金)`
   （否则模型按期货口径推理基差/展期，拿到的是现货价，会算出错误结论）
2. 同文件 "COMEX黄金 / 黄金现货" 两行现在同源同值 ⇒ **删掉重复那行**
3. `_derived` 金银比：金=现货、银仍是期货（差 ~0.4%）⇒ 加注释。
   **只影响绝对水位，不影响 `goldsilver_change_pct`（日变化率，两端同向偏差抵消）。**

### 顶栏精简（用户："位置不够了…越简单越好"）
加了黄金后外盘 12 项，最占宽的是日期块：
- `日期 [今天 2026-11-03]` → `[今天 11-03]`（年份进 title/option）
- `● 17/17 · 库79.4% · 00:35 ▾` → `● 17/17 · 79% · 00:35 ▾`（去"库"、百分比取整）
- 外盘间距 `gap-3→gap-2`、`px-1.5→px-1`、`min-w-560→420`

## 005｜复盘：黄金换源到底必要吗 + 东财字段补全（`d1f3af4f`）

**用户反问**："黄金是不是没必要换成 122.XAU" ⇒ 结论：**对系统判断确实没必要，属口径偏好而非缺陷修复。**

依据（不是感觉，是查过的）：
- 规则只消费 `change_pct`（日内涨跌幅）与 `goldsilver_change_pct`（金银比变化率），
  **没有任何一条用金价的绝对水位** ⇒ 现货 3928 / 期货 3938 差 0.2%，方向分一分不差。
- 原来 `hf_GC` 走腾讯兜底**本来就拿得到值**（3938），所以换源不是"补数据缺口"。
- 真实代价：① `macro_daily_history` 断一天口径 ② 金银比变混合口径（金现货+银期货）
  ③ 改了 LLM prompt 的 label。
- 结论：**换不换都行**。保留的理由只是"现货更贴直觉 + 东财字段更全"。
