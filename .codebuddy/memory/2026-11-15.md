## 顶栏深证成指 → 上证50，恒生科技加雪球链接（`ba694254`）

用户："将上证50(SH:000016)替换顶部深证成指，其中跳转雪球地址：
恒生科技指数：https://www.xueqiu.com/S/HKHSTECH"

### 改了什么

**① `backend/app/routers/market.py::MAIN_INDICES` 第 2 项**
```
("sz", "399001", "深证成指")  →  ("sh", "000016", "上证50")
```
顶栏 `topIndices` 只取 `.slice(0, 3)` ⇒ 前 3 项变成
**上证指数 / 上证50 / 创业板指**（大盘 / 权重 / 成长三档），
与 `style_spread` 的权重端（11-14 已切上证50）口径一致。

**② 恒生科技链接**
`globalsRow`（外盘行）原本整列纯 `<div>` 不可点。给 `hstech` 的 defs 加了
用户指定的完整 URL，并在 map 里透出 `href`；模板改成与 A股 指数同款的
`<component :is="g.href ? 'a' : 'div'">` —— **有地址才渲染链接**，
其余外盘项没给地址就保持纯文本（不猜 HK/商品代码，避免指错标的）。

### 三个必须验证/注意的点

**① 硬前提：腾讯能不能拉到 `sh000016`？**
实测 `_fetch_tencent('sh000016')` ⇒ `price=2775.02` ✓。
原因是 `_main_indices_quotes()` **直接拼** `f"{prefix}{code}"` 请求腾讯，
**不经过 `get_index()` 的"首位数字猜前缀"逻辑** ⇒ 不需要改 `tencent.py`。
（`tencent.py:984` 的 `INDEX_MAP` 没有 `000016`，但那是 `get_kline` 的
WAF 冷却期防串标的用，与这里无关。）

**② 下游安全性**
`amreview.py:236` 消费 `_OVERVIEW_IDX_SNAP` 时取 `snap[:3]` 且**动态读 `name`**
⇒ 不硬编码"深证成指"，替换无破坏。
其余 `scanner.py` / `flash_brief.py` / `intraday_path.py` / `key_level_watch.py`
里的"深证成指"是**各自独立的指数池**，不属于顶部，**不要动**。

**③ 雪球链接口径（项目既有设计，别改错）**
- 指数**不能**用个股的 `xqUrl()`（按首位数字猜市场）：
  `000001` 既是上证指数（SH000001）又是平安银行（SZ000001）。
- 指数一律用 `xqIndexUrl(prefix, code)`，`prefix` 由 `MAIN_INDICES` 下发 ⇒
  上证50 自动得到 `https://xueqiu.com/S/SH000016`。
- 现有 `xqIndexUrl` 域名是 `xueqiu.com`（无 www），用户给的恒生科技范例带 www；
  两者等价（雪球会重定向），**没有全局改域名**，只在 hstech 一项原样用了用户地址。
