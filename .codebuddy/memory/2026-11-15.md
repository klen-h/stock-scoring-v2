### ★ 两个设计坑（都是实测/单测逼出来的）

**坑 1：固定百分比距离带对低波动股无效**
000429 实测 338 个交易日：**109 天 feasible，但两端同时触及 0 天**。
根因：支撑→阻力空间平均 **3.58%**，当日振幅平均只有 **1.93%** ——
"前高/前低"天然离现价 1.5~2.7%，**一天走不完一个来回**。
修法：① 距离上限改为 `min(3%, atr_pct × 1.2)`；② 新增 `现价 ± m×ATR` 近端兜底候选。
修后触发 0 → 19 次。

**坑 2：`0.8×ATR` 门槛被 ATR 候选"自我满足"**
加了 ATR 候选后，`space` 几乎恒等于 ~1×ATR ⇒ **永远 ≥ 0.8×ATR** ⇒ 可行性判定形同虚设。
（写单测时才发现：`step=0.005` 的平滑序列竟然 feasible=True。）
修法：**再加绝对百分比下限 `T_MIN_SPACE_PCT = 1.0`**（扣 0.1% 成本后还要有肉）。
**教训：倍数门槛和百分比门槛是两件事——前者管"相对波动够不够"，后者管"扣完成本还剩多少"。**

### 回测口径也修过一次

### 实现要点

**执行层 `t_trade_exec.py`（与纯计算 `t_trade.py` 分离）**
- `t_plans`：预案（唯一索引 `code+plan_date`；**盘中绝不重算**，否则位漂移）
- `t_trades`：**成对成交**（一次T = 一行 open_* + close_*）
  - ⚠️ **不塞 `paper_positions`**：那边是"按日信号→持仓→止盈止损"框架，
    做T 是**同一天两次反向操作**，混进去算不出这一笔的独立盈亏。
  - 盈亏方向（容易写反）：`long_t` = 后−先，`short_t` = 先−后。

**反T 不全仓（用户明确要求）**
```python
calc_shares('short_t', price, base_shares, cash, ratio, today_bought)
#   = 底仓 × ratio，再减去今日买入；100 股取整
```
默认 1/3 ⇒ 接不回来最多丢 1/3 底仓。今日买入占满 ⇒ 返回 0（不能卖成负数）。

**方向自动判断**
`有底仓+有资金 ⇒ 反T 优先`（不占资金 + T+1 合规）；只有底仓 ⇒ 只能反T；只有资金 ⇒ 只能正T。

**触发两阶段 `check_trigger`**
- 未开仓：贴支撑（≤sup×1.002）开正T / 贴阻力（≥res×0.998）开反T
- 已开仓：到另一端兑现；`支撑−0.5ATR` 止损（正T）/ `阻力+0.5ATR` 认错（反T）
- **尾盘 14:50 强制平**，不留隔夜

**两个循环**
- `t_trade_loop`（60s）：**只盯 自选+持仓**（全市场 300+ 只 → 推送灾难）
- `t_trade_scan_loop`（15:40 后一次）：**必须 `asyncio.to_thread`** ——
  `scan_market` 同步跑 **72 秒**，直接在协程里跑会卡死整个调度器

**性能**：批量 SQL（`code IN (...)` 200 只一批）把 164s → **72s**。
逐只查 `backtest_prices` 是瓶颈（原 163s）。

**API**（`/api/t-trade`）
`GET /plans`（`watch_only=1` 只返回关注里的）/ `GET /plan?code=`（库里有读库，没有则 live 解释）/
`GET /explain?code=` / `GET /summary` / `POST /scan`（BackgroundTasks，不阻塞 HTTP）

**前端**：右栏常驻「做T 看板」——全市场可行数、关注里可做数、今日开/平/盈亏、前 3 只可做标的。
⚠️ 必须显示 `plan_date`（预案是上一交易日收盘算的，不能假装是盘中算的）。
