## 001 复盘正文「具体交易信号」空白 —— 根因与修复（`deca3669`）

### 现象（用户："交易信号 etf 格式在企微里是空白的"）
`push_log` 实测：**10-30 盘前 `## 五、具体交易信号`、午盘 `## 六、具体交易信号`
下方均为 3~4 个空行**，标题在、内容空。
对比 10-29 有内容 —— 那天 LLM 输出空数组 + 文字说明（属偶然，不是设计）。

### 根因
`_SIGNAL_SCHEMA_HINT` 要求 LLM 把信号写在**报告末尾 ```json 块**，
`run_review_llm` 用 `_JSON_BLOCK_RE.sub("", md)` 把整块剥掉（供结构化入库），
⇒ 正文只剩标题 + 空行。**剥块是对的，缺的是"剥完补一段人可读的"。**

### 修复（`backend/app/flash/llm.py`）
1. `_render_signals_md(signals)`：把结构化信号渲染成**手机友好列表**
   （不用宽表格——企微要横向滚动）。空数组输出「本次无信号…空仓等待也是一种决策」。
2. `_fill_signal_section(md, signals)`：用正则定位
   `## [一二三四五六七八九十]+、具体交易信号`，替换标题到下一个 `##` 之间的内容。
   - 序号通配（盘前「五」/午盘「六」不同）
   - **找不到标题就原样返回**（盘后按设计无该节）
   - **原段落若有 `---` 保留回去**（首版会吞掉，用例验证时发现并修正）
   - 任何异常都原样返回（展示优化不得影响推送）
3. `run_review_llm` 在 `_JSON_BLOCK_RE.sub` 之后调用 `_fill_signal_section`。

### 验证（四用例，全部通过）
| 用例 | 结果 |
|---|---|
| 2 个信号 | 列表正确渲染，`---` 保留 |
| 空数组 | 「本次无信号…」 |
| 无该标题（盘后） | 原样返回 |
| 盘前序号「五」 | 正确匹配 |

## 002 买入规则同步（A：ETF 信号门槛）—— 检出门槛全是死代码（`7d20ab25`）

### 用户确认
「买入规则同步」指 **A = `signals/tracker.py` 的 `add_signal_with_validation`**
（不是 B = 个股 `trade_gate`）。

### 体检结论：4 道门槛里 2 道从未生效
实测 `tracking_state.data_json` 的 `rejectedSignals`（50 条，上限）：
```
32 次  午盘信号在 defensive 市不放行
11 次  持仓数超限 (5/5)
 7 次  相关性超限 (2/2)
 0 次  技术分不达标      ← 从未拦过
 0 次  总风险超限        ← 从未拦过
```
⇒ **只限制"买多少"，完全不限制"买得对不对"。**

### 五个 bug（均已修）
| # | 问题 | 后果 |
|---|---|---|
| 1 | `tech["passed"]` 算出后**从未被读**，只取 warnings | RSI 超买/逆势只警告，照放行 |
| 2 | `_check_total_risk` 量纲错：`止损幅度 × 账户 × 0.015` = 45 元，上限 6000 元 | 需 133 个持仓才触发 |
| 3 | 平仓时 `history.insert` 一次，函数末尾清理循环**又 insert 一次** | history 52 条 / 唯一 34 条（重复率 34.6%），perf 被重复累加（36 笔 vs 真实 18 笔） |
| 4 | 缺"信号质量"门槛 | 见下 |
| 5 | `invalidation` / `position_sizing` / `confidence` / `timeframe` 被 `build_signal_from_llm` **整段丢弃** | LLM 说"跌破6.95失效"，代码一律 `support*0.97` |

### 新增：风险回报比门槛 `RISK_CONFIG["min_rr"] = 1.0`
止损固定 3% ⇒ RR = 支撑阻力间距 / 3%。

**依据（去重后 18 笔真实成交重放）**：
| RR | 笔数 | 胜 | 累计 |
|---|---|---|---|
| <0.5 | 2 | 0 | -5.26% |
| 0.5~1.0 | 4 | 0 | -11.20% |
| 1.0~1.5 | 4 | 1 | -4.86% |
| >=1.5 | 8 | 2 | -6.46% |
| **合计** | 18 | 3 | **-27.78%** |

**拦掉 RR<1 的 6 笔（0 胜）⇒ 累计从 -27.78% 降到 -11.32%，少亏 59%。**

### 修复后口径冲突（待用户决定）
`max_positions=5` × `max_risk_per_trade=1.5%` = 7.5% > `max_total_risk=6%`
⇒ **实际有效持仓上限变成 4 个**。
若想保留 5 个，把 `max_total_risk` 调到 0.075。

### 验证（`_tmp_gatetest.py`，已删）
- RR 0.18 / 0.91 → 拒绝；RR 1.79 → 通过 ✅
- 3 持仓 + 1 新 = 6% 通过；4 + 1 = 7.5% → 拒绝 ✅
- 重复 id → perf/ history 都不重复；新 id → 正常计入 ✅
- 做空分支 bug：初版拿 `resistance` 当止盈端（做空时 entry==resistance）⇒ reward 恒 0，
  已改用 `takeProfit`。

### 技术分门槛的真实效力（低）
即使接上，`score` 也几乎不会 <50：
- 单条最多扣 30（逆势），RSI 极端与逆势条件互斥
- 实测"单边上涨 25 天 + 做空" = 85 分（-30 逆势 +15 RSI超买）**仍放行**
⇒ 它修的是"读都没读"这个 bug，**不是万能药**。

### 仍未做（需用户决策，风险更高）
1. **止损同步**：用 LLM 的 `invalidation` 替代固定 `support*0.97`
   （需正则解析"跌破6.95"，解析失败要回退）
2. **仓位同步**：`position_sizing`（轻仓/标准/重仓）映射到 0.75%/1.5%/2.5%
3. **入场确认**：现在是"跌到支撑就买"，正确应为"跌破支撑不买、反弹回来才买"
   ⇒ **这是胜率 16.7% 的核心**。所有亏损单 `entry < support`（跌穿才成交），
   所有盈利单 `entry ≈ support`（触及即反弹）。改这个要动状态机，风险最高。
4. **存量绩效数据**：history 里 18 条重复 + `performance` 累加值偏大，
   已在 `calculate_advanced_metrics` 消费侧去重兜底，但 `tracking["performance"]`
   本身仍是脏的（改需动生产数据）。
