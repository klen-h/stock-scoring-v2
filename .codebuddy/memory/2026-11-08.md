### 发现的三个问题（未改，用户只要审查）

**P1 真 bug —— 推送记账顺序反了**（`policy_tone_watch.watch_check_push` L448-461）
```
for w in hit_map: UPDATE last_pushed_at=now   ← 先记账
wechat.push_markdown_batched(...)             ← 后推送
```
企微失败 ⇒ 记账已落 ⇒ **当天该词永久不再推**（`last_pushed_at[:10]==day` 会跳过）。
注释写"可能重复一条"，**与实际行为正好相反**（实际是漏推，不是重推）。
**修法**：先推、`push_markdown_batched` 不抛异常后再记账。

**P2 逻辑缺陷 —— FedWatch 方向匹配会漏报**（`thesis_hints.scan_fedwatch` L100-121）
```
latest = matches[0]                    # 全局最新一条
if latest["direction"] == direction:   # 方向不匹配 ⇒ None
    latest_pct = latest["pct"]
```
若最新一句是"**维持利率不变**的概率 X%"，则加息假设的 `latest_pct` 直接 None
⇒ **即使加息定价早已跌破阈值也不触发**。
**修法**：按方向分别取最新 `{"加息": ..., "降息": ..., "维持利率不变": ...}`，
用同方向的最新句比对阈值。

**P3 测试漏洞 —— [28b] 覆盖不到 `snapshot`**（`test_policy_tone_watch.py` L165-168）
```
_ledger_src = src[src.find("def compute"):src.find("def ensure_tables")]
```
切片只含 `compute`，而 `snapshot` 定义在 `ensure_tables` **之后**，不在范围内。
断言名写"compute/snapshot 路径"，**名不副实**。
代码实际是安全的（`snapshot` 确实没推送），但断言挡不住将来的改动。
