## ★ 后端包「一直超时」的真正根因（2026-09-07 实测定位，已修复）
- **根因 = 腾讯 fqkline 的 count 参数超限**，不是并发/配额/超时设置！`generate-kline-pack.py` 传 `count = days*2`，后端包 days=1100 → count=2200 → 腾讯**直接拒绝返回 0 根**（0.1s 快速失败，非超时）。100% 失败 → 单只重试惩罚放大 → 1442 只必然顶穿 job 上限。前端包 days=150 → count=300 正常 → 所以"前端每次成功、后端必超时"。
- 实测上限：count=2200→0 根；1600→仅 640 根；**800 + 区间 1100 天 → 749 根**（≈2.9 年，够回测 500 交易日目标）。
- **修复**：`generate-kline-pack.py` 加 `KLINE_COUNT_CAP = min(days*2, 800)`（env `PACK_KLINE_COUNT_CAP` 可覆盖）；本地验证 000001/600519/000858 → **749 根、0.06-0.11s** ✅（修复前 0 根/10s 超时）。
- **附带修复**：`fetch_all_klines` 加中途熔断 `MIDWAY_FAIL_FAST=80`（前 80 只零成功立刻 RuntimeError 退出，不再空耗到 90-150 分钟超时才发现）；workflow 参数 PACK_REQUEST_TIMEOUT 6→15（750 根大响应）、CONSECUTIVE_COOLDOWN 6→15。
- 日志特征：`0/1442 成功` + 每 6 次失败 `暂停 30s` + **无 [WAF] 日志** = count 被拒（不是 501 封禁）。下次若再全挂，看是否熔断在 ~4 分钟内快速失败（正确行为），而非熬满 2 小时。
- 股票池 1442 只（quotes 已过滤过 ST/科创创业，故质量减法剔 0 只属正常，勿慌）；count 修复后 1442 只 5 并发预计 <10 分钟。

## ★ Render 崩溃重启循环（crash loop）诊断 + 只读模式开关（已实施代码）
- **现象**：Render 日志 `Started server process [1]` 反复出现 = OOM 崩溃循环；同时 `[pack_source] 下载数据包` 每次重启都出现。
- **机制（关键）**：Render 免费实例 512MB 内存 + **临时磁盘（重启即清空）** → 每次重启都要重新下载 31MB gz 并解压成 **126MB SQLite**，再叠加十几个定时任务（战法扫描池 2063 只 > pack 覆盖 1426 只 → 大量回源腾讯 → 满屏 `[WAF] K线请求被拦截`）→ OOM → 重启 → 重新下载解压 → 死循环。
- **包体积事实**：backend-pack.db.gz = **31.6MB**（07 Sep 12:59 发布），解压 126MB；用户看到的 160MB+ = gh-pages 仓库累积（每天提交一个 30MB 包，git 保留全部历史）→ 需清理历史否则仓库膨胀。
- **ENABLE_HEAVY_JOBS=0 不够**：它只控制 `indicator_cache_refresh_loop` + `backtest_preheat_loop` 两个；战法扫描/回测回填/资金流/mainforce/龙虎榜/各类快照/日报/矛盾扫描**都不受它管**，仍在跑。
- **已实施**：`backend/app/flash/scheduler.py` 新增 `RENDER_READ_ONLY` 开关（默认 0 = 行为不变）：
  - 保留（9 个）：flash(快讯) / track(持仓) / health / news_alert / regime_cache / stock_cache / open_confirmation / paper_fill / paper_track
  - 关闭（其余全部）：review / macro_daily / kline_cache / backtest_prices / mainflow / mainforce_state / lhb / zz_finance / strategy_scan / backtest_report / score_snapshot / market_snapshot / daily_report / midday_radar / intraday_alert / contradiction_scan+report / news_history / calendar / industry_map / mainline / sector_snapshot / finance
  - 启动日志会打印「★ 只读模式」确认行。
- **使用**：Render 环境变量 `RENDER_READ_ONLY=1` → 重启生效（需先 push 该改动）。
- **若仍 OOM**：需瘦身 pack（`generate_backend_pack.py` 的 `BACKEND_KLINE_CAL_DAYS` 1100→约 700，或收缩池子只数）→ 解压体积减半；或升级实例（512MB 确实不够）。
