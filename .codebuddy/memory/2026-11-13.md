## ★★★ 给「加仓」补方向判断：`gate_add_weak_direction`（`8b50565f`）

### 规则内容

`gate_add` 原来只看「涨跌比 > 0.8 且跌停 < 10」，**完全不看钱往哪个流**。
新增独立规则：当「近 5 日 沪深300 − 创业板」分化度 **< 3pp** 时否决加仓。

**阈值 3pp 的来源（实测 17 个 gate_add 触发日）**：

- **fail-open**：取不到分化度时**不否决**（缺数据 ≠ 方向不对）

   - 缓存为空 ⇒ `up/down = None` ⇒ **把当天真值覆盖成 None**
   - 缓存冻结在上一交易日 ⇒ 写入**与昨日完全相同**的 up/down

4. **`policy_bottom_watch` 的校验形同虚设**：
   它校验 `close_as_of` 日期 == 行日期，但 `close_as_of` 来自
   `val["as_of"] = _bj_now()` —— **写入时刻**，恒等于行日期。

## ★★★ 交易日误判导致**整站行情停更**（`a2210323`）

用户："持仓状态（4 只 · 风险 1 / 机会 0）行情 09:35，怎么持仓状态不是实时了"

### 一行数据锁定根因

```
quote_as_of   = 2026-11-13 09:35     ← 今天确实抓到过一次
from_snapshot = False                ← 不是快照恢复
data_date     = 2026-11-12           ← ⚠️ 抓到的数据被标成"昨天"
has_live      = True
```

`data_date` 来自 `_price_date_now()`：**交易日且过 9:15 ⇒ 今天**。
09:35 肯定是过了 9:15 的，却得出 11-12 ⇒ **`is_trading_day(2026-11-13)` 返回了 `False`**。

而 `stock_cache_refresh_loop` 的门禁就是
`market = get_china_market_status(); if market["is_open"]: refresh_all_stocks(...)`
⇒ `is_open=False` ⇒ **整天一次都不刷**。

09:35 那一次是别处（接口触发的 `refresh_all_stocks` / `market_overview` 的 BackgroundTask）抓的，
之后循环再也没跑 ⇒ 所有读同一份 `tencent._cache["stocks"]` 的块全部冻结：
持仓盈亏、涨跌家数、涨停统计、竞价看板、持仓雷达。

**⇒ 一个"日历错一天"，表现为"整个站点不实时"。**

### 根因：外部日历说 False 就被无条件采信

```python
_v = _tc.is_trading_day(now)      # fuyao 交易日历
if _v is not None:
    return bool(_v)               # ← False 直接返回，不与手工 HOLIDAYS 交叉验证
```

**11-13 是普通周五**，`HOLIDAYS` 里也没有 11 月 ⇒ 手工表会判「交易日」，但外部说「休市」就直接信了。

### 修法：冲突检测 + 回退保守判定

外部日历说"休市"，但**当天是工作日**且**不在法定节假日表** ⇒ 视为日历数据异常：
- 打警告（`[rules] ⚠️ 日历冲突：...`）
- **回退手工判定（按交易日处理）**

**取舍**：手工表保守但可靠，外部日历可能缺天/错天。
「多跑一天日批」的成本，远小于「整站数据停更一天」——后者只能靠用户肉眼发现。

### 验证（三种日期 × 三种外部返回）

| 日期 | 外部=True | 外部=False | 外部=None |
|---|---|---|---|
| 2026-11-13 周五（事故日） | True | **True + 警告** | True |
| 2026-11-14 周六 | True | False | False |
| 2026-10-01 国庆 | True | False | False |

（`外部=True` 对周末返回 True 是"外部权威"方向的信任，本次不改。）

### ★ 教训

「**外部数据源说不行**」不能等同于「**事实就是不行**」。
凡是"一个返回值决定整条流水线跑不跑"的开关，都必须有**第二信源交叉验证**，
且**冲突时偏向"继续跑"**（可观测的浪费 < 静默的停摆）。

### 排查手法（可复用）

`quote_as_of`（抓取时刻）vs `data_date`（数据所属日）**不一致**时，
说明"抓到了但判错了日期"，直接把矛头指向日期判定层，不用去翻网络日志。
