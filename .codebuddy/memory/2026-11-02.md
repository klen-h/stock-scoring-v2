## 001｜AI 解读提示词扩容：把项目里「没用上的数据」接进来（`a3936712`）

用户："加，但是提示词还不够，项目里有大把有用的数据没用上。"

### 改前
user prompt 只有 **246 字符**（盘面 4 项 + 宏观 5 项 + 消息 1 条），
模型除了"涨跌家数多"说不出任何因果。

### 改后（同一日实测 **1173 字符**）
新增 `_extra_block(day, is_live, missing)`，补三个**成因层**维度：

| 维度 | 数据源 | 回答的问题 |
|---|---|---|
| 主力资金结构 | `mainforce_state` GROUP BY phase | 钱在吸筹还是在出货 |
| 板块成交占比 Top6 | `industry_amount_share`（零外呼） | 钱去了哪个板块 |
| 情景推演 | `scenario_watch.load(day)` | 系统自己对后市的先验 |

外加：持仓结构（市值/集中度/风格）与**数据口径**段（让模型知道哪些是定稿、哪些是快照）。

### 三个踩出来的错（都是"想当然"，不是笔误）
1. **阶段枚举猜错**：首版写 `accum/wash/range/down`，库里实际是
   `decline / sideways / accumulation / markup / distribution / shakeout`
   ⇒ 6 个里 4 个没映射上，喂给模型的还是英文。
   **教训：中文映射表的 key 必须 `SELECT DISTINCT` 查出来，不能凭印象写。**
2. **`scenario_watch.load()` 结构猜错**：以为是 `{base/bull/bear: {prob}}`，
   实际返回 `{scenario(字符串), lean, n_up, n_down, anchor{level,state}, stale}`
   ⇒ 首版该段恒为空。改成用真实字段后能输出
   「当前情景「基准（磨底）」；倾向 偏空；信号 多2/空3；上证锚点 3574 守住」。
3. **口径噪音**：`caliber` 里混进兜底文案"无解读映射"（来自日历 impact 兜底），
   对模型零信息量 ⇒ 过滤。

### 顺带的性能修正（每多一个维度都是跨境往返）
- 主力结构原来 `MAX(date)` + `GROUP BY` 两条查询 ⇒ 合并成一条
  `GROUP BY date, phase`（省 570ms）。
- `scenario_watch.load()` 内部 2 条查询 ⇒ 加**按日 10 分钟缓存**（`_SC_CACHE`）。
- 实测：今日 **3160 → 1677ms**；历史 10-30 4410ms（该日日历数据多）；
  缓存命中 **0ms**。

### 边界（如实标注，不造假）
- **历史日没有板块占比**：它由实时行情池聚合，盘中未落库 ⇒ 进 `missing` 说明，不用今天的数据冒充。
- 外盘缺前值时输出「（无前值，仅为水平值）」而不是裸价格 —— 否则模型会对着 `111.43` 瞎猜涨跌。
- 数值与单位之间补空格（`1100 家`），便于模型正确切分。

## 002｜**AI 解读整篇是编的**——`missing` 没进 prompt（`fb6e3563`）

### 现象
用户贴回一段输出，读起来极其专业、逻辑自洽：

> 白酒板块 -2.8% 与隔夜纳指 -1.9% 同向…
> 半日成交 9842 亿、按曲线推全天约 1.55 万亿，环比缩量 12%…
> PMI 49.8 跌破荣枯线…

**逐条核对：一条都不在数据里。**

| 输出里的数字 | 系统实际 |
|---|---|
| 白酒 -2.8% | `amount_share available=False`，无板块涨跌 |
| 隔夜纳指 -1.9% | **纳指根本不在数据源**（代码注释：标普/纳指不在日频表内） |
| 上涨 2814 家 | `market_emotion_daily` 当天**整行不存在** |
| 半日成交 9842 亿 / 全天 1.55 万亿 | `market_amount.peek()` 全为 None |
| PMI 49.8 | 当日 `actual=None`（未公布），consensus 51.6 / prev 52.1 |
| 水泥/钢铁跌幅小于指数 | 无板块、无指数 |
| 消息面两条 | `flash_block news=0 条` |

当天实际喂给模型的**只有 4 行**：市场状态、主力资金结构、情景推演、数据口径。
（当时是 **00:27**，周一凌晨，本来就没有早盘数据。）

### 根因（三层，都不是"模型不听话"）
1. **`missing` 从来没进 prompt** —— 模型不知道自己缺什么，只看到 4 行，却要满足"4~6 条"的要求。
2. **system 里"不得编造"是软约束** —— 没有"数据不足就直接拒答"的硬门，也没有"未提供的板块名/指数名禁止出现"。
3. **端点无数据门槛** —— 无论 payload 有没有料，都直接调 LLM。

### 修法
- `_digest_user_text`：顶部插入「可用数据：盘面 N / 宏观 N / 消息 N」，末尾追加
  「⚠️ 数据缺失（你没有这些，**禁止推测、禁止补数字**）」逐条列出原因。
- `_DIGEST_SYS`：加四条绝对红线（未出现的板块名/指数名/数据值不得出现；
  缺失段列出的类别不得给结论；可用<4 项只输出一行"数据不足"；禁止引入外部数字）。
  条数改为"由数据量决定"，明确「宁可 1 条有出处，不要 5 条编一半」。
- `am_review_digest_run`：**硬门**——盘面为空直接拒绝（`blocked=True`）且不烧 LLM，
  同时 `pop` 掉可能已缓存的"编造版"；前端把 `hint` 一起显示。

### 验证
- 今日（00:27）：`ok=False blocked=True`，返回具体缺什么 + 该怎么做。
- 历史 10-30（盘面 4 项 / 宏观 16 项）：正常生成 **453 字**，全部可追溯：

```
815/4137、涨停49/跌停93、连板1、主力2853只(下跌1981/吸筹237/出货22+洗盘14=36 自己算的加法)、
布伦特111.85、法国GDP -0.1% vs 前值0.50%、情景基准磨底 多2/空3 锚点3574
```
  **没有再出现成交额、指数点位、板块涨跌、个股名。** 唯一提到的"银行/保险/煤炭"是引用消息面原文。

### 教训（写进 MEMORY 级别）
**展示型 AI 输出必须显式告知"你缺什么"，而不是只说"你不能编"。**
LLM 在信息真空下不会留白，它会用最合理的常识填空 —— 而"合理"恰恰最难被察觉。
**输入越贫乏，输出越流畅，就越危险。**
