### 两张表
- `thesis_registry`：假设登记簿（claim / nature / p_mine / p_market / market_source /
  market_as_of / deadline / resolution_rule / resolution_source / invalidation_early /
  status / backfilled / created_by / created_at）
- `thesis_events`：append-only 事件（register / revise / invalidate / evidence_manual / resolve）

### 三条铁律（本模块地基）
1. **claim / resolution_rule 登记后不可改**，只能 `revise`（改概率，必带 reason + trigger）或 `invalidate`
2. **裁决权不在 LLM**，按结构化 `resolution_rule` 求值
3. **没有 deadline / 失效条件的"长期观点"不允许登记**（那是信仰）

### 评审追加的"三刀"（缺一刀就退化成自我安慰工具）
1. `backfilled=1` **永久排除统计**（回填 9/16 样本只做 schema 演示）
2. **状态类命题不进本表**（滞胀 ON / 市场底清单 2/6 归 `scenario_watch`/`stagflation`），
   故 `nature` 只有 `prediction` / `decision`
3. **N≥30 前不产出 Brier / 折扣系数**，`stats()` 只报计数

### 双库坑规避（评审重点提醒）
- `SERIAL` 在 SQLite 不自增 → 按 `db.is_postgres` 分支：
  PG 用 `SERIAL PRIMARY KEY`，SQLite 用 `INTEGER PRIMARY KEY AUTOINCREMENT`
- JSON 一律存 **TEXT**（`resolution_rule` / `payload`），读取 `_loads()` 兼容
  "原始串 / 驱动已解析对象"两种形态
- 占位符统一 `%s`（`db` 内部自动转 `?`）
- **`db.insert()` 返回的是 rowcount 不是 id**（`insert` → `execute` → `cur.rowcount`），
  必须 `SELECT ... WHERE claim=%s ORDER BY id DESC LIMIT 1` 回查

### 踩到并修掉的 bug
`_now_bjt()` 返回 **aware** datetime（`datetime.now(timezone.utc) + 8h`），
与 `_parse_dt()` 的 **naive** 比较抛
`TypeError: can't compare offset-naive and offset-aware datetimes`。
修法：`.replace(tzinfo=None)`。
**凡是"UTC 加偏移"得到的时间，都必须显式去 tzinfo 才能和 naive 比较。**
