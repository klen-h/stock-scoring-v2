## ★★ 落地：`key_level_watch` 补 open/high/low + 推演新增 4 指标

用户（00:09 后）："'标准③「盘中低点 ≥3520」用 EOD 快照的日低字段就能测，数据现成，只差落库。'"

### 关键发现：数据一直是有的，只是没取没存

`_load_index_kline()` 返回的 bars **本来就带** `open/high/low`
（腾讯 `get_kline` 与库兜底 `_db_index_kline` 两条路径都有），
`get_index()` 的实时返回也带 `data[5]/[41]/[42]`。
⇒ **不是拿不到，是 `_analyze`/`upsert`/`load` 三处都没接**。

### 改动（3 个文件）

**`key_level_watch.py`**
```
① ensure_table(): 幂等 ALTER 加 open/high/low
   （PG 用 ADD COLUMN IF NOT EXISTS；SQLite 用 PRAGMA 后 ALTER
     ——⚠️ 与 t_trade_exec 同型：SQLite 的 PRAGMA 会多消耗 db.fetch，
       位置式 mock 的测试会被挤爆，见 11-24 那条教训）
② _analyze(): 从 bars[-1] 取 open/high/low
③ upsert: 三字段落库
④ _live_index_quotes()._one(): 实时路径也带回 open/high/low（**盘中就有日内低点**）
⑤ load().out: 实时值优先、否则落库值
```

**`thesis_scenarios.py`**
```
METRIC_LABELS += sh_open / sh_high / sh_low / sh_open_gap_pct
metric_value(): 从 key_level_watch 取；历史行 NULL ⇒ 返回 None + 原因（**不是 0**）
新增 _prev_trading_day(): 优先 flash.rules.is_trading_day（含 fuyao 日历），
                          不可用时退化只跳周末
```

### ★★ 一个必须避开的坑：开盘缺口不能对"任意更早日期"

最初写成 `date < day ORDER BY date DESC LIMIT 1` 取昨收 —— **错的**：
日批漏跑/长假/停牌时取到的可能是 3~5 天前收盘，中间指数已涨跌 5%
⇒ 算出的"低开幅度"完全是假数。

改用：先算**理论上一交易日** `_prev_trading_day(day)`，再精确匹配那一天，缺了就 None。
