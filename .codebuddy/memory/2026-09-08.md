## 🔴 Supabase 425MB 真凶定位：DDL 洪水触发 PostgREST schema cache 反复重载（已修复）
- **现象**（用户贴的 Supabase 日志）：02:02:21-02:02:58 每秒 1-2 条 `CREATE TABLE IF NOT EXISTS mainflow_history` / `CREATE INDEX idx_mainflow_date`；02:40-02:45 同样重复 `contradictions` / `contradiction_reports` 建表 60+ 次。
- **机制**：每个 ensure_table() 被放进循环（资金流回填 544 只、矛盾扫描等）→ 每条 DDL 触发 PostgREST **schema cache 全量重载**（日志每次 `Schema cache queried in 929/1359 ms`，重新拉取 43 个 Relations）→ 这就是日流量数百 MB 的来源。
- **修复（database.py，一处改动全局生效）**：`Database.execute` 开头对 `CREATE TABLE / CREATE INDEX / ALTER TABLE` 做**进程内去重**（`_DDL_DONE` 集合，命中直接 return 0）。这些 DDL 都是 IF NOT EXISTS 幂等，进程内执行一次即可，无需改任何调用方。
- 预期：日批期间的 DDL 从上千条降到每进程每表 1 条 → schema cache 不再反复重载 → Supabase 日流量大幅下降（明天观察验证）。
