## ★ 已落地：#3「`overview.stats` 口径切换」的**轻量实现**（用户："轻量切换"）

**背景**：工作台两处卡片（盘中「看盘序」+ 盘后「今日盘面定稿」）的 6 格中，
「涨停/跌停」来自 `/api/market/overview` 的 `overview.stats`，原先只有**内存池 + 按板幅近似**。
（9/29 用户问"#3 是什么意思"时已核实：原报告的"跌停 123→65"**大头已被当天 A1 顺带修掉**，
剩 4 条结构性差异 —— 见 9/29 记忆。）

**实现（3 文件）**
- `app/realtime_uplimit.py`：新增 **`peek(max_age=180)`** —— **只读缓存、绝不抓取**。
  ★ 为什么必须单独开这个入口：`snapshot()` 缓存冷时会**阻塞抓取 3 批 rt_k（~14s）**，
  而新的消费方 `market_overview` 是**首页接口**（要求秒开）⇒ 直接调会把首页拖成超时
  （同 `_gate_watch_live` 39.8s 的教训）。原则：**主路径只允许读缓存**，抓取交给预热循环。
  阈值 180s 的依据：预热循环 120s/轮 + 抓取 ~14s ⇒ 缓存龄 0~134s ⇒ 预热正常**必命中**
  （不会来回切口径），预热停摆则**稳定回退**近似。
- `app/routers/market.py`：新增 `_limit_counts_best(stocks)` —— **rt_k 精确优先，失败回退
  `_limit_counts`**，返回 `(up, down, src, meta)`；新增 `_shadow_log()`（**影子对比**，
  30 分钟一条、ASCII）；**两处调用点一起切**（`market_overview` + `market_temperature`
  —— 只切一处会**重新制造**"同页两个涨跌停家数"）；`stats`/`breadth` 下发口径披露字段
  `limit_src` / `limit_data_date` / `limit_age_sec`。
- `frontend/src/views/Workbench.vue`：新增 `limitTip()`，两处卡片的涨停/跌停格加
  `cursor-help` + `:title="limitTip()"`（**说清当前用的哪个口径**；近似口径显式标注
  "不含北交所、ST 被排除、0.3pt 容差"）。

**实测验证（含关键安全属性）**
```
① peek 冷缓存            → None ✓
② 回退路径（rt_k 冷）    → src=board_approx，耗时 0.0ms ✓✓  ← 若走 snapshot 会是 ~14000ms
   板幅判据自检：主板 10% → 涨停 ✓｜创业板 10.5% → **不算** ✓｜科创 20% → 涨停 ✓｜主板 −10% → 跌停 ✓
③ 预热后（真实抓取一次） → src=rt_k，up=57 down=12，耗时 0.5ms ✓；与 rt_k 值一致 ✓
   影子日志：`[market][shadow] limit counts: approx(mem) up=2 down=1 | rt_k(exact) up=57 down=12 | delta up=+55 down=+11 | data_date=2026-09-29 intraday=False age=0.0s`
④ overview 全路径（注入合成票池）→ stats 含 limit_src=board_approx、耗时 62.5ms ✓
   market_temperature 同源：breadth.limit_src=board_approx、temperature=63.3 ✓
```

**依赖影响（切换前已核实，避免误伤决策链）**
- `_breadth_score` 里涨跌停只占 **±8 封顶的微调**（`(33−65)/5250×100 ≈ −0.6`）
  ⇒ 切精确后温度计变化 **<1pt**；
- 前端**无任何位置**显示 `breadth.limit_up/down` ⇒ 不产生"两个数并行展示"。
