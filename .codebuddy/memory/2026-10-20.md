### 二、10-19 没扫到 = 扫描日被回退到 10-16
- `latest_trading_date()` 判据：近 5 日里「覆盖 ≥800 只」的最新一日。
- 实测 `backtest_prices`：**10-19 只有 263 只**，其余 **747 只最新仍停在 10-16**
  ⇒ 返回 10-16 ⇒ 扫描又把 10-16 那只重扫一遍（幂等重写，所以显示"命中 1/落库 1"）。

### 三、根因：`backfill()` 把"源没返回"当成"已同步"（静默失效）
- `backfill_history.backfill()`：若 `start` 存在且 `fetch_history` 返回空 ⇒ **直接 return 0**，
  注释写的假设是"已同步到最新"。
- 但实测数据源**有** 10-19（600000 / 603013 / 000001 的 `fetch_history(start='2026-10-16')`
  都返回 10-16 + 10-19 两根）⇒ 那 747 只是**请求被限流/中断后无感知**，不是源缺数据。
- 后果链：回填静默失败 → `latest_trading_date()` 回退 → 形态扫描每天重复扫旧日 →
  `pattern_watch` 的 T+1/5/10 跟踪也不会前进。
- 同族教训（项目已有）：**恒 0 / 空返回比报错危险**；「已有数据 + 无新行」必须与
  「源限流/源滞后」区分开（要拿 benchmark 日期比对，不能只看有没有抛异常）。

### 四、另外两点（非 bug，但会被误读）
