## ★★ 工作台评分榜改「本地优先」（2026-09-28，用户纠正）

**用户指出**："评分榜之前不就是实时的吗?我都是使用本地计算的"
⇒ **我上一轮说"评分榜要盘中实时得另接接口"是错的**。项目**本就有前端本地评分引擎**：

- `composables/useFrontendScoring.js` = 前端评分引擎（`initFrontendScoring` / `downloadKlineData` /
  `computeRanking` / `shadowBoards`）；**状态是模块级 ref**（`dbReady`/`dbStockCount`/`scoringResult`/
  `lastScoreTime`/`useFrontendMode`）⇒ **跨页面共享同一份**（工作台调 `useFrontendScoring()` 拿到同引用）。
- `views/ScoreRank.vue`（榜单页）**双模式**：`useFrontendMode`（用户偏好，持久化）
  → 本地 = K 线包入 IndexedDB + **实时行情** + 本地精算 ⇒ **盘中即实时**；否则走后端。
- `utils/scoringEngine.js` 与后端 `scoring/engine.py` 是**两套独立实现**（详情页"本地优先"）。

**问题**：工作台 `loadTop()` 恒走后端 `/score/batch/top`（**盘中通常是上一交易日快照**）
⇒ 与用户习惯的本地实时结果**口径不一致**（榜单页注释自己都写了"避免前后端榜单不一致被误认为 bug"）。

**修复（本地优先 + 后端兜底）**：`Workbench.vue`
- 引入 `useFrontendScoring` / `computeRanking`；`onMounted` 调 `initFrontendScoring()`（**不 await**，
  与榜单页同款）→ **完成后若已就绪且是本地模式 ⇒ 补刷一次** `loadTop()`
  （否则首次 loadTop 可能早于 dbReady 而回了后端，用户会看到"后端批次"）。
- `loadTop()`：`useFrontendMode && dbReady` → 本地（**5 分钟内结果直接复用**，避免工作台切阶段/轮询
  反复触发重算 —— `computeRanking` 会拉全市场行情+分批财报，很重）；否则回退 `getScoreTop`。
- **新增口径标记** `topMode`（`'local'`/`'backend'`）→ 卡片标题旁如实显示「本地实时 / 后端批次」+ tooltip。
- **字段零适配**：本地 `preciseResults` 本就含 `code/name/total_score/change_pct`（与卡片渲染一致）。

**验证**：`npm run build` 通过（708 modules，12.01s，0 error；`useFrontendScoring` 为独立 chunk 34KB）。
**待部署**前端。

**教训**：上一轮我凭"工作台走的是后端接口"就下结论"要另接实时接口"，**没有先查项目是否已有前端引擎**。

## ⚠️ 修复：`topMode` 声明丢失 → Vue warn + 评分榜「加载失败」（2026-09-28 用户报错）

**现象**：`Workbench.vue:1396 [Vue warn]: Property "topMode" was accessed during render but is not
defined on instance.` + 评分榜 Top10 显示「—（加载失败）」。

**根因**：`const topMode = ref('')` 的声明**未落盘**。该条属于"同一批次对**同一文件**连发 5 个
`replace_in_file`"那批 —— 工具**报 success，但文件里没有**（静默丢失）。
⇒ **一个缺失解释两个症状**：
  ① 模板读不到 `topMode` → Vue warn；
  ② `loadTop()` 里 `topMode.value = 'local'` → **TypeError（Cannot set properties of undefined）**
     → 被 catch → `topErr` → 卡片显示「加载失败」。
（已核实 `useFrontendScoring` 的 import + 解构**都在**，不是导入问题。）

**修复**：补 `const topMode = ref('')`（单条编辑）→ **用 search 复验确认落盘**（2142 行）；
`npm run build` 通过（708 modules，11.49s，0 error）。

**★★ 教训（工程纪律，已并入 MEMORY.md 踩坑纪律）**：
**同一批次不要对同一文件连发多个编辑** —— 存在静默丢失风险。改为**分批 + 每批后用 search/read 复验关键行**。
（本次仅丢 1 条，却造成"渲染告警 + 功能失败"两个症状 ⇒ 成本很高。）

### ① 观察池「详情」跳转后选中观察池 tab
