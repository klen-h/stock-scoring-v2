### ① 防御市期间战法样本**永久断档**（`for_scan` 覆盖不到 defensive）
- **现象**：`[8/20] 战法全量扫描` → `scanned=0, skipped=10`，10 条
  `[scheduler] 战法 X 未准入（当前为防御市，禁止战法入场），跳过扫描`；
  `[recommendation] 动态白名单（落库缓存）: []`。
- **★ 代码根因（`app/strategies/market_regime.py:531-542`）**：
  ```python
  base = {"offensive": "trending", "neutral": "oscillating",
          "neutral_bearish": "oscillating", "defensive": None}.get(regime)
  if base is None:                      # ← defensive 在这里就 return 了
      return False, f"当前为{…}市，禁止战法入场", …
  # ── 扫描层到此为止（B 方案）──      ← 永远到不了这行
  if for_scan and STRATEGY_WIDE_SCAN:
      return True, "准入（扫描层·攒样本）", …
  ```
  ⇒ **`for_scan=True` 只豁免「阴跌闸门 + 高波白名单」，豁免不了 `base is None`**。
- **与注释的缺口**：同文件 491-500 行「B 方案（2026-09-13）」的理由写的是
  **"阴跌期间 strategy_results 永久断档，未来无法复盘"** —— 而 `defensive` 会造成**同样的断档**，
  B 方案没覆盖到。492 行注释也确实写着"（进攻→趋势类、震荡→震荡类、**防御→禁**）"，
  所以**算设计如此**，但**后果真实**。
- **佐证**：`strategy_results` 停在 **2026-09-14**（128 行 / 22 个扫描日）⇒ 与"9-15 起转防御"吻合。
- **影响**：防御市（可能持续数周）期间**无法积累战法样本** ⇒ 战法回测/白名单优化**没有新数据**。
