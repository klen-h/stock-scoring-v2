### 三、★★ 日批时间：文档写的"19:30"**是错的**，实际是**次日凌晨**
生产库实测（北京时间，`contradictions.created_at` 等）：

| 数据日 | 日批写入窗口 | 备注 |
|---|---|---|
| 10-16 | 10-17 **02:53 ~ 03:25** | 正常 |
| 10-15 | 10-16 **03:23 ~ 03:41** | |
| 10-14 | 10-15 **03:49 ~ 03:57** | |
| 10-13 | 10-14 **04:54** | |
| 10-12 | 10-13 **07:10** | GitHub 队列延迟最久（约 5h） |

- **根因**：cron-job.org 的 job `0 18 * * 1-5` **默认时区是 UTC** ⇒ 北京 **次日 02:00** 启动；
  上游 `backend-pack` 跑 ~50 分钟后 `workflow_run` 接棒日批 ⇒ 02:53 开始写。
  （注释里"北京 18:00 / 19:00 / 约 19:30"是按北京时间写的，与实际差 7~8 小时。）
- **后果**：交易当日 19:30~24:00 **看不到当日数据**；极端情况次日 07:10 才写完，
  早 8 点前看仍可能缺数据。
- **修法（需用户操作，代码改不了）**：把 cron-job.org 的 job 时区改成 `Asia/Shanghai`，
  或把时间改成 `0 10 * * 1-5`（UTC）= 北京 18:00（**推荐**）。
