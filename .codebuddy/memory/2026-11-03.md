### 推荐方案：**前后端同机 + nginx 反代 /api + IP:80 访问**

（备案是"域名 + 大陆服务器"的要求）。前端 `baseURL` 默认 `/api` **不用改代码**。

### 三个必须知道的坑
1. **`frontend/Dockerfile` 用 `node:16`，而 vite 是 `^5.4.0`（要 Node 18+）**
   ⇒ 那个 Dockerfile **构建会失败**。前端不要走 Docker：本地 `npm run build` 后把
   `frontend/dist` 传上去，用宝塔静态站点托管。
2. **若前端继续留在 GitHub Pages（HTTPS），后端必须 HTTPS**
   —— 否则浏览器拦 mixed content。要么给后端配域名+证书（大陆需备案），
   要么把前端一起搬过来（推荐）。
3. **2 GiB 仍要防闸门 210MB**：`gate_states_for_signals` 单次构建就 ~210MB，
   加上基础占用 ~200MB。今天已验证的"逐条增量 + 单飞锁"必须在生产生效，
   否则 2G 也会被吃穿。

### 004｜构建上下文配错导致「没有 requirements.txt」（`f5cbaa35`）

**用户报错**：服务器上执行 compose 构建，提示 `requirements.txt` 不存在，问是否要手工创建。

**真相：文件在，是我的 compose 写错了。**
`Dockerfile` 里的 `COPY ./requirements.txt .` / `COPY . .` 路径是**相对构建上下文**
（不是相对 Dockerfile 所在目录）。而 `requirements.txt` 只在 `backend/` 下，
仓库根目录**没有** ⇒ `context: ..`（根）时第一条 COPY 就 "not found"。

**修法**：`context: ../backend` + `dockerfile: Dockerfile`（prod），
根目录开发用 `docker-compose.yml` 同样是错的，一并改成 `context: ./backend`
（那份**从来没有构建成功过**，所以之前没人发现）。

**验证**：用 yaml 解析两份 compose，`os.path.exists(context/requirements.txt)` 均为 True。

**教训（Docker 通用）**：
`COPY` 的源路径永远相对 **build context**，且 **Dockerfile 放在子目录时，
context 必须指向那个子目录**，否则第一层 COPY 就炸。
看到"文件不存在"先查 context，别急着补文件 —— **手写 requirements.txt 会漏依赖**，
后面会变成一堆 ImportError，比现在的错更难查。

### 008｜**站点已上线** http://101.201.222.167 （迁移成功）
外网验证响应头（判定"是不是自己的站"的三个证据）：
```
Content-Length: 463              ← 不是宝塔默认页的 1326
Last-Modified: 2026-11-03 ...    ← 今天构建的产物（默认页是 2017 年）
Cache-Control: no-store, no-cache, must-revalidate   ← 我们在 nginx-site.conf 里配的
```

**踩到的坑（nginx 层面，值得记）**：
- 宝塔默认站点和我们的站点**都写了 `server_name _;`**，nginx 保留**先出现**的
  ⇒ 请求全被默认页接走（`Content-Length: 1326` + `Last-Modified: 2017` 就是它的指纹）。
- 另有一个 `server_name 127.0.0.1;` 的块 ⇒ **用 `curl 127.0.0.1` 永远测不到自己的站**。
- 修法：把自己的 `server_name` 改成**真实 IP**（精确匹配优先于 `_`），
  `nginx -t && nginx -s reload`。
- 教训：`curl -I` 返回 200 **不等于**站点生效，要看 `Content-Length` / `Last-Modified` 才能确认身份。

### 009｜前端 404：`vite base` 写死 `/stock-scoring-v2/`（`a2ed1214`）
**现象**：浏览器报 `GET http://IP/stock-scoring-v2/assets/index-xxx.js 404`
＋ `Expected a JavaScript module but MIME type of text/html`。

**根因**：`frontend/vite.config.js` 里 `base: '/stock-scoring-v2/'`
（GitHub Pages 部署在子路径下必须如此）。自有服务器把 `dist` 挂在**站点根**
⇒ 产物里的资源路径多了一层 `/stock-scoring-v2` ⇒ 全部 404。

**修法**：`base: process.env.VITE_BASE || '/stock-scoring-v2/'`
- 默认值不变 ⇒ **GitHub Pages 照旧可用**
- 自有服务器构建：`VITE_BASE=/ npm run build`（PowerShell: `$env:VITE_BASE='/'; npm run build`）

**验证**：构建后 `dist/index.html` 里是 `/assets/index-xxx.js`（根路径），
本地 grep `/stock-scoring-v2/assets` 应无命中。

**另一个必须配的 nginx 段**（`deploy/nginx-site.conf` 已加，`d8c41493`）：
```nginx
location ~* \.(?:js|mjs|css|json|png|jpe?g|gif|svg|webp|ico|woff2?|ttf|eot|map)$ {
    try_files $uri =404;
}
```
否则缺失资源会被 SPA 回退兜成 `200 text/html`，浏览器只报 MIME 错，**看不出是文件缺失**。
