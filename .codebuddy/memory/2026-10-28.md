## 066 主力资金流静默滞后 4 天（真 bug，`f7fad567`）

- **现象**：系统状态「主力资金流 stale，滞后 2 天」；实测 `mainflow_history` 最新 **10-23**，
  10-26/10-27 两交易日各缺 **2852 只**，而 `mainforce_state` 有 10-26/10-27。
- **根因**：`missing_codes(day)` / `thin_codes(day)` 宇宙用
  `m.date = COALESCE(%s, (SELECT MAX(date) FROM mainforce_state))`（严格匹配当天），
  但日批顺序 `mainflow`(第5) → `mainforce_state`(第10) ⇒ 跑 mainflow 时当天 state 未写
  ⇒ 名单恒空 ⇒ 每天打印「当日无缺口，跳过」而**从未补过**。
- **修复**：宇宙改 `date <= COALESCE(%s, CURRENT_DATE)` 的最新 state（回退上一交易日）。
  实测：10-27 → 2852、10-26 → 2852、10-23 → 0、thin_codes → 0。
- **补数**：本地 `backfill_missing(day='2026-10-27', workers=4)`（逐只 130 天，幂等），
  100 只用 113s ⇒ 2852 只约 **50 分钟**；一次同时补 10-26/10-27。
- **附带事实**：`batch_runs` 最新成功记录是 **10-27（45/45）**，**10-28 尚无记录**
  —— 用户说"今日日批已跑完"需再确认（可能在跑/未到点/失败未收尾）。
- **教训**：跨任务的「宇宙」依赖必须用 `<= day` 回退，禁止严格等于 day；
  否则一旦任务顺序让生产者晚于消费者，缺口判定会**静默恒空**（不报错、只打印"无缺口"）。

## 078 LLM 突然不可用：诊断与「写死进代码」的修法（`4a611ec9`）

- **用户报**："LLM 现在不可用了" → "你直接写死代码里，可以吗？"
- **真实探测**（不是猜）：
  · 免费站 `deepseek-v4-flash` → **429**，code 先 `insufficient_quota`（配额耗尽）、
    后漂移成 `Throttling.BurstRate`（突发限流）⇒ **不能只看 message，要看 code 分桶**；
  · 主力站 siliconflow → **402** `account balance is insufficient`；
    但 `GET /models` 仍 200 且有 98 个模型 ⇒ **"能列出模型"≠"能调用"**（排障时差点被误导）；
  · 同账号仍可用：`deepseek-flash` 200、`sensenova-6.8-flash-lite` 200；
    不可用：`glm-5.2`/`kimi-k3` 429、`sensenova-u1.5-lite` 404、`deepseek-v4.1-flash` 403。
- **配置缺陷（真正的放大器）**：`LLM_MODEL` 空 ⇒ 主力站从未进链；`LLM_FREE_MODEL_FALLBACK` 空
  ⇒ 免费站 `models` 只有 1 个 ⇒ `_call_provider` 的"第 2 次起切兜底模型"**无处可切**
  ⇒ 配额一耗尽整链永久失败，且 **env 不会自愈**（这就是"突然不可用且一直不好"）。
- **修法（写进代码，不改 env 也生效）**：
  1. `_FREE_MODEL_BUILTIN = [deepseek-flash, sensenova-6.8-flash-lite]` + `_free_models()`：
     env 配置优先、内置候选兜底（去重保序）；`_providers()`/`llm_configured()` 同步改。
  2. `_call_provider`：`tries = max(retries, min(len(models), 3))`
     —— 原来 `retries=1` 时永远试不到后备模型（这行逻辑是死代码）。
  3. `_MODEL_QUOTA_COOL` 分类冷却：`insufficient_quota`→60min 且 **wait=0**（等几秒没用）；
     其它 429→5min 但**仍退避**。冷却只改**排序**，不剔除模型（避免一次抖动被永久放弃）。
- **实测**：env 仍是耗尽的 `deepseek-v4-flash`；第 1 次 28s 自动切模型成功，
  第 2 次 **4.7s**（顺序已把可用模型顶到前面）。
- **经验**：
  · 第三方额度错误的 **code 会漂移**，分类逻辑要按 code 集合而非单一字符串；
  · "配置里只有 1 个候选"是**单点**，即使代码写了 fallback 分支也永远走不到
    —— 内置一组候选比多写注释有用；
  · 排障先区分 `429 insufficient_quota`（等没用）与 `429 tpm/burst`（等一下就好），
    否则会用"退避重试"去治一个"配额耗尽"的病。
