## 做T 自动建底仓：功能正常，但没有"待触发的建仓计划"

用户："做T 交易台不会自动建底仓吗？"

### 结论：**会建，而且真的建过**

```
t_sim_positions 唯一一条：
  000878 云南铜业 300股 @12.76 · open_date 2026-11-18
  plan_id tp_1794763727465_000878 · status=closed · note=stop
⇒ 11-18 自动建仓 → 11-19 跌破止损自动平仓
```

**现在显示"没有底仓"是事实**：唯一的仓已止损平掉，且**没有新的 pending 建仓计划**。

### 完整触发链（关键：**不是"池子里的票"直接触发**）

```
① 池子/预案里有票
② 用户点「设建仓点」→ POST /t-trade/build-plan
   → 写 user_trade_plans（plan_type='t_build'，status='pending'）
③ trade_plan_trigger_loop（盘中 60s）
   现价 ≤ buy_price × 1.02 且 未跌破 buy_price（`auto_build_allowed`）
④ _plan_auto_build() → TX.auto_build()
   → t_sim_positions 写一笔 holding（股数 = max(300, min_base_shares(ratio))）
⑤ 此时才算"有底仓"，t_trade_loop 才会对它做T
```

**①② 之间是人工断点** —— 自动选池（`auto_pick_pool`）**只建池子，不建计划**。

### 当前数据实况

```
t_sim_positions   holdings=0（唯一一条 closed）
user_trade_plans  t_build 1（已 stopped） / trial 3（hit/stopped）
⇒ 没有 pending 计划 ⇒ 循环无事可做
```

### 为什么用户"看不到建过"

`GET /t-trade/sim` 返回的 `held` **只含 status='holding'** ⇒
已平的那条（云南铜业）**不在界面上**，于是看起来像"从来没建过"。

**改进方向（待用户定）**：模拟底仓区也列"已平"记录（类似 11-22 加的做T 历史页）。

### 若要做"全自动"（选池即建仓）

需要在 `auto_pick_pool` 末尾顺带给每只票建 `t_build` 计划，
但要先定**数量上限**（现在自动池 15 只，全建就是 15 笔模拟仓）。

## ✅ 已实现：选池即建仓（`e2fd36bd`）

用户："全自动：选池即建仓，需要精心挑选"。

### ★★ 核心发现（这次最值钱的一条）

`t_plans` 最新一批 **372 只 feasible 里，259 只的 `support_type` 是 `ATR×0.5`**。

```
ATR×0.5 = 现价 − 0.5×ATR    
```

**这是算法兜底造出来的人造位，没有承接含义。**
实测反例正是用户踩过的坑：000878 云南铜业 11-18 自动建仓 @12.76
（支撑 12.71 = ATR 位），**次日就跌破止损**。

⇒ 自动建仓的第一道门槛就是**只认真实技术位**：

```
前低(60日) / 近20日最低 / MA20 / MA60 / 整数位
```

### 四道门槛（都有实测依据）

| # | 门槛 | 砍掉 | 依据 |
|---|---|---|---|
| ① | 支撑必须是真实技术位 | **259** | ATR 位无承接力（云南铜业实例） |
| ② | `space_pct × ratio >= 0.8%` | 45 | 选池第 15 名只有 0.57%，建了白建 |
| ③ | 现价距支撑 **0.5% ~ 5%** | 0 | 太近一跌就破位（云南铜业 +0.39%）；太远等不到 |
| ④ | 数量上限 **3 只** | — | 模拟仓多了界面乱、无法逐个复核 |

372 → 68 候选 → 取 3。

**不加门槛时前 5 名全是 `ATR×0.5`** —— 正好印证必须要有 ①。

### 关键设计：**只建计划，不建仓**

```
scan_market（盘后 15:40）
  → auto_pick_pool（选池，15 只）
  → auto_build_plans（精挑 ≤3 只，建 status='waiting' 的计划）
       ↓ 次日盘中价格到买点
  → trade_plan_trigger_loop → _plan_auto_build → 模拟底仓
       （auto_build_allowed 还会再拦一次"已跌破买点"）
```

⇒ **即使精挑选错，也只是多一条没触发的计划，不会凭空多持仓。**

### 避免两处漂移

抽出 `TX.build_plan_row(plan, uid)`，手动接口 `POST /build-plan` 与
`auto_build_plans` **共用同一份落库逻辑**
（项目踩过 `_bench_code` / `SPREAD_THRESHOLD` 同型事故）。

### ★ 中证2000（932000）加进顶栏（`51c71ad5`）

用户："中证2000(CSI:932000) 加在顶部的创业板后面，这个代表着小盘，是个非常重要的信号"。
场景：隔夜纳指大跌 5% 而 A 股放量上涨（尤其创业板/中证1000）时，**系统可能错过修复信号**。

#### 数据源是唯一的难点（重要，别再试一遍）

| 源 | 结果 |
|---|---|
| 腾讯 `sh932000` | `v_pv_none_match`（无此代码） |
| 东财 `1.932000` / `0.932000` | `rc=100` |
| 新浪 `s_sh932000` | 空串 |
| 中证指数官网 | **只有日线**，收盘后才有 ⇒ 盘中不可用 |
| **雪球 `CSI932000`** | ✅ **2443.9155 / +3.91%** |

⚠️ 雪球必须写 **`CSI932000`**，写 `SH932000` 返回 `quote: null`。

#### 实现

- `MAIN_INDICES` 加 `("csi", "932000", "中证2000")`（创业板后第 4 位）
- `_csi_index_quote()`：**雪球优先 → 中证2000ETF(563300) 涨跌幅兜底**
  - 同日实测：指数 +3.91% / ETF +3.97%，**偏差 0.06pp**，判断强弱够用
  - 但 ETF 的 `1.125` **不是指数点位 `2443`** ⇒ 兜底时标 `proxy=True`
- 雪球 10 秒 TTL（比腾讯 3 秒宽松，反爬）+ **60 秒失败退避**
  （否则 `/overview` 每 3 秒调一次会把自己打成黑名单）
- 腾讯批量请求**排除 `csi` 前缀**（混入无匹配代码可能整批异常）

#### 前端两处必改（少一处就不显示）

1. `topIndices` 的 `.slice(0, 3)` → **`slice(0, 4)`**
   —— 原来只显示上证/上证50/创业板，第 4 位会被切掉
2. `xqIndexUrl` 前缀白名单加 `csi`
   —— 否则返回 `''`（无链接），且 `sh` 会拼成 `SH932000`（雪球无此标的）

#### 实测

```
1 上证指数  2 上证50  3 创业板指  4 中证2000  5 沪深300  6 中证500  7 科创50
_csi_index_quote() → 2443.9155 / +3.91%  缓存命中第二次 0.000s
```

**当日印证**：中证2000 +3.91% > 创业板 +3.08% > 中证1000 +2.90%
—— 正是用户说的"小盘在修复"。

### 配置项

```

T_AUTO_PLAN_TOP=3          数量上限
T_AUTO_PLAN_MIN_EXPECT=0.8 期望空间门槛(%)
T_AUTO_PLAN_MIN_DIST=0.5   距支撑下限(%)
T_AUTO_PLAN_MAX_DIST=5.0   距支撑上限(%)
```

## 复制失败 bug：`navigator.clipboard` 在明文 http 下不存在（`39cfd8e1`）

用户：\"点复制提示：复制失败，请手动选中文本\"。

### 根因

```js
navigator.clipboard  // 只在**安全上下文**（https / localhost）才存在
```

线上是 `http://101.201.222.167`（明文 http）⇒ `navigator.clipboard` 为
`undefined` ⇒ `.writeText()` 直接抛 `TypeError` 被 `catch` 住 ⇒ 误报"复制失败"。

**代码本身没错，是环境不支持。**

### 修复：统一 `copyToClipboard()`，两级降级

```
① window.isSecureContext && navigator.clipboard.writeText  → Clipboard API
② 否则：隐藏 textarea + document.execCommand('copy')
```

`execCommand` 已废弃，但它是**非安全上下文下唯一可用**的方案。
回退时保存/恢复用户原选区（否则复制后光标跳到页首）。

`copySample` / `copyText` 都改用它；失败文案改为"请手动选中文本后按 Ctrl+C"。

### 顺带：情景名列宽 112px → 150px

`w-28`(112px) 下"A 指数补跌、广度修复"会折行 ⇒ `style="width:150px"` + `leading-snug`。

```
build 14.10s · ThesisView 26.78kB(gzip 8.66kB) · lint 干净 · 卫生门无新增违规
```

**仅 `ThesisView.vue` 用了 clipboard，其他页面无此问题。**
⚠️ 线上仍是旧 bundle，**必须部署后复制才恢复**。
